# 牌堆流转与打出

> **一句话：原版只有四个牌区——抽牌堆、手牌、弃牌堆、消耗堆。没有判定区。打出一张牌 = 检查合法性 → 扣费 → 离手 → 结算效果 → 进弃牌堆或消耗堆。抽牌堆空了就把弃牌堆洗回去；两堆都空就停抽，不是报错。**

## 1. 四个区

```text
抽牌堆 ──抽──→ 手牌 ──打出──→ 弃牌堆
                      └──消耗──→ 消耗堆（本场不回来，除非效果明示取回）
手牌 ──回合结束弃牌──→ 弃牌堆
手牌 ──虚无／效果消耗──→ 消耗堆
```

| 区 | 玩家可见性 | 顺序 |
| --- | --- | --- |
| 抽牌堆 | 可知张数，默认不可见顺序（检索、预见类例外） | 有序；效果可以插到顶、底、任意位置 |
| 手牌 | 完全可见 | 无战斗规则上的顺序，只有展示顺序 |
| 弃牌堆 | 可知内容 | 通常可见列表；洗回抽牌堆时再随机 |
| 消耗堆 | 可知内容 | 本场仓库；默认不洗回 |

「延迟到下回合」用保留、能力、或牌留在手里结算（燃烧），不新增第五区。

容器需求（游戏规则层面）：必须支持从任意区取出指定实例，以及往抽牌堆**顶**放牌、往抽牌堆**随机位置**洗入牌。原版会动抽牌堆位置的操作只有这两种：放到顶（头槌 Headbutt：从弃牌堆选一张放到抽牌堆顶；预备）、洗入随机位置（伤口、Alpha 的 Beta）。「塞到抽牌堆第 N 张」原版没有；本项目容器若支持任意位置插入，属于预留，不要写成原版已有。旧版此处写的「无头骑士」不是一代卡牌，应为头槌。

## 2. 抽牌

一次「抽 N 张」= 重复 N 次「抽 1 张」，每张单独处理满手和空堆。

抽 1 张的规则：

1. 手牌已达上限（10）→ 这次抽失败，不从抽牌堆拿牌。不是把牌抽出来丢掉。
2. 抽牌堆有牌 → 拿走最上面一张进手，然后结算「抽到时」（虚空失去能量、蛋类遗物升级、混乱改费用）。
3. 抽牌堆空、弃牌堆有牌 → 弃牌堆洗进抽牌堆（用本场战斗随机种子），再执行 2。
4. 两堆都空 → 这次抽失败，静默结束。允许手牌不足 5 张仍进行行动。

洗牌是可观察事件：日晷等按「第几次洗牌」计数。

战斗开始的构建：牌组全部进入抽牌堆并洗牌，然后处理固有（固有牌必须进入第一回合手牌），再抽到第一回合应得张数。瓶装遗物指定的那张牌视为固有。

## 3. 手牌上限与「加入手牌」

上限 10。抽牌撞上限见上节。

效果「把一张牌加入手牌」（生成打击、炼金产物、液态记忆）：

- 未满 → 进手牌
- 已满 → 进弃牌堆（不是消耗，也不是消失）

药水抽牌、能力抽牌、卡牌抽牌，同一套上限。

符文金字塔不弃手，很容易顶满 10 张，之后抽牌全失败。这是该遗物的代价，不是 bug。

## 4. 打出一张牌的顺序

玩家选择一张手牌并指定目标之后：

| 顺序 | 步骤 | 失败则 |
| ---: | --- | --- |
| 1 | 按 [卡牌类型与关键词.md](卡牌类型与关键词.md) 第 7 节检查合法性 | 整次打出取消，牌仍在手，不扣费 |
| 2 | 扣除当前费用（X 费扣除全部当前能量） | — |
| 3 | 这张牌离开手牌（此时手牌少 1，抽牌效果才能抽到第 10 张） | — |
| 4 | 结算牌面效果（可能造成多段伤害、抽牌、施加能力、再打出别的牌） | 效果中途敌人全灭则胜。原版已入队的后续伤害段仍会跑完（对尸体无效）；本项目「已生成的下一段伤害可以停」是有意简化，结果一致，见 [伤害格挡与生命损失.md](伤害格挡与生命损失.md) 第 7 节。不要在死后继续对尸体施加 Debuff |
| 5 | 「打出成功」钩子：钢笔尖、开信刀、项圈计数、时间扭曲计数、回声形态、痛苦诅咒等 | 喝药不走本步 |
| 6 | 牌进入弃牌堆；若类型是能力牌或带消耗，进入消耗堆 | 死灵诅咒等会从消耗堆再回来 |

第 3 步在第 4 步之前：打出「抽 2 张」时，这张牌已经不占手牌。

回声形态 / 双发：在第 4 步后再把**同一张运行中实例的效果**结算第二遍，不是从抽牌堆再找一张同名配置。第二遍仍可能消耗能量以外的资源（目标、格挡），但不第二次扣费。第二遍**计入**第 5 步的「打出」计数——原版的墨水瓶、天鹅绒项圈、时间吞噬者都数两次；且若第一遍恰好是第 12 张，时间扭曲立刻结束回合，第二遍**不会发生**（社区实测一致）。本项目沿用这两条。若某张牌声明「不触发打出」，单独写。

## 5. 弃牌、消耗、放回

| 操作 | 从哪到哪 | 是否触发「消耗时」 |
| --- | --- | --- |
| 打出后默认 | 手 → 弃 | 否 |
| 打出后消耗 | 手 → 消耗堆 | 是 |
| 回合结束弃掉 | 手 → 弃 | 否 |
| 虚无结束时 | 手 → 消耗堆 | 是 |
| 效果「消耗一张手牌」 | 手 → 消耗堆 | 是 |
| 效果「消耗抽牌堆顶」 | 抽 → 消耗堆 | 是 |
| 弃掉带消耗关键词但未打出的牌 | 手 → 弃 | 否 |

暗之拥抱、无惧疼痛只关心「有牌进了消耗堆」。死灵诅咒进消耗堆后立刻回到手或抽牌堆，仍算发生过消耗。

检索（Seek）：玩家从抽牌堆**看见并选择**一张拿到手。原版**不洗牌、不改其余牌的相对顺序**，抽牌堆为空时也不会把弃牌堆洗回来（它不是「抽」）。本项目若做检索，写死为「选出的牌上手，其余洗回抽牌堆」，避免保留已知顺序破坏信息——这是**本项目的选择**，与原版不同，不要事后当成原版。

预见（Scry）：看抽牌堆顶 N 张，任意张进入弃牌堆，剩下的保持原相对顺序回到抽牌堆顶。

## 6. 随机与种子

下列操作必须使用**本场战斗**的随机源，同样种子同样牌组应得到同样顺序：

- 开战洗牌、弃牌堆洗回抽牌堆
- 随机敌人目标、随机生成牌
- 混乱把费用随成 0～3
- 药水「随机一张攻击牌」的牌池抽取

地图、奖励用另一路种子（局外），不要和战斗洗牌搅在一起。需求上只要「战斗内可复现」；局外种子不在本文。

## 7. 第一回合手牌

1. 洗牌
2. 所有固有（含瓶装）进入手牌；若固有超过 10，超出部分按加入手牌规则进弃牌堆（极端边角）
3. 再抽 `max(0, 本回合抽牌数 - 已在手的固有数)` 还是再抽满 5 张固有另算？原版是：固有保证在第一手，**第一手总张数仍是 5**（准备背包再 +2）。固有超过 5 则第一手可以超过 5。

准备背包：第一回合多抽 2 张，是在起手 5 张抽完之后、开战遗物阶段按拾取顺序再抽一次，不是把第 3 步的抽牌数改成 7——所以痛楚印记在它之前拾取时，这 2 张可能抽到伤口（见 [回合时序与能量.md](回合时序与能量.md) 2.1）。

## 8. 和能力、遗物相关的牌堆事件

必须作为独立事件存在、供能力/遗物监听（游戏规则上「发生了这件事」，不是实现接口）：

- 抽到一张牌
- 打出一张牌（带类型、费用、是否攻击）
- 一张牌被消耗
- 弃牌堆被洗进抽牌堆
- 手牌在行动结束被弃掉
- 生成一张牌并说明落入哪个区

没有这些事件，虚空、钢笔尖、日晷、暗之拥抱都无法定义。

## 9. 对本项目的需求分析结论

- 四区是底线；消耗堆与「能力牌打出后进消耗堆」一起出现。
- 抽牌失败是合法结果。
- 「先离手再结算」是原版打出顺序，也是抽牌类卡需要的顺序。0.2 起 `BattleSession.TryPlayCard` 已按此顺序实现（`TakeFromHand` → 结算 → `AddToDiscard`，剑柄打击是第一张消费者）；「打出中的牌不在任何牌区」与本文第 4 节第 3 步一致，显式的「结算中」位置等复制打出类效果出现再加。「打出钩子不含喝药」从第一瓶药水就要遵守。
- 牌堆不是栈：至少要能放到顶、洗入随机位置、取出指定实例；「任意位置插入」是本项目预留，原版没有对应牌。
- 复制与二次结算复制的是运行中的那张牌，不是配置表里的原型。
