# 敌人意图与多敌人

> **一句话：意图是「先展示、后执行」。每个敌人在自己行动结束时就决定并亮出下一轮要做什么；玩家整段行动都能看见。多敌人时没有嘲讽，玩家自由选目标；怪物侧先对全体做回合开始（清格挡、中毒），再逐只出手。**

## 1. 意图对玩家意味着什么

每个存活敌人展示一个当前意图，包含：

- 种类（见第 2 节）
- 若是攻击：预览伤害数字（含该敌人力量、虚弱，以及玩家易伤；不含钨条等扣血后修正）
- 若是多段：段数（例如 3×7）
- 若是施加：将要施加的能力名称与层数，能预览就预览

隐藏意图（符文圆顶）把上述信息全部挡住，敌人仍按真实意图结算。这是信息规则，不是「敌人变成随机乱打」。

意图在敌人**自己的角色行动结束**时刷新。玩家行动期间不会无故改掉（例外：玩家效果明确改意图，如造成眩晕、或某些牌「敌人失去意图」——本项目若没有这种牌，则玩家行动中意图冻结）。

## 2. 意图种类

| 种类 | 执行时做什么 | 展示 |
| --- | --- | --- |
| 攻击 | 对玩家造成攻击伤害，可多段 | 伤害与段数 |
| 攻击 + 施加 | 先伤害后施加，或按该怪写死的顺序 | 伤害 + Debuff 图标 |
| 攻击 + 格挡 | 伤害与获得格挡 | 两者都示意 |
| 防御 / 格挡 | 只获得格挡 | 格挡意图 |
| Buff | 给自己或同伴施加 Buff | Buff 图标 |
| Debuff | 给玩家施加 Debuff | Debuff 图标 |
| 眩晕 / 无法行动 | 跳过出手 | 眩晕 |
| 逃跑 | 该敌人离开战斗（不一定算玩家击杀） | 逃跑 |
| 未知 / 睡觉 | 特定阶段（如守护者休眠） | 特殊图标 |

一只敌人同一时刻只有一个当前意图。复杂敌人用「模式」在血线或回合计数上切换意图表，仍然是「现在展示这一个」。

## 3. 意图如何决定

每只敌人有自己的模式，不是全局 AI。常见模式（写某个敌人的需求时选一种）：

| 模式 | 规则 |
| --- | --- |
| 固定循环 | A→B→C→A…… |
| 概率 | 按权重随机，用战斗种子 |
| 不能连用 | 「不会连续两次用同一击」 |
| 血线切换 | 低于 50% 进入第二阶段，可能立刻改意图或从下一段行动改 |
| 计数 | 时间吞噬者累计玩家打出张数；守护者累计受到伤害 |

决定意图发生在该敌人角色行动结束（战斗开始时决定第一个意图，见 [回合时序与能量.md](回合时序与能量.md) 2.1）。

执行前要再检查一次**是否还能执行**：

- 已眩晕 → 跳过，通常下一段行动醒
- 目标（玩家）已死 → 战斗已失败，不再执行
- 模式要求「同伴全死则逃跑/强化」→ 按该怪需求改这次执行或改下次意图

「先展示后执行」的含义：玩家根据展示做决策；执行时以检查后的可行性为准，不按展示强行打一个已无效的动作（眩晕就是这种检查）。

## 4. 眩晕

眩晕是 Debuff 或一次性状态：该敌人下一次角色行动跳过出手。

- 跳过时：仍在怪物阵营开始时清格挡（除非路障）、仍结算中毒，仍走行动结束触发，仍决定下一个意图。中毒把睡着的拉盖尔沃林打醒会消耗掉它的眩晕回合（wiki.gg Poison）。
- 玩家在敌人眩晕的那一轮能看见眩晕意图。
- 对正在展示攻击的敌人施加眩晕，应把当前意图改成眩晕，玩家立刻看到。

## 5. 多敌人场面

### 5.1 目标选择

- 玩家单体牌：指定一只存活敌人。
- 全体牌：对所有存活敌人各结算一遍，顺序与站位一致。
- 随机牌：每段在存活敌人中抽；结算中途死人则从剩余里抽。
- **没有嘲讽、没有强制打前排。** 这是原版战斗信息清晰的前提。
- 敌人默认只打玩家。同伴之间的 Buff（如某怪给全体怪物加力量）写在该意图上，不是「敌人选目标系统」。

### 5.2 站位与行动顺序

从左到右（或编队表顺序）依次走角色行动。一只在自己行动里召唤新敌人：新敌人本轮是否行动，必须在该召唤效果上写死（原版多为「下轮再动」）。

全体伤害按顺序结算时，左边死了不影响右边已经排定的「这一轮要行动」——但若全体伤害发生在**玩家行动中**，死人根本不会进入之后的怪物阵营。

### 5.3 钩子时序（多敌人真正要的东西）

多敌人需要的不是更多级别的回调，而是一条批处理顺序：**全体怪物先做回合开始（每只清格挡、再中毒）→ 逐只出手 → 回合结束效果 → 轮末减层**。

| 事件 | 时点 | 例子 / 挂错后果 |
| --- | --- | --- |
| 清格挡 | 怪物阵营行动开始，每只各清（路障 / 模糊例外），早于毒发和任何出手 | 挂到毒发之后：守护者被毒发切进防御形态拿到的格挡会被清掉（原版留到玩家回合） |
| 中毒结算 | 怪物阵营行动开始，所有中毒敌人一起，早于任何出手 | 三只毒蛙同一时刻掉血；毒死召唤者，随从逃走不出手 |
| 金属化 / 仪式 | 该敌人出手之后、玩家回合之前 | 逐只结算还是全体出手后一起，公开资料未写清、玩家也看不出差别；二选一写死 |
| 虚弱减层 | 一轮结束，所有人一起 | 不要在某只行动结束时单独减 |

1v1 时这些顺序退化成「敌人打一下」，测不出错误。多敌人是这些需求的验收场。

### 5.4 随从与分身

| 规则 | 含义 |
| --- | --- |
| 随从 | 打死不结束战斗；召唤者死了随从怎么处理（立刻死、逃跑、变独立）由该遭遇写死 |
| 分裂 | 史莱姆死亡变成两只更小的，必须在死亡当刻插入新敌人，并给它们意图 |
| 生命共享 | 对一只造成的生命损失按该遭遇规则分摊或复制 |

这些是遭遇需求，不是通用战斗规则。通用层只保证：战斗未结束当且仅当「还存在必须击杀的敌人」；死亡时可以立刻生成新敌人。

## 6. 玩家死亡与敌人全灭的插入点

任何一次生命变化之后都要判定：

- 玩家 ≤0 且无致死改写 → 失败，取消尚未执行的敌人意图
- 必须击杀的敌人全部不在场 → 胜利，取消尚未执行的后续敌人行动

中毒在阵营开始清场，属于后者。多段攻击在第 2 跳打死玩家，取消第 3 跳和后续敌人。玩家打死敌人时，原版已入队的后续跳数仍会跑完（对尸体无效），本项目立刻停是简化，见 [伤害格挡与生命损失.md](伤害格挡与生命损失.md) 第 7 节。

## 7. 对本项目的需求分析结论

- 1v1 固定 6 点攻击是「每种意图里最简单的一种 + 每轮刷新成同一句」，不是「没有意图系统」。
- 多敌人引入的不是选目标 UI 那么简单，而是怪物侧的批处理时序（全体回合开始 → 逐只出手 → 回合结束 → 轮末减层）、全体/随机结算、死亡插入召唤。
- 眩晕证明「展示的意图在执行前可被作废」。
- 符文圆顶证明意图信息可以隐藏，逻辑仍按意图走。
