# 1.2 技术设计：地图与节点分发

> **技术目标：地图成为枢纽。** `StartRun` 只建 `RunState` 并上地图，不 `Begin`。进入当前节点才按 `NodeType` 分发；战斗胜利未通关则 `DiscardSession` 回地图，禁止在 `ApplyOutcomeIfEnded` 里 `Begin` 下一场。`BattleSession` / `BattleInput` / `BattleSetup` 不认识 `NodeType`。无奖励页、无空商店页、无分支图。
>
> 玩法要求见 [`游戏设计.md`](游戏设计.md)，执行顺序见 [`TODO.md`](TODO.md)。总设计见 [`../游戏设计.md`](../游戏设计.md)。对照 1.1：[`../1.1/技术设计.md`](../1.1/技术设计.md)。
>
> 流程、写回单通道、遗物字典、地图交互与 `NodeType` 取值已定（枚举只有 `Combat`）。无未拍的 **[待确认]**。

## 1. 技术原则

- **地图是枢纽，战斗页仍只管局内。** 选下一场、回地图都是流程的事。局内命令仍只打 `RunController`。
- **结束写回仍是单通道。** `PlayCard` / `EndTurn` 返回前读一次 `Phase`，至多一次 `ApplyResult`。禁止 `Update`。1.1 场间「未通关立刻 `Begin`」改为「未通关回地图」；通关 / 失败仍去 Result。
- **回地图必须丢掉 Session。** 否则 `IsReady` 仍为 true：顶栏会误跟局内、`EnterCurrentNode` 会被挡住。`DiscardSession` 仍不清遗物字典。
- **`NodeType` 只活在 Run 与流程。** 不进 `BattleSession`、不进 `BattleInput`、不进 `BattleSetup`。不把 `RunState` 传入 Session。
- **有消费者才加原语。** 本版没有商店 / 休息 / 事件页，就不做空页占位，枚举也不预声明这些值。

## 2. 分层与依赖

```text
Views（顶栏 + Start / Map / Combat / Result）
  ↓ Start → StartRun；地图进入 → EnterCurrentNode
  ↓ 局内命令只打 RunController；战斗页 Refresh 仍可读 BattleController
Controllers
  RunController（仍唯一 SerializeField 持有 RunConfig）
  BattleController.Begin / DiscardSession / …（合同相对 1.1 不变）
  ↓
Core.Run（RunState + NodeType；BattleInput 五字段不变）
Core.Battle（Session 构造不变，grep 不到 NodeType）
Data（RunConfig 本版不改字段）
```

## 4. 核心接口

### 4.1 NodeType **[已定] 只有 Combat**

本版三个节点全是战斗。要证明的是「新类型 = 新页 + 流程一个分支」，不是预建空商店。不预声明 `Shop` / `Rest` / `Event`。

- 枚举只有 `Combat`。`RunState` 构造仍是 1.0 那五个参数；内部 `_nodeTypes` 按遭遇表长度全填 `Combat`。`RunConfig` 不改。
- `switch (Run.CurrentNodeType)` 必须真实存在，禁止 `if (true)` 直接 `Begin`。
- `default`：`Debug.LogError`，留在地图，不 `Begin`、不 `CreateBattleInput`（挡住非法强制转换的枚举值）。
- `Core/Battle/`、`BattleInput.cs`、`BattleSetup` grep 不到 `NodeType`。
- 以后加商店 = 枚举加一个值 + 新页 + `switch` 多一个分支，不改 `BattleSession`。

### 4.2 RunState

**[已定] 构造仍是 1.0 那五个参数。** `encounters` 仍恰好 3 条 `EnemyDefinition`。

```csharp
namespace CardRPGFramework.Core.Run
{
    public enum NodeType
    {
        Combat = 0,
    }

    public sealed class RunState
    {
        // 1.0 已有成员一字不改语义：CreateBattleInput / ApplyResult / AddCard / IsCleared …
        public IReadOnlyList<NodeType> NodeTypes { get; }

        /// 自定义 get：未结束返回 _nodeTypes[NodeIndex]；IsOver 抛 InvalidOperationException。
        /// 不要自动属性。失败时 NodeIndex 仍在范围内，不能用下标当哨兵。
        public NodeType CurrentNodeType { get; }

        // 构造仍是 (runSeed, playerSetup, deck, relicIds, encounters)
        // encounters 仍恰好 3、无 null。内部 _nodeTypes = 三个 Combat（浅拷贝，长度与遭遇表相同）。
    }
}
```

`CreateBattleInput` 仍用 `_encounters[NodeIndex]`，仍不看类型。非战斗节点不该走到这里——拦在 `EnterCurrentNode`。

`IsCleared` 仍是 `NodeIndex >= _encounters.Count`，不要写 `== 3`。`CurrentNodeType` **看 `IsOver`**，不要只判断 `NodeIndex >= Count`：通关后下标会越界，失败后下标仍合法、静默返回 `Combat` 会把失败当成还能进。地图在通关 / 失败路径上不会去读。

**[已定] 不公开遭遇表列表。** 地图不写敌人名（总设计只要三个点）。没有第二个消费者就不要加 `Encounters`  getter。

新增 EditMode（写进现有 `RunStateTests.cs`，不往 EditMode 根目录加文件）：

- `NodeTypes.Count == 3` 且全是 `Combat`。
- 开局 `CurrentNodeType == Combat`；一场胜利后 `NodeIndex == 1` 仍是 `Combat`。
- `IsCleared` 后 `CurrentNodeType` 抛 `InvalidOperationException`。
- `IsFailed` 后同样抛（`NodeIndex` 未越界也不能读）。
- 1.0 的 `CreateBattleInput` / `ApplyResult` / `IsCleared` / `AddCard` **断言不改**。

### 4.3 结束写回（相对 1.1 只改 Victory 未通关）

**[已定] 仍禁止 `Update`。** `ApplyOutcomeIfEnded` 仍只从 `PlayCard` / `EndTurn` 调用。失败只认 `Phase == Defeat`。场间仍 **先 `ApplyResult`**，再决定 UI；不要先 `CreateBattleInput`。

| `Phase` | 写回 | UI（相对 1.1 的变化） |
| --- | --- | --- |
| `Victory` 且写回后 **未** `IsCleared` | 先 `ApplyResult(true, 局内生命)` | **`DiscardSession`（不清字典）→ `ShowMap`（含点状态与 `RefreshShell`，见 4.4）。禁止 `Begin`。** |
| `Victory` 且写回后 `IsCleared` | 同上 | 与 1.1 相同：`DiscardSession`（不清字典）→ Result（通关） |
| `Defeat` | `ApplyResult(false, …)` | 与 1.1 相同：`DiscardSession`（不清字典）→ Result（失败）。**不回地图** |

1.1 场间「未通关立刻 `Begin`」会跳过地图，是本版要删的路径。写反（先造下一场 input 再写回）1.0 测试仍会绿；「第二场开局生命 = 第一场结束生命」继续靠 Play。本版第二场的 input 在玩家点进入时才发，不在写回当时发。

### 4.4 RunController

```csharp
namespace CardRPGFramework.Controllers
{
    public sealed class RunController : MonoBehaviour
    {
        [SerializeField] private RunConfig runConfig;
        [SerializeField] private BattleController battleController;
        [SerializeField] private BattleView battleView;
        [SerializeField] private MapPageView mapPageView;
        [SerializeField] private RunShellView runShellView;
        [SerializeField] private ResultPageView resultPageView;
        [SerializeField] private GameObject startPage;
        [SerializeField] private GameObject mapPage;
        [SerializeField] private GameObject combatPage;
        [SerializeField] private GameObject resultPage;

        public RunState Run { get; private set; }

        /// 校验失败则 LogError 并停留在 Start。
        /// 通过则 CreateRunState → SetRelicDisplayNames(runConfig.Relics) → ShowMap。
        /// 不 CreateBattleInput、不 Begin。
        public void StartRun();

        /// Run == null / IsOver / IsReady 则直接 return，不读 Phase。
        /// 「未开战」就是 Run == null，不要写成 !IsReady——再和 IsReady 拼会永远 return。
        /// 否则 switch CurrentNodeType：Combat 则 CreateBattleInput → Begin → 显示 Combat
        /// → battleView.Refresh → RefreshShell。
        /// 未实现类型：LogError，留在地图。
        public void EnterCurrentNode();

        public bool PlayCard(int handIndex);   // 相对 1.1 不变：转发后 ApplyOutcomeIfEnded
        public bool EndTurn();
        public void Restart();                 // 相对 1.1 不变；ShowStart 时地图一并隐藏

        /// 只允许从 PlayCard / EndTurn 调用。Victory 未通关禁止 Begin，见 4.3。
        private void ApplyOutcomeIfEnded();
    }
}
```

**[已定] 产品侧 `battleController.Begin` 只出现在 `EnterCurrentNode` 的 `Combat` 分支。** `StartRun` 与 `ApplyOutcomeIfEnded` 都不得 `Begin`。

`SetPages` 改为四页显隐（Start / Map / Combat / Result 同一时间只一张）。`ShowMap` 显示地图并 `mapPageView.Refresh()`、`RefreshShell()`。胜利未通关、`StartRun` 上地图都走这一条，不要在 `ApplyOutcomeIfEnded` 里另写一套显隐。

遗物字典相对 1.1 **时机不变**，只是第一次 `Begin` 从 `StartRun` 挪到 `EnterCurrentNode`：

| 时机 | 做 |
| --- | --- |
| `StartRun` | 校验通过后、**任何 `Begin` 之前**调一次 `SetRelicDisplayNames(runConfig.Relics)` |
| 场间回地图 / 再 `EnterCurrentNode` | **不再**填字典 |
| 通关 / 失败 `DiscardSession` | **不清**字典 |
| `Restart` | 空列表清空 |

`Begin` / `DiscardSession` 仍不碰 `_relicDisplayNames`。`RelicDisplayName` 一字不改。

文件里**不要** `void Update()`。

### 4.5 RunConfig

**[已定] 本版不改字段、不改 `TryValidate`、不改 `CreateRunState`。** 三场敌人仍是遭遇表；类型不是 SO 上的第二列。不要在 Inspector 里露出商店类型。

生命 / 能量 / 手牌仍不写 80 / 3 / 5。空牌组仍拒。

### 4.6 地图 UI **[已定]**

总设计第 6 节：三个点、一条线、一个进入按钮。圆点只展示，不是按钮（避免给已完成 / 未到节点挂点击）。1.2 游戏设计按这一条收口。

```csharp
namespace CardRPGFramework.Views
{
    public sealed class MapPageView : MonoBehaviour
    {
        [SerializeField] private RunController runController;
        [SerializeField] private Button enterButton;
        // 三个点：Image 或任意 Graphic 即可，用颜色区分状态；不要做成按钮。

        private void Start();   // enterButton → runController.EnterCurrentNode；跟 StartPageView 一样，不要改 Awake
        public void Refresh();  // 只读 Run.NodeIndex：已完成灰、当前高亮、未到暗。点未接线时跳过，第 1 节可先空挂。
    }
}
```

`Run == null` 时地图不可见，`Refresh` 不必为 Start 页服务。不要读 `RunConfig`。不要在地图上印敌人名 / 牌组。进入后由流程切 Combat 并 `battleView.Refresh()`。

`MapPageView` 只调 `EnterCurrentNode`。不要调 `PlayCard` / `Begin` / `ApplyResult`。

### 4.7 BattleController / 战斗页

相对 1.1 **不改合同**。`Begin` / `DiscardSession` / `SetRelicDisplayNames` / 局内转发仍按 1.1。`BattleView` 仍只打 `RunController.PlayCard` / `EndTurn`。不要把 `NodeType` 或地图按钮塞进战斗页。

## 5. 测试策略

- **不要**重写 1.0 的 `IsCleared` / 三场 `ApplyResult` 用例。不要写「Victory 且未通关 → 再 `Begin`」这种 1.1 场间复述——那正是本版要删的。
- `RunStateTests` 只加 4.2 的 NodeType 项。`RunController` 是 MonoBehaviour，不抽 `RunLoop`；地图枢纽与「第二场开局生命」靠 Play。
- Play：开始 → **地图** → 进入第一场 → 胜利回地图（节点 0 灰、1 高亮）→ 进入第二场（开局生命 = 第一场结束生命）→ 胜利回地图 → 进入第三场 → 通关 Result；中途死亡 → 失败 Result、不回地图；再来一局后 Start 顶栏 `遗物：无`。漏配仍进不了局。
- `RunConfig.TryValidate` 仍不写 EditMode。
- 验收 grep：
  - `RunController.cs` 没有 `Update`。
  - `battleController.Begin` 只出现在 `EnterCurrentNode`。
  - `ApplyResult` 只出现在 `ApplyOutcomeIfEnded`。
  - `Assets/Scripts/Runtime/Core/Battle/`、`BattleInput.cs`、`BattleSetup` 没有 `NodeType`。
  - `BattleView` 仍不调 `battleController.PlayCard` / `EndTurn`。
  - `Begin` / `DiscardSession` 仍不出现 `_relicDisplayNames`。

## 6. 排除项

- 奖励页、三选一、`g(runSeed, rewardIndex)`（1.3）。
- 空商店 / 休息 / 事件页；预声明这些 `NodeType` 值；分支图；下一节点列表。
- EventBus、拆场景、异步加载、抽 `RunLoop`。
- 改 `BattleSession` 构造签名；把 `NodeType` 塞进 Session / `BattleInput` / `BattleSetup`。
- `Update` / 协程读 `Phase` 或 `ApplyResult`。
- 场间先 `CreateBattleInput` 再 `ApplyResult`；未通关 Victory 仍 `Begin`。
- 圆点当按钮；为 Start / 地图预填 80 / 10。
- 公开 `RunState` 遭遇表只为了在地图上写敌人名。

## 7. 关键技术决策

| 决策 | 1.2 选择 | 原因 |
| --- | --- | --- |
| 开始一局去哪 | [已定] 地图，不 `Begin` | 地图是枢纽；1.1 自动开战是没有地图时的权宜 |
| 第一次 `CreateBattleInput` | [已定] `EnterCurrentNode` 的 Combat 分支 | 类型分发之后才需要战斗输入；Shop 将来不应预支战斗种子 |
| 胜利未通关 | [已定] `DiscardSession` 回地图，禁止 `Begin` | 否则跳过地图，本版边界证伪 |
| 回地图是否丢 Session | [已定] 必须 `DiscardSession` | 否则 `IsReady` 挡住进入、顶栏误跟局内 |
| 通关 / 失败 | [已定] 仍 Result，失败不回地图 | 与 1.1、总设计一致 |
| 写回通道 | [已定] 仍 `PlayCard` / `EndTurn` 内一次 | 与 1.1 相同风险：第二入口会打穿 1.0 |
| 地图进入 | [已定] 一个进入按钮，圆点只展示 | 总设计第 6 节；点三个点当按钮会让已完成 / 未到需要额外拒绝 |
| 地图是否印敌人名 | [已定] 否 | 没有第二个消费者，不公开遭遇表 |
| `RunConfig` | [已定] 本版不改 | 三场仍是遭遇表；类型不是第二套 Inspector 列 |
| `NodeType` 枚举取值 | [已定] 只有 `Combat` | 有消费者才加原语；商店进候选池再加枚举值与页 |
| 遗物字典 | [已定] 合同同 1.1，首次 `Begin` 改到进入节点 | `StartRun` 仍在任何 `Begin` 前填一次 |
| Session 构造 | [已定] 相对 1.0 / 1.1 不变 | 本版证明的是流程分发，不是战斗入口 |

## 8. 完成定义

- 游戏设计第 4 节验收满足。
- 产品侧 `Begin` 只在 `EnterCurrentNode`；`StartRun` / `ApplyOutcomeIfEnded` 不 `Begin`。
- 产品侧 `ApplyResult` 只在 `ApplyOutcomeIfEnded`、每节点一次；`RunController` 无 `Update`。
- `Core/Battle` 与 `BattleInput` / `BattleSetup` 无 `NodeType`。Session 构造签名不变。
- `SetRelicDisplayNames` 仍只由 `RunController` 按 4.4 调用。
- 无奖励页、无空商店页。
- 0.x～1.1 测试不改断言通过。
