# 1.2 游戏设计：地图与节点分发

> **交付目标：地图成为枢纽。** 三个战斗节点一条线，只能进当前节点；胜利回地图，最后一场去结束页。节点带类型，流程按类型开页；`BattleSession` 里没有 `NodeType`。
>
> 不做空商店页、不做分支图、不做奖励页（1.3）。
>
> 总设计见 [`../游戏设计.md`](../游戏设计.md) 第 4、6 节。进入本版前补技术设计与 TODO。

## 1. 设计原则

- **新节点类型 = 新页 + 流程一个分支**，不改 `BattleSession`、不改战斗页。
- 地图页只是枢纽：显示当前 / 已完成节点，进入当前节点。未实现的类型进不了地图。
- 1.1 的"胜利自动下一场"改为"胜利回地图"。

## 2. 本版做 / 不做

| 做 | 不做 |
| --- | --- |
| 三个战斗节点一条线；当前高亮、已完成变灰 | 分支、下一节点列表 |
| `NodeType`；流程按类型分发（本版只有战斗） | 空商店 / 休息 / 事件页占位 |
| 胜利回地图；最后一场胜利或失败 → 结束页 | 随机遭遇生成器 |
| 只能进入当前节点 | 改 Session 构造或内部加 `NodeType` |

敌人仍按总设计：第 1 场颚虫、第 2 场蓝奴隶贩子、第 3 场颚虫（至少两种，允许重复）。

## 3. 验收标准

- 地图上三个点、一条线；只能点当前节点进入战斗。
- 第一、二场胜利后回到地图，当前节点前进；第三场胜利去结束页。
- 代码里新增一种节点类型不需要改 `BattleSession`。
- 1.1 的连打与顶栏仍成立；没有奖励页。
- 0.x～1.1 测试不改断言通过。
