# 1.2 游戏设计：地图与节点分发

> **交付目标：地图成为枢纽。** 三个战斗节点一条线，只能进当前节点；胜利回地图，最后一场去结束页。节点带类型，流程按类型开页；`BattleSession` 里没有 `NodeType`。
>
> 不做空商店页、不做分支图、不做奖励页（1.3）。
>
> 总设计见 [`../游戏设计.md`](../游戏设计.md) 第 4、6 节。1.1 已完成。技术设计 / TODO 已转正，无未拍的 **[待确认]**。

## 1. 设计原则

- **新节点类型 = 新页 + 流程一个分支**，不改 `BattleSession`、不改战斗页。
- 地图页只是枢纽：显示当前 / 已完成节点，进入当前节点。未实现的类型进不了地图。
- 1.1 的「胜利自动下一场」改为「胜利回地图」。开始一局先到地图，不要自动开战。

## 2. 本版做 / 不做

| 做 | 不做 |
| --- | --- |
| 三个战斗节点一条线；当前高亮、已完成变灰 | 分支、下一节点列表 |
| `NodeType`；流程按类型分发（本版只有战斗） | 空商店 / 休息 / 事件页占位 |
| 胜利回地图；最后一场胜利或失败 → 结束页 | 随机遭遇生成器 |
| 只能进入当前节点 | 改 Session 构造或内部加 `NodeType` |

敌人仍按总设计：第 1 场颚虫、第 2 场蓝奴隶贩子、第 3 场颚虫（至少两种，允许重复）。

```text
开始页：[开始一局] → StartRun
  ↓
RunConfig.TryValidate → CreateRunState → 填遗物字典 → 地图页（不 Begin）
  ↓
地图页：[进入] → EnterCurrentNode → 按 NodeType 分发
  ├─ Combat → CreateBattleInput → Begin → 战斗页
  └─ 未实现类型 → 留在地图（不 Begin）
  ↓
战斗页：点牌 / 结束回合（只打 RunController）
  ├─ Defeat → ApplyResult(false, …) → DiscardSession → 结束页（失败）
  └─ Victory → ApplyResult(true, 局内生命)
        ├─ 尚未通关 → DiscardSession → 地图页（当前节点已前进）
        └─ 已通关 → DiscardSession → 结束页（通关）
  ↓
结束页：[再来一局] → Restart → 开始页
```

1.3 会在「胜利写回」与「回地图 / 结束页」之间插入奖励页。本版不要预留空奖励页或挂钩。

## 3. 地图页

总设计第 6 节：三个点、一条线、**一个进入按钮**。圆点只展示状态，不是按钮。

| 节点 | 展示 |
| --- | --- |
| 已完成（下标 `< NodeIndex`） | 变灰 |
| 当前（下标 `== NodeIndex`） | 高亮 |
| 未到（下标 `> NodeIndex`） | 暗，不能进 |

进入按钮只进当前节点。战斗页内没有选下一场或回地图的控件。

顶栏：地图页不在战斗中，生命读 `RunState`。Start 页仍不读 `RunConfig`。战斗中生命仍跟局内。

## 4. 验收标准

- 点「开始一局」先到地图，不自动开战。地图三个点、一条线；当前高亮、已完成变灰；一个进入按钮。
- 第一、二场胜利后回到地图，当前节点前进；第三场胜利去结束页，不再回地图。
- 第二场开局生命等于第一场结束时的生命（Play 验收；必须先 `ApplyResult` 再在进入时 `CreateBattleInput`）。
- 中途死亡进入失败结束页，不回地图。再来一局后 Start 顶栏 `遗物：无`。
- 代码里新增一种节点类型不需要改 `BattleSession`；`BattleInput` / `BattleSetup` 仍不塞 `NodeType`。
- 1.1 的顶栏合同仍成立。没有奖励页。战斗页内没有选卡或进下一场的控件。
- 0.x～1.1 测试不改断言通过。
