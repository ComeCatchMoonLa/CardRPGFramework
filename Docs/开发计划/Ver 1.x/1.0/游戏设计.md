# 1.0 游戏设计：短 Run 闭环

> **交付目标：从开始界面进入一局，连打三场不同的战斗，每场胜利后三选一加卡，生命 / 牌组 / 遗物跨场保留，打完或死亡进入结束页并可重开。局外状态（`RunState`）与局内状态（`BattleSession`）是两套东西，进出战斗有明确的转换点；界面分成常驻的 Run 壳与可换的页，以后加商店 / 休息 / 事件是加页，不是改战斗界面。**
>
> 不做分支地图、商店、休息处、事件、遗物奖励、卡牌移除 / 升级、存档、金币消费。
>
> **本文只写游戏设计。技术设计与 TODO 在进入 1.0 之前再写**（见 [`../../README.md`](../../README.md) 第 2 节），第 7 节先列出那时必须回答的技术问题。

## 1. 设计原则

- **局外是状态，不是规则系统。** `RunState` 只保存生命、牌组、遗物、金币；进战斗时拷贝成局内状态，出战斗时写回生命。不存在"局外 RuleSystem"（[`../../../Phase 2 扩展边界批注.md`](../../../Phase%202%20扩展边界批注.md) 第 5 节）。
- **先买扩展方式，不买内容量。** 三个节点全是战斗，但节点带类型、界面分壳与页；以后加节点类型不碰 `BattleSession` 和战斗页。
- **战斗页只管局内。** 选卡、进下一场、结束页都属于 Run 流程，不塞进 `BattleView`。
- 数值取原版铁甲战士开局：80 生命、3 能量、5 张手牌、起始牌组 10 张。

## 2. 一局的流程

```text
开始页：[开始一局]
  ↓
初始化 RunState：80/80 生命，起始牌组 10 张，起始遗物 1 件，金币 0
  ↓
地图页：一条线上三个战斗节点，当前节点高亮；[进入战斗]
  ↓
战斗页：用 RunState 构造 BattleSession（生命、牌组、遗物、本节点的敌人）
  ├─ 失败 → 结束页（失败）
  └─ 胜利 → 写回剩余生命 → 奖励页
        ↓
奖励页：从奖励池随机三张，选一张加入牌组，或跳过
        ↓
不是最后一个节点 → 地图页，当前节点前进
是最后一个节点   → 结束页（胜利）
  ↓
结束页：显示结果与本局摘要（打了几场、牌组张数）；[再来一局] 回到开始页
```

## 3. Run 状态

| 字段 | 初始 | 变化 |
| --- | --- | --- |
| 当前生命 / 最大生命 | 80 / 80 | 战斗结束写回当前生命；本版本没有回复来源 |
| 牌组 | 5 打击、4 防御、1 痛击 | 奖励页选卡加入 |
| 遗物 | 起始 1 件（默认金刚杵，可配置） | 本版本不增减 |
| 金币 | 0 | 本版本不变；字段存在是为了顶栏与以后的商店不再挖坑 |
| 当前节点 | 0 | 每场胜利后 +1 |

局内 / 局外转换规则：

- **进战斗**：局内生命 = Run 当前生命；牌堆由 Run 牌组洗出；遗物栏 = Run 遗物；敌人由节点决定。局内的格挡、能量、Buff、消耗堆都是本场临时状态，不来自 Run。
- **出战斗（胜利）**：Run 当前生命 = 局内剩余生命。牌组不变（本场消耗、弃牌都不影响 Run 牌组）。
- **出战斗（失败）**：直接结束页，Run 作废。

## 4. 地图与节点

| 项 | 1.0 |
| --- | --- |
| 形状 | 一条线，三个节点 |
| 节点类型 | 全部为"战斗"；数据上节点带类型字段 |
| 敌人 | 第 1 场颚虫、第 2 场蓝奴隶贩子、第 3 场颚虫（数值可配；三场不同敌人优先，敌人数量不够时允许重复） |
| 地图页 | 三个圆点 + 连线，当前节点高亮，已完成节点变灰，只能进入当前节点 |

以后的扩展方式（现在不实现，但数据形状要允许）：

- 加休息 / 商店 / 事件 / Boss：节点类型多一个值，流程按类型打开对应页；地图页只是多一种图标。
- 加分支：节点带"下一节点列表"，地图页从一条线变成图；流程仍是"当前节点 → 对应页 → 完成 → 走到玩家选的下一节点"。
- 加随机遭遇：节点的敌人由生成器在进战斗时用 Run 种子决定。

1.0 不要做空的商店页占位；**要做的是节点带类型、流程按类型分发**，未实现的类型进不了地图即可。

## 5. 奖励

- 奖励池 = 所有可获得的卡牌配置（0.2～0.4 的痛击 / 双击 / 剑柄打击 / 坚不可摧 / 力量强化 / 剧毒 / 虚弱 / 易伤 / 治疗），排除打击与防御。
- 每次从池中随机三张不同的卡；用 Run 种子，保证同一种子同一局结果可复现。
- 选一张加入牌组，或跳过。选完立刻在顶栏看到牌组张数 +1。
- 本版本不做遗物奖励、金币奖励、卡牌移除与升级。

## 6. 界面：Run 壳与页

```text
RunShell（常驻，整局不销毁）
  ├── 顶栏：生命 80/80 | 金币 0 | 牌组 10 | 遗物：金刚杵
  └── 主区：同一时间只显示一页
        StartPage | MapPage | CombatPage | RewardPage | ResultPage
        （以后：RestPage | ShopPage | EventPage）
```

| 层 | 1.0 要做的 | 以后加节点类型时 |
| --- | --- | --- |
| 流程 | 当前页 + 当前节点下标；胜利 / 失败 / 选完卡 / 点击进入等事件驱动换页 | 新页对应一个新的页 Id 与流程分支 |
| 顶栏 | 读 `RunState` 显示；战斗中生命显示局内值（Run 值在出战斗时才写回，两者战斗中允许不同，顶栏跟局内） | 加遗物 = 顶栏遗物排多一项，不改布局 |
| 战斗页 | 现有 `BattleView` 及其子视图整体作为一页；结束遮罩改为"胜利 → 通知流程"，不再自己拦住玩家 | 多敌人只改这一页 |
| 奖励页 | 三张候选卡（复用卡面描述生成）+ 跳过 | 商店是另一页，不复用奖励页写死的"三张" |
| 地图页 | 三个点、一条线、一个进入按钮 | 变图时只改这一页 |
| 结束页 | 结果 + 摘要 + 再来一局 | 不变 |

Unity 落地保持最小：同一个场景，几个 Panel 显隐，不做 UI 框架、不拆场景、不做异步加载。等真有三种以上非战斗页再考虑是否拆场景。

## 7. 技术要点（写技术设计时必须回答）

1. **`RunState` 放在 `Core.Run`**，纯 C#，不引用 Unity；包含"进战斗转换（输出 `BattleSetup` + 牌组 + 遗物）""出战斗写回""加卡"三个操作，各有测试。
2. **`RunConfig` SO**：玩家生命 / 能量 / 手牌数、起始牌组、起始遗物、三个节点的敌人配置、奖励池。`BattleConfig` 是否保留给 `TestScene` 单场快速调试，还是被 `RunConfig` 取代——二选一，不留两套真相。
3. **`BattleController` 改为被流程创建 / 销毁**：不再在 `Awake` 里读 `BattleConfig`，改为 `Begin(BattleSetup, deck, relics, enemy, random)`；`BattleView` 现有的"命令后刷新"模式不变。
4. **流程控制器**（`RunController`）：持有 `RunState` 与当前页；换页 = 显隐 Panel；战斗胜利 / 失败由 `BattleController` 通过回调或轮询状态告知流程，不引入事件总线。
5. **随机源**：Run 种子派生战斗种子与奖励抽取，保证"同一种子同一局"可复现；`useFixedSeed` 开关上移到 `RunConfig`。
6. **顶栏数据来源**：战斗中读局内生命，其它页读 `RunState`；两者战斗中不同步是设计而不是 bug，技术设计要写清。
7. **风险**：`EndScreenView` 现在自己拦操作，1.0 要改成通知流程；奖励页的卡面直接用 0.2 的 `CardDescriptionFormatter.Format(CardDefinition)`（基础数值、不依赖 Controller），不要用 0.3 带预览委托的重载——没有战斗就没有预览。

## 8. 验收标准

- 从开始页点一次进入，连打三场到结束页，全程不回 Editor。
- 第二场开局生命等于第一场结束时的生命；第一场胜利后选的卡在第二场能抽到；起始遗物三场都在遗物栏且生效。
- 三场敌人按配置出现，至少两种不同。
- 奖励页三张互不相同且不含打击 / 防御；跳过后牌组张数不变。
- 战斗页内没有选卡或进下一场的控件；顶栏在地图 / 战斗 / 奖励 / 结束之间切页时始终存在。
- 中途死亡进入失败结束页；再来一局后 Run 从初始状态开始。
- 固定种子下两局的洗牌顺序与奖励候选一致。
- 代码里新增一种节点类型不需要改 `BattleSession`；`RunState` 有 EditMode 测试；0.x 全部测试不改断言通过。

局外规则对照 [`../../../杀戮尖塔机制研究.md`](../../../杀戮尖塔机制研究.md) 第 1 节（二代把 Run 与战斗分成两层状态）。
