# 1.0 游戏设计：`RunState`

> **交付目标：局外第一次以纯 C# 状态出现。** `RunState` 持有一局的生命、牌组、遗物、金币、当前节点和主种子；能输出一场战斗的输入、能接收一场的胜负与剩余生命、能往牌组里加卡。Play 仍是 `TestScene` 单场，本版没有任何 Run UI。
>
> 不做 Run 壳、地图、奖励页、`RunConfig` SO。`BattleController` 里 0.x 的 `new BattleSession` 原样保留。
>
> 总设计见 [`../游戏设计.md`](../游戏设计.md)。技术实现见 [`技术设计.md`](技术设计.md)，执行顺序见 [`TODO.md`](TODO.md)。

## 1. 设计原则

- **局外是状态，不是规则系统。** 不存在"局外 RuleSystem"。进战斗是快照，出战斗只写回约定结果。
- **Run 不创建战斗。** `CreateBattleInput` 返回 `BattleInput`，不返回 `BattleSession`。测试辅助（以及以后的流程层）拿这份输入去 `new BattleSession`。
- **当前节点只是 `int`。** 给 `f(runSeed, nodeIndex)` 派生本场 `Random`；`NodeType` 是 1.2。

## 2. 本版做 / 不做

| 做 | 不做 |
| --- | --- |
| `RunState`：生命、牌组、遗物 Id、金币恒 0、当前节点 `int`、主种子、开局三份 `EnemyDefinition` | 任何 Run UI；`RunConfig` SO |
| `CreateBattleInput` → `BattleInput`（含当前生命） | `new BattleSession`（`Core.Run` 与本刀新文件） |
| `ApplyResult(won, remainingHp)` | 把牌组 / 消耗 / 弃牌写回 Run |
| `AddCard`（1.3 才抽三张） | 地图、奖励页、节点类型 |
| 每场 `f(runSeed, nodeIndex)` 新建 `Random`，用完即弃 | 改 `BattleController.Awake` |

数值约定与总设计一致：测试里自己传入 80 / 3 / 5、起始牌组、起始遗物 Id、三场敌人；本版没有配置资产当真相。

## 3. 转换规则

- **进战斗**：局内生命 = Run 当前生命；牌组列表浅拷贝（不洗）；遗物每次新建实例；敌人取当前节点那一份。洗牌发生在 `CardPile` 用这份拷贝和本场 `Random` 构造之时。格挡、能量、Buff、消耗堆是本场临时状态。
- **出战斗（胜利）**：写回剩余生命，`nodeIndex++`。牌组不变。
- **出战斗（失败）**：标记失败，不写生命、不推进节点。Run 作废，不能再要下一场输入。
- 同一节点可以多次 `CreateBattleInput`（每次同一战斗种子）；`ApplyResult` 必须先有过一次输入，且每节点一次。重复调用拒绝，不静默。
- **`AddCard`**：失败后拒绝；通关后仍允许。`IsCleared` 表示没有下一场战斗，不表示牌组冻结（第三场胜利先写回，1.3 的奖励页还要加卡）。

## 4. 验收标准

全部 EditMode，不要求 Play 连打三场。

- 进战斗快照与 Run 解耦：残血开战可以不经 `RunState`，只靠 `BattleSetup` 第四参。
- 写回后第二场输入是残血；`AddCard` 后下一场牌组含新卡。三场胜利后 `AddCard` 仍成功，再 `CreateBattleInput` 仍抛。
- 本场消耗、弃牌不写回 Run 牌组。
- 同一 `runSeed` + 同一节点得到同一战斗种子。
- 重复 `ApplyResult`、失败或通关后再 `CreateBattleInput` 均被拒绝。
- `Core/Run/` 与本刀新增的 Runtime 文件 grep 不到 `new BattleSession`。测试辅助可以 `new`；`BattleController` 那一处不算本刀范围。
- 0.x 全部测试不改断言通过（`BattleSetup` 三参仍是满血）。
