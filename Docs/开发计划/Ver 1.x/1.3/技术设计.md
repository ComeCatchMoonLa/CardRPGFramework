# 1.3 技术设计：战后三选一

> **技术目标：奖励抽卡发生在战斗页之外。** 胜利写回并 `DiscardSession` 后上奖励页，用 `g(runSeed, rewardIndex)` 从奖励池抽出三张不同的 `CardDefinition`；玩家 `AddCard` 或跳过后再去地图 / 结束页。战斗 `Random` 与奖励抽取互不消费。`BattleSession` 构造不变，不新增 `NodeType`。无遗物奖、无升级、无移除。
>
> 玩法要求见 [`游戏设计.md`](游戏设计.md)，执行顺序见 [`TODO.md`](TODO.md)。总设计见 [`../游戏设计.md`](../游戏设计.md)。对照 1.2：[`../1.2/技术设计.md`](../1.2/技术设计.md)。`AddCard` 合同对照 1.0：[`../1.0/技术设计.md`](../1.0/技术设计.md) 第 4.3 节。
>
> 抽取公式、奖励池挂在 `RunConfig`、流程插入点、卡面类型中文抽成 `CardTypeDisplayNames` 均已定。无未拍的 **[待确认]**。

## 1. 技术原则

- **奖励是流程步骤，不是节点类型。** 1.2 证明的是「新 `NodeType` = 新页 + `switch` 一个分支」。本版的奖励页接在战斗胜利之后，三个节点仍全是 `Combat`。禁止给 `NodeType` 加 `Reward`。
- **结束写回仍是单通道。** `PlayCard` / `EndTurn` 返回前读一次 `Phase`，至多一次 `ApplyResult`。禁止 `Update`。相对 1.2，Victory 无论是否通关都先写回、丢掉 Session、上奖励页；去地图还是去 Result 推迟到选完 / 跳过。失败仍不经奖励页。
- **奖励 RNG 用完即弃，与战斗种子同形、不同常数。** `CreateRewardChoices` 自己 `new Random(g(...))`，不调用 `CreateBattleInput` 返回的那份 `Random`，也不在 `RunState` 上持有。同一 `rewardIndex` 多次抽取结果相同（与同一节点多次 `CreateBattleInput` 同形）。
- **有消费者才抽公共类型名。** 奖励页是卡面类型中文的第二个调用方，把 `BattleView` 私有 `TypeLabel` 抽成 `CardTypeDisplayNames`（0.4 已预定）。不要为此新建 UI 框架，不要给奖励页做预览委托。
- **构造签名不扩。** `RunState` 仍是 1.0 那五个参数；奖励池是抽取时传入的只读列表，产品侧挂在 `RunConfig` 上。不要为 1.4 的 asmdef 改命名空间或挪文件。

## 4. 核心接口

### 4.1 奖励种子与 rewardIndex **[已定]**

战斗种子 1.0 已定：`f(runSeed, nodeIndex) = unchecked(runSeed * 397 ^ nodeIndex)`。

**[已定] 奖励种子。** `g(runSeed, rewardIndex) = unchecked(runSeed * 389 ^ rewardIndex)`。389 是靠近 397 的另一个小质数，避免 `g(seed, 0)` 与 `f(seed, 0)` 撞同一种子、测试里看起来像共用了战斗 RNG。不使用 `HashCode.Combine`。测试可以按这个公式自算期望种子。

**[已定] `rewardIndex = 胜利写回后的 NodeIndex - 1`。** 本版三个节点全是战斗，`ApplyResult(true, …)` 之后 `NodeIndex` 为 1 / 2 / 3，对应第 0 / 1 / 2 次奖励。不要另加 `_rewardCount` 字段——以后非战斗节点进候选池时再单独计数。`NodeIndex == 0`（还没赢过）禁止抽取。

| 时机 | NodeIndex | rewardIndex | 备注 |
| --- | --- | --- | --- |
| 开局 / 尚未胜利 | 0 | 不可用 | `CreateRewardChoices` 抛 |
| 第一场胜利写回后 | 1 | 0 | 未通关，选完回地图 |
| 第二场胜利写回后 | 2 | 1 | 未通关，选完回地图 |
| 第三场胜利写回后 | 3 | 2 | `IsCleared == true`，选完去 Result；`AddCard` 仍允许 |

失败后 `IsFailed`，不抽取。同一 `rewardIndex` 多次 `CreateRewardChoices` 不推进节点、不改牌组。

### 4.2 RunState.CreateRewardChoices

```csharp
namespace CardRPGFramework.Core.Run
{
    public sealed class RunState
    {
        // 1.0 / 1.2 已有成员一字不改语义：CreateBattleInput / ApplyResult / AddCard /
        // IsCleared / NodeTypes / CurrentNodeType …
        // 构造仍是 (runSeed, playerSetup, deck, relicIds, encounters)

        /// 从 pool 无放回抽 3 张。返回新列表（3 个 CardDefinition 引用），调用方改列表不影响下次抽取。
        /// 只在 IsFailed 或 NodeIndex == 0 时抛 InvalidOperationException。
        /// **不要写成 if (IsOver)**：第三场写回后 IsCleared / IsOver 已为 true，这时必须还能抽。
        /// CreateBattleInput 才看 IsOver，两条门槛不是同一条。
        /// pool 为 null 抛 ArgumentNullException；不足 3 张、含 null、Id 重复抛 ArgumentException。
        /// 不在 Core 里按 "Attack" / "Defend" 过滤——那是 RunConfig 的产品约束。
        public IReadOnlyList<CardDefinition> CreateRewardChoices(IReadOnlyList<CardDefinition> pool);
    }
}
```

**[已定] 抽样算法与 `CardPile` 洗牌同形。** 浅拷贝 `pool` 到 `List<CardDefinition>`，再：

```csharp
var rng = new Random(unchecked(RunSeed * 389 ^ (NodeIndex - 1)));
for (var i = copy.Count - 1; i > 0; i--)
{
    var j = rng.Next(i + 1);
    (copy[i], copy[j]) = (copy[j], copy[i]);
}
return copy.GetRange(0, 3);
```

不要用另一套「循环 `Next` 直到 3 个下标不重复」。`CreateRewardChoices` **不**调用传入池以外的 `Random`，**不**调用 `CreateBattleInput` 已经发出的那份 `Random`，**不**预支 `Next` 之外的用途。

`AddCard` / `ApplyResult` / `CreateBattleInput` 相对 1.0 **断言不改**。通关后 `CreateRewardChoices` 必须成功（第三场奖励），`CreateBattleInput` 仍抛。第 5 节这条 EditMode 不要省略——抄 `IsOver` 会在 Core 里炸掉，Play 还没走到选卡。

### 4.3 结束写回（相对 1.2 只改 Victory 去向）

**[已定] 仍禁止 `Update`。** `ApplyOutcomeIfEnded` 仍只从 `PlayCard` / `EndTurn` 调用。失败只认 `Phase == Defeat`。场间仍 **先 `ApplyResult`**，再 `DiscardSession`；不要先 `CreateBattleInput`。

| `Phase` | 写回 | UI（相对 1.2 的变化） |
| --- | --- | --- |
| `Victory`（无论是否 `IsCleared`） | 先 `ApplyResult(true, 局内生命)` | **`DiscardSession`（不清字典）→ `ShowReward`。禁止 `Begin`，禁止在这里 `ShowMap` / `ShowResult`。** |
| `Defeat` | `ApplyResult(false, …)` | 与 1.2 相同：`DiscardSession`（不清字典）→ Result（失败）。**不经奖励页、不回地图** |

1.2 通关 Victory 直接 Result，会跳过第三场奖励，是本版要删的路径。选完 / 跳过后：`IsCleared` → Result，否则 → `ShowMap`。`resultPageView.SetOutcome` 只在真正 `ShowResult` 时调（摘要牌组张数要含本场 `AddCard`）。

**[已定] 产品侧 `AddCard` 只出现在 `SelectReward`。** `ApplyOutcomeIfEnded` 只写回，不加卡。跳过不调 `AddCard`。

### 4.4 RunController

```csharp
namespace CardRPGFramework.Controllers
{
    public sealed class RunController : MonoBehaviour
    {
        [SerializeField] private RunConfig runConfig;
        [SerializeField] private BattleController battleController;
        [SerializeField] private BattleView battleView;
        [SerializeField] private MapPageView mapPageView;
        [SerializeField] private RewardPageView rewardPageView;
        [SerializeField] private RunShellView runShellView;
        [SerializeField] private ResultPageView resultPageView;
        [SerializeField] private GameObject startPage;
        [SerializeField] private GameObject mapPage;
        [SerializeField] private GameObject combatPage;
        [SerializeField] private GameObject rewardPage;
        [SerializeField] private GameObject resultPage;

        public RunState Run { get; private set; }

        /// 当前奖励三张。未在等选时为空列表，不要 null；字段初始 Array.Empty，Awake 不要赋 null。
        /// ShowReward 赋值为恰好 3 张；SelectReward / SkipReward / Restart 清成空。
        /// View 只读这个出口，禁止自己调 CreateRewardChoices。
        public IReadOnlyList<CardDefinition> RewardChoices { get; private set; }

        /// 校验失败则 LogError 并停留在 Start。通过则 CreateRunState → 填遗物字典 → ShowMap。
        /// 不 CreateBattleInput、不 Begin、不上奖励页。
        public void StartRun();

        /// Run == null / IsOver / IsReady / RewardChoices.Count != 0 则直接 return。
        /// 未开战就是 Run == null，不要写成 !IsReady。
        /// 否则 switch CurrentNodeType，Combat 分支与 1.2 相同。
        public void EnterCurrentNode();

        public bool PlayCard(int handIndex);   // 相对 1.2 不变：转发后 ApplyOutcomeIfEnded
        public bool EndTurn();

        /// 未在等选奖励则 return。下标不在 0..2 则 return。
        /// AddCard(RewardChoices[index]) → 清 RewardChoices → RefreshShell → 未通关 ShowMap，通关 ShowResult。
        public void SelectReward(int index);

        /// 未在等选奖励则 return。不加卡，其余去向与 SelectReward 相同。
        public void SkipReward();

        public void Restart();                 // 相对 1.2 不变；ShowStart 时奖励页一并隐藏；RewardChoices 清成空

        /// 只允许从 PlayCard / EndTurn 调用。Victory 见 4.3。
        private void ApplyOutcomeIfEnded();
    }
}
```

**[已定] 产品侧 `battleController.Begin` 只出现在 `EnterCurrentNode` 的 `Combat` 分支。** `StartRun` / `ApplyOutcomeIfEnded` / `SelectReward` / `SkipReward` 都不得 `Begin`。

**[已定] 等待选奖励期间禁止进入下一场。** 等待标志就是 `RewardChoices`：空列表 = 未等待；`ShowReward` 赋值为恰好 3 张。不要另做一套 `_awaitingReward` 再和缓存打架。`SelectReward` / `SkipReward` / `Restart` 清成空列表。`EnterCurrentNode` 在 `RewardChoices.Count != 0` 时直接 return——否则 Session 已丢、`IsReady` 为 false，会跳过奖励直接 `Begin` 下一场，本版边界证伪。

奖励页时地图是藏的，Play 点不到「进入」，**不能用 Play 绿证明这道早退**。靠 `EnterCurrentNode` 方法体里的条件与第 5 节 grep。

`SetPages` 改为五页显隐（Start / Map / Combat / Reward / Result 同一时间只一张）。`ShowReward` 显示奖励页并 `rewardPageView.Refresh()`、`RefreshShell()`。不要在 `ApplyOutcomeIfEnded` 里另写一套显隐。

遗物字典相对 1.2 **时机不变**：`StartRun` 在任何 `Begin` 前填一次；场间 / 奖励页不填；通关 / 失败 `DiscardSession` 不清；`Restart` 空列表清空。

文件里**不要** `void Update()`。不要把 `RunConfig` 传进 `BattleSession`。

当前三张只活在 `RewardChoices`：`ShowReward` 时 `Run.CreateRewardChoices(从 runConfig.RewardPool 转出的 CardDefinition 列表)` 赋进去，`RewardPageView.Refresh` 与 `SelectReward` 都读它。不要在 `Refresh` 里换一份新的 `Random`——`CreateRewardChoices` 本身幂等，再调一次也可以，但 View 只读 `RewardChoices`，不要自己调 `RunState`。不要给 `Refresh` 加 `IReadOnlyList` 参数当第二出口。

### 4.5 RunConfig

**[已定] 本版只加奖励池，不改生命 / 牌组 / 遭遇表字段。** `CreateRunState` 仍五参构造，**不**把奖励池塞进 `RunState`。

```csharp
[SerializeField] private List<CardData> rewardPool = new();   // 不要预填 9 张到类型默认值

public IReadOnlyList<CardData> RewardPool => rewardPool;
```

`TryValidate` 在既有检查之外追加：

| 项 | 拒绝 |
| --- | --- |
| `rewardPool` null / 不足 3 张 | 是 |
| 空引用 / 某张 `CardData.TryValidate` 失败 | 是 |
| 两份不同 `CardData` 同 Id；同一资产引用两次 | 是（三张必须能互不相同） |
| Id 为 `Attack` 或 `Defend`（与 `Assets/Data/Cards/Attack.asset` / `Defend.asset` 一致） | 是 |
| 池里有痛击而起始牌组也有痛击 | 否（总设计允许） |
| 名单必须恰好那 9 个中文名 | 否（内容写在 `Default` 资产上，不要写进类型） |

产品资产 `Assets/Data/Runs/Default.asset` 配总设计那 9 张：Bash / TwinStrike / PommelStrike / Impervious / Strength / Poison / Weak / Vulnerable / Heal。`RunConfig.TryValidate` 仍不写 EditMode。

### 4.6 奖励 UI 与 CardTypeDisplayNames **[已定]**

```csharp
namespace CardRPGFramework.Views

    public sealed class RewardPageView : MonoBehaviour

        [SerializeField] private RunController runController;

                                // $"{name}\n{CardTypeDisplayNames.Of(type)} · 费用 {cost}\n{Format(card)}"

```

`BattleView.TypeLabel` 删掉，手牌改走 `CardTypeDisplayNames.Of`。文案与现网三字必须一致，0.4 卡面用例不改断言。

`RewardPageView` 只调 `SelectReward` / `SkipReward`。不要调 `PlayCard` / `Begin` / `ApplyResult` / `AddCard`。不要用带预览委托的 `Format`。`Run == null` 时奖励页不可见，`Refresh` 不必为 Start 页服务。

`RewardPage` 与 Combat / Result / Map 一样给顶栏留 inset。第 1 节就建物体并默认隐藏，接到 `rewardPage` / `rewardPageView`；**跳过按钮本节就挂上**（可以先没文案），否则第一次 `ShowReward` 会 `SetActive(true)` 再跑 `Start`，空 `skipButton` 会炸。三张卡槽仍第 2 节再铺，`Refresh` 未接线则跳过。

相对 1.2 **不改合同**。`Begin` / `DiscardSession` / `SetRelicDisplayNames` / 局内转发仍按 1.1。`BattleView` 仍只打 `RunController.PlayCard` / `EndTurn`。`MapPageView` 仍只调 `EnterCurrentNode`。不要把选卡按钮塞进战斗页或地图圆点。

## 5. 测试策略

- **不要**重写 1.0 的 `IsCleared` / 三场 `ApplyResult` / `AddCard` 用例。不要写「Victory 通关后立刻 Result」这种 1.2 复述——第三场必须先奖励。
- `RunStateTests` 只加 4.2 的抽取项（同文件，不往根目录加文件）：
  - 一场胜利后抽出 3 张：均在 pool 内、Id 互不相同、长度为 3。
  - 同一 `runSeed` 两个 `RunState`、同样先胜利再抽：三张与顺序相同。再调一次 `CreateRewardChoices` 仍相同。
  - 先 `CreateBattleInput` 并对 `input.Random` 连续 `Next()` 若干次，再胜利再抽：与「不消费战斗 Random」的对照局候选相同。
  - 胜利并抽取后，下一场 `CreateBattleInput().Random` 的 `Next()` 序列，与「胜利后不抽取」的对照局相同（奖励 `new Random` 用完即弃）。
  - `NodeIndex == 0`、`IsFailed` 后抽取均抛；三场胜利后（`IsCleared` / `IsOver` 已为 true）抽取成功且 `AddCard` 仍成功。不要把 `CreateBattleInput` 的 `IsOver` 门槛抄过来。
  - `pool` null / 不足 3 张 / 含 null / Id 重复抛。不要在 Core 用例里断言拒绝 `Attack` Id——那是 `RunConfig` 的事。
- `CardTypeDisplayNames` 的 3 条文案写进现有 `CardDescriptionFormatterTests.cs`（同属 Views 纯函数）。`BattleView` 手牌类型三字不变，无单独 View 单测。
- `RunController` 是 MonoBehaviour，不抽 `RunLoop`；奖励页枢纽、「第一场选的卡第二场能抽到」、「第三场奖励后再 Result」靠 Play。
- Play：开始 → 地图 → 第一场胜利 → **奖励页**（三张不同、无打击 / 防御）→ 选一张顶栏 10→11 → 地图 → 第二场开局生命 = 第一场结束生命、牌堆能抽到所选卡 → 胜利 → 奖励 → 跳过张数不变 → 第三场胜利 → 奖励仍能选 → Result（通关摘要含牌组张数）。另走一遍第三场点跳过：仍进通关结束页，摘要张数不含新卡（停在奖励页则 1.0 测试仍会绿）。中途死亡 → 失败 Result、**不经奖励页**；再来一局后 Start 顶栏 `遗物：无`。漏配奖励池（空 / 不足 3 / 含打击）点开始进不了局。
- `RunConfig.TryValidate` 仍不写 EditMode。
- 验收 grep：
  - `RunController.cs` 没有 `Update`。
  - `battleController.Begin` 只出现在 `EnterCurrentNode`。
  - `EnterCurrentNode` 的早退条件能看到 `RewardChoices`（等待选奖励时 return；Play 点不到隐藏的地图进入，不能当本条的锁）。
  - `ApplyResult` 只出现在 `ApplyOutcomeIfEnded`。
  - 产品侧 `AddCard` 只出现在 `SelectReward`。
  - `Assets/Scripts/Runtime/Core/Battle/`、`BattleInput.cs`、`BattleSetup` 没有 `NodeType` 新用法，也没有奖励页类型。
  - `NodeType.cs` 仍只有 `Combat`。
  - `BattleView` 仍不调 `battleController.PlayCard` / `EndTurn`，没有选卡入组控件。
  - `CreateRewardChoices` 不出现 `CreateBattleInput` 返回值上的 `.Next`。
  - `Begin` / `DiscardSession` 仍不出现 `_relicDisplayNames`。

## 6. 排除项

- 遗物奖、金币奖、卡牌升级、卡牌移除、商店 / 休息 / 事件页。
- 给 `NodeType` 加 `Reward` / `Shop` / `Rest`。
- 稀有度、Pity、精英 / Boss 不同奖池、奖励时升级（原版有，本 Demo 不做）。
- 把奖励 `Random` 接到 `BattleInput.Random` 或 `UnityEngine.Random`。
- 抽卡结果写进 `BattleSession`；`RunState` 构造加第六个奖励池参数。
- EventBus、拆场景、异步加载、抽 `RunLoop`。
- `Update` / 协程读 `Phase` 或 `ApplyResult`。
- 通关 Victory 仍直接 Result；未通关 Victory 仍直接 `ShowMap`；等待奖励时 `EnterCurrentNode` 仍 `Begin`。
- 为 Start / 奖励页预填 80 / 10；奖励卡面走预览委托；把三个字段拼成一行。
- `Refresh(cards)` 当第二出口；View 自己调 `CreateRewardChoices`；另做 `_awaitingReward` 和 `RewardChoices` 两套等待标志。
- `CreateRewardChoices` 抄 `CreateBattleInput` 的 `if (IsOver)`。
- `Core.asmdef`（1.4）。不要为本版改程序集或挪 `Core/` 文件。

## 7. 关键技术决策

| 决策 | 1.3 选择 | 原因 |
| --- | --- | --- |
| 奖励是不是 `NodeType` | [已定] 不是；胜利后的流程步骤 | 1.2 的分发边界是「进节点」；奖励发生在出战斗之后 |
| 谁抽三张 | [已定] `RunState.CreateRewardChoices(pool)` | 种子在 Run；UI / Controller 不自己 `Random` |
| 奖励池放哪 | [已定] `RunConfig` 传入抽取；不进 `RunState` 构造 | 构造五参与 1.0 测试保持；池整局不变 |
| `rewardIndex` | [已定] `NodeIndex - 1`（写回后） | 本版全是战斗；不预留 `_rewardCount` |
| `g` 的乘数 | [已定] 389，不用 397 | 与 `f` 同形不同常数；测试对照更直观 |
| 抽样 | [已定] 拷贝后 `CardPile` 同形 Fisher-Yates，取前 3 | 不发明第二套洗牌 |
| 通关后是否奖励 | [已定] 要 | 1.0 已规定 `IsCleared` 不是牌组冻结 |
| 失败是否奖励 | [已定] 否 | 总设计：失败 Run 作废，不再加卡 |
| 等待奖励时进入 | [已定] `EnterCurrentNode` 见 `RewardChoices.Count != 0` 则 return | 否则跳过奖励页直接开战。Play 点不到隐藏地图，不能当本条的锁 |
| 当前三张出口 | [已定] `RunController.RewardChoices` | View 只读这一处；不要 `Refresh(cards)` 或 View 调 `RunState` |
| 卡面类型中文 | [已定] `CardTypeDisplayNames` | 0.4 预定的第二个调用方 |
| 候选卡按钮 | [已定] 复用 `CardButtonView` | 已按索引回调，不手写第三套按钮 |
| Session 构造 | [已定] 相对 1.0～1.2 不变 | 本版证明的是局外抽卡，不是战斗入口 |

## 8. 完成定义

- 游戏设计第 4 节验收满足；总设计第 8 节在本版完成后可勾。
- 产品侧 `Begin` 只在 `EnterCurrentNode`；Victory 必须先奖励页；等待选奖励时 `EnterCurrentNode` 早退看 `RewardChoices`。
- 产品侧 `ApplyResult` 只在 `ApplyOutcomeIfEnded`、每节点一次；`AddCard` 只在 `SelectReward`；`RunController` 无 `Update`。
- `CreateRewardChoices` 自建 `Random(g(...))`；战斗 `Random.Next` 不改变候选。
- `NodeType` 仍只有 `Combat`。Session 构造签名不变。
- `SetRelicDisplayNames` 仍只由 `RunController` 按 1.2 的时机调用。
- 无遗物奖、无空商店页、无 `Core.asmdef`。
- 0.x～1.2 测试不改断言通过。
