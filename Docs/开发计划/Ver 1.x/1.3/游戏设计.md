# 1.3 游戏设计：战后三选一

> **交付目标：奖励抽卡发生在战斗页之外。** 胜利 → `ApplyResult` 写回 → `DiscardSession` → 奖励页 → `AddCard` / 跳过 → 地图或结束。奖励 RNG 用 `g(runSeed, rewardIndex)`，与战斗 `Random` 无关。`AddCard` 在 1.0 已有，本版只负责抽出三张并让玩家选。第三场通关后 `IsCleared` 已为 true，仍走奖励页再去结束页。
>
> 不做遗物奖励、金币奖励、卡牌移除与升级；不把奖励做成 `NodeType`；不做稀有度与升级。
>
> 总设计见 [`../游戏设计.md`](../游戏设计.md) 第 5、8 节。1.2 已完成。技术设计 / TODO 已写出，无未拍的 **[待确认]**。**短 Run 完成定义在总设计第 8 节，已在本版勾完。**

## 1. 设计原则

- **奖励页不是战斗页，也不是地图节点。** 三张候选卡复用 `CardDescriptionFormatter.Format(CardDefinition)`（基础数值、不依赖 Controller），没有战斗就没有预览。选卡 / 跳过是 Run 流程，不塞进 `BattleView`，也不新增 `NodeType` 值。
- **奖励 RNG 独立于战斗洗牌。** 同一开局种子、同一局外操作序列（含选了哪张 / 跳过）→ 各场洗牌与各次候选都相同。单场内出了多少牌、重洗几次，不改变该场胜利后的候选。
- 选一张加入牌组，或跳过。选完立刻在顶栏看到牌组张数 +1（跟局外生命一样，奖励页 Session 已丢掉，顶栏读 `RunState`）。

对照原版：[wiki Card Rewards](https://slay-the-spire.fandom.com/wiki/Card_Rewards) 是战后三张互不相同、可跳过；[`../../../杀戮尖塔机制研究.md`](../../../杀戮尖塔机制研究.md) 第 1 节与 [`../../../详细游戏设计文档参考/牌堆流转与打出.md`](../../../详细游戏设计文档参考/牌堆流转与打出.md) 第 6 节都要求地图 / 奖励用另一路种子，不要和战斗洗牌搅在一起。本版只取「独立种子流 + 三张不重复 + 可跳过」，不做稀有度、Pity、精英 / Boss 不同奖池、奖励升级。

## 2. 本版做 / 不做

| 做 | 不做 |
| --- | --- |
| 胜利 → `ApplyResult` → 奖励页 → `AddCard` / 跳过 → 地图或结束 | 遗物奖、金币奖 |
| 奖励池 = 可获得卡（排除打击 / 防御）；随机三张不同 | 升级、移除；按稀有度抽 |
| `g(runSeed, rewardIndex)` 派生抽取 | 把奖励随机接到战斗 `Random` 上 |
| 选一张 `AddCard` 或跳过 | 商店、休息 |
| 第三场胜利仍先奖励页，再结束页 | 把奖励做成 `NodeType`；空商店页 |

奖励池与总设计第 5 节一致：痛击 / 双击 / 剑柄打击 / 坚不可摧 / 力量强化 / 剧毒 / 虚弱 / 易伤 / 治疗。起始牌打击、防御不进池。池内卡可以与起始牌组重复（开局已有一张痛击，奖励仍可能再给一张）。

```text
开始页：[开始一局] → StartRun → 地图页
  ↓
地图页：[进入] → EnterCurrentNode → 战斗页
  ↓
战斗页：点牌 / 结束回合（只打 RunController）
  ├─ Defeat → ApplyResult(false, …) → DiscardSession → 结束页（失败，不经奖励）
  └─ Victory → ApplyResult(true, 局内生命) → DiscardSession → 奖励页
        ↓
        奖励页：三张候选 + 跳过
          ├─ 点一张 → AddCard → 顶栏牌组 +1
          └─ 跳过 → 牌组不变
        ↓
        尚未通关 → 地图页（当前节点已前进）
        已通关   → 结束页（通关；摘要里的牌组张数含本场所选）
  ↓
结束页：[再来一局] → Restart → 开始页
```

1.2 的「胜利未通关回地图 / 通关去结束页」中间插入奖励页。失败路径相对 1.2 不变。

## 3. 奖励页

总设计第 6 节：三张候选卡 + 跳过。点一张立刻入组并离开本页；点跳过立刻离开。不要「选中再确认」。

| 项 | 本版 |
| --- | --- |
| 候选 | 三张，互不相同，来自奖励池，不含打击 / 防御 |
| 卡面 | 三个字段：名字、`类型 · 费用 X`、描述（无委托 `Format(CardDefinition)`）。斜杠只是本文分隔，**排版与手牌相同：三行换行**，不要拼成一行。没有战斗、没有预览 |
| 跳过 | 单独按钮；牌组张数不变 |
| 顶栏 | Session 已丢掉，生命 / 牌组读 `RunState`；选完 `AddCard` 后立刻 `Refresh` 顶栏 |
| 战斗页 | 没有选卡或进下一场的控件 |

同一场奖励刷新界面不得换三张（派生种子只看 `runSeed` 与 `rewardIndex`，不看刷新次数）。

## 4. 验收标准

对照总设计第 8 节；勾那一节的前提是本版完成。

- 从开始页点一次进入，连打三场到结束页，全程不回 Editor；每场胜利都经过奖励页。
- 奖励页三张互不相同且不含打击 / 防御；跳过后牌组张数不变；选一张后顶栏牌组 +1。
- 第一场胜利后选的卡在第二场能抽到。第三场胜利写回后仍能选卡入组，然后再去结束页；结束页摘要的牌组张数含这张。第三场点跳过同样进通关结束页，摘要张数不含新卡。
- 第二场开局生命等于第一场结束时的生命；起始遗物三场都在遗物栏且生效。
- 同一开局种子、同一局外操作序列下，两局的各场洗牌与各次奖励候选一致。单场内出牌与重洗次数不改变该场候选。
- 战斗页内没有选卡或进下一场的控件；顶栏在地图 / 战斗 / 奖励 / 结束之间切页时始终存在。
- 中途死亡进入失败结束页，不经奖励页；再来一局后 Run 从初始状态开始。
- 代码里新增一种节点类型不需要改 `BattleSession`；本版也不为奖励新增 `NodeType`。
- 0.x～1.2 测试不改断言通过。
