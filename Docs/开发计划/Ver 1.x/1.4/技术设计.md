# 1.4 技术设计：Core.asmdef

> **已转正。** 第 9 节已按 1.3 实现勾完。
>
> **技术目标：Core 零 `UnityEngine` 成为编译约束。** 在 `Assets/Scripts/Runtime/Core/` 放置独立 asmdef，`noEngineReferences: true`。父级 `Runtime.asmdef` 与 `Tests.asmdef` 显式引用它（asmdef 引用不传递）。不为它倒逼 1.0～1.3 改 C# 引用方向；不按命名空间再拆。
>
> 玩法要求见 [`游戏设计.md`](游戏设计.md)，执行顺序见 [`TODO.md`](TODO.md)。对照 1.3：[`../1.3/技术设计.md`](../1.3/技术设计.md)。Unity 字段见手册 [Assembly Definition Inspector](https://docs.unity3d.com/Manual/class-AssemblyDefinitionImporter.html) 的 No Engine References，以及 [Referencing assemblies](https://docs.unity3d.com/Manual/assembly-definitions-referencing.html)（自定义程序集之间的引用必须写明，不会沿 `Runtime` 自动透传 Core 类型给 Tests）。

## 1. 技术原则

- **嵌套 asmdef 只包住 `Core/`。** 文件必须放在 `Assets/Scripts/Runtime/Core/Core.asmdef`（或同目录等价文件名）。放在 `Runtime/` 根会把 `Data` / `Controllers` / `Views` 一并卷进「零引擎」程序集，UI 立刻编不过。
- **打开 No Engine References，而不是「不写引用」。** `noEngineReferences: false` 时 Unity 仍会自动加 `UnityEngine` / `UnityEditor`；那只是约定，不是约束。
- **不搬家、不改命名空间。** 1.0～1.3 已经按「Core 不用 `UnityEngine`」在写。本版只加程序集边界。1.3 的 `CreateRewardChoices` 用 `System.Random`，复核时确认它仍在 `Core.Run`。
- **Tests 必须自己引用 Core。** 现在 Tests 只引用 `Runtime`，Core 类型碰巧和 Controllers 在同一程序集。拆开之后不传递，漏写引用会表现为测试工程找不到 `RunState` / `BattleSession`。

## 2. 分层与依赖

```text
Tests.asmdef（EditMode）
  → Runtime
  → CardRPGFramework.Core      （本版新加；不传递）
  → UnityEngine.TestRunner / nunit（已有）

Runtime.asmdef（Data / Controllers / Views）
  → CardRPGFramework.Core      （本版新加）
  → Unity.TextMeshPro / UnityEngine.UI（已有）

CardRPGFramework.Core（Core/ 下全部 .cs）
  → 无引擎引用，无 Runtime 反向引用
```

禁止 Runtime ↔ Core 循环引用。Core 已经不引用 `Data` / `Controllers` / `Views`，不要为拆程序集倒过来。

## 3. 目录与文件

```text
Assets/Scripts/
├── Runtime/
│   ├── Runtime.asmdef              （改：references 加上 CardRPGFramework.Core）
│   └── Core/
│       └── Core.asmdef             （新：name CardRPGFramework.Core，noEngineReferences true）
└── Tests/EditMode/
    └── Tests.asmdef                （改：references 加上 CardRPGFramework.Core）
```

**不**移动任何 `.cs`。不新建 `Core.Actions.asmdef`。不改 `rootNamespace`（仍与现网一致：`CardRPGFramework`）。Unity 会为新 asmdef 生成 `.meta`，一并纳入版本库。

现网 `Runtime.asmdef` 的 `name` 是 `Runtime`；Tests 已按这个短名引用。Core 用全名 `CardRPGFramework.Core`，避免和引擎模块或第三方 `Core` 撞名。

## 4. 核心接口

本版没有新的 C# 类型合同。asmdef JSON 形状如下，实现时按此写，不要在 Inspector 里另开一组互相矛盾的勾选。

### 4.1 Core.asmdef **[已定]**

```json
{
    "name": "CardRPGFramework.Core",
    "rootNamespace": "CardRPGFramework",
    "references": [],
    "includePlatforms": [],
    "excludePlatforms": [],
    "allowUnsafeCode": false,
    "overrideReferences": false,
    "precompiledReferences": [],
    "autoReferenced": true,
    "defineConstraints": [],
    "versionDefines": [],
    "noEngineReferences": true
}
```

`noEngineReferences` 必须为 true。`references` 保持空——Core 只应依赖 BCL。不要为了「能 Debug.Log」把引擎加回来；Core 继续靠抛异常 / 返回值说话（Phase 1 已定）。

### 4.2 Runtime.asmdef **[已定] 只加一条引用**

现网已有 `Unity.TextMeshPro`、`UnityEngine.UI`。本版在 `references` **追加** `"CardRPGFramework.Core"`，不删现有项，不改 `name` / `rootNamespace`。

### 4.3 Tests.asmdef **[已定] 只加一条引用**

现网已有 `Runtime`、两个 TestRunner。本版在 `references` **追加** `"CardRPGFramework.Core"`。不要去掉 `Runtime`——`EffectSpecDataTests` / `EnemyActionDataTests` 仍引用 `CardRPGFramework.Data`。不要给 Tests 开 `noEngineReferences`。

### 4.4 若复核时 Core 里出现 UnityEngine

**[已定] 只改那一处引用，不借机重构。** 当前 `Assets/Scripts/Runtime/Core/` 下 grep 不到 `using UnityEngine`（转正时已再 grep）。若 1.3 实现误把 `UnityEngine.Random` 或 `Debug.Log` 写进 Core：改回 `System.Random` / 抛异常，不要把该文件挪出 `Core/` 来「绕过」asmdef。

## 5. 测试策略

- **不要**为拆程序集重写 0.x～1.3 用例，不要改断言。
- 拆完后跑全部 EditMode。若大面积 `The type or namespace name 'RunState' could not be found`，先查 Tests 是否漏引 Core，不要回头把 Core 文件搬进 `Runtime/`。
- Play：相对 1.3 走一遍短 Run（开始 → 地图 → 战斗 → 奖励 → 地图 / 结束）。流程不变才算本版没破坏玩法。
- 验收 grep：`Assets/Scripts/Runtime/Core/` 无 `using UnityEngine`；`Core.asmdef` 含 `"noEngineReferences": true`；`NodeType` / `CreateRewardChoices` / `BattleSession` 仍在 `Core/` 下。
- 手工负例（不要提交）：在 `RunState.cs` 顶上临时加 `using UnityEngine;`，确认 Console 编译失败，再还原。

## 6. 排除项

- 改玩法、改 `RunState` / `BattleSession` 签名、改奖励公式。
- 按 `Core.Actions` / `Core.Buffs` / `Core.Run` 再拆 asmdef。
- 把 `CardDescriptionFormatter` 或 `Data` 搬进 Core（它们分别已经依赖显示名表 / `UnityEngine` 的 SO）。
- 为拆程序集改 namespace、改文件夹、抽 `InternalsVisibleTo`。
- 清空 `Library` 来「逼 Unity 认新 asmdef」（见仓库不可逆规则）。等 Unity 自己 recompile。
- HybridCLR、Addressables、把 Tests 也改成零引擎。

## 7. 关键技术决策

| 决策 | 1.4 选择 | 原因 |
| --- | --- | --- |
| 要不要做 | [已定] 可选版本；1.3 短 Run 不依赖它 | 大纲写明不为 1.0～1.3 倒逼 |
| 约束手段 | [已定] `noEngineReferences: true` | 不打开则 Unity 仍自动引用引擎 |
| asmdef 位置 | [已定] `Runtime/Core/` 内 | 嵌套程序集只编译该文件夹树 |
| 程序集名 | [已定] `CardRPGFramework.Core` | 避免短名 `Core` 撞包 |
| Tests 引用 | [已定] Runtime + Core 都写 | 引用不传递 |
| 是否搬家 | [已定] 不搬 `.cs` | 倒逼 1.0～1.3 改路径没有收益 |
| 是否再拆命名空间 | [已定] Core 仍一个程序集 | 0.5 已说明互引，拆开会循环引用 |
