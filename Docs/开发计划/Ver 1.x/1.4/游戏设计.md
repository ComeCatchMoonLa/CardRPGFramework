## 1. 设计原则

- **本版证明的是编译边界，不是新玩法。** 玩家从开局打到结束页的流程、奖励三选一、地图枢纽，相对 1.3 一字不改。
- **约束要真能红。** 只在 asmdef 的 `references` 里不写 `UnityEngine` 不够——Unity 仍会给自定义程序集自动加上引擎引用。必须打开 No Engine References（`noEngineReferences: true`），在 Core 里写 `using UnityEngine` 才会编不过。
- **一个 Core 程序集。** 0.5 已说明命名空间互引（`Actions` ↔ `Relics` 等）靠职责边界，不靠再拆 asmdef。当时文里写的「1.1 拆程序集」是旧版本号，实际排在本版。

## 2. 本版做 / 不做

| 做 | 不做 |
| --- | --- |
| `Core/` 下新增 asmdef，零引擎引用 | 改卡牌、敌人、奖励、地图、壳 UI |
| `Runtime.asmdef` / `Tests.asmdef` 显式引用 Core | 按命名空间再拆 Core |
| 现有 EditMode 全绿、Play 短 Run 仍可走完 | 为拆程序集挪 `.cs` 路径或改命名空间 |
| | 把 `Data` / `Views` 并进 Core；给 Core 加 `UnityEngine.UI` |

## 3. 验收标准

- `Assets/Scripts/Runtime/Core/` 内有 asmdef，且 No Engine References 为 true。
- 在任意 Core 源文件写 `using UnityEngine;` 无法通过编译；不要把这样的修改留在仓库里。
- `Controllers` / `Views` / `Data` 仍在 `Runtime` 程序集，仍可引用 Core 类型与 Unity UI。
- 0.x～1.3 测试不改断言通过；Play 短 Run（含奖励页）相对 1.3 无变化。
- `Core/` 目录结构与命名空间相对 1.3 不变（除非复核时真的发现 Core 引用了 `UnityEngine`，只改那一处引用，不借机搬家）。
