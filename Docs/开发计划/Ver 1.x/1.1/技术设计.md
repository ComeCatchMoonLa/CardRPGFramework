# 1.1 技术设计：Run 壳与战斗接入

> **技术目标：流程层持有 `RunState`，用 `BattleController.Begin` 创建 / 销毁 Session。** Play 只走 `RunConfig` → `RunState` → `Begin`。开始页、战斗页、结束页与顶栏同一场景显隐。场间胜利立刻下一场；通关或失败才上 Result。无地图、无奖励。
>
> 玩法要求见 [`游戏设计.md`](游戏设计.md)，执行顺序见 [`TODO.md`](TODO.md)。总设计见 [`../游戏设计.md`](../游戏设计.md)。对照 1.0：[`../1.0/技术设计.md`](../1.0/技术设计.md)。
>
> 时序、开战真相与类型合同已定（含遗物字典、删除 `EndScreenView`）。无未拍的 **[待确认]**。

## 1. 技术原则

- **Session 生命周期在流程层。** `Awake` 不再 `new BattleSession`，改由流程调 `Begin`。不把 `RunState` 传入 Session。
- **结束写回是单通道。** 每个结束 `Phase` 只 `ApplyResult` 一次。局内命令唯一入口是 `RunController`；命令方法返回前读一次 `Phase`。禁止 `Update`（以及协程 / 定时器）里读 `Phase` 或 `ApplyResult`。删除 `EndScreenView`；场间 / 终局都不走结束遮罩。
- **不引入事件总线。** 写回入口不是遮罩。
- **顶栏战斗中跟局内生命，其它页读 Run。** 两者不同步是设计。Start 页点「开始一局」前没有 `RunState`，不读 `RunConfig`：遗物写 `遗物：无`，生命 / 金币 / 牌组不要预填 80 / 0 / 10。
- **短 Run 是唯一开战真相。** Play 只走 `RunConfig`。`RunConfig` 只由 `RunController` 持有。不保留单场旁路、快捷键、命令框、插件入口。

## 2. 分层与依赖

```text
Views（顶栏 + Start / Combat / Result）
  ↓ 局内命令与开局 / 再来一局只打 RunController
  ↓ 战斗页 Refresh 仍可读 BattleController 的只读状态
Controllers
  RunController（唯一 SerializeField 持有 RunConfig；持有 RunState）
  BattleController.Begin / DiscardSession / SetRelicDisplayNames / PlayCard / EndTurn
  （命令只给 RunController 转发；SetRelicDisplayNames 也只由它调）
  ↓
Core.Run（1.0 的 RunState / BattleInput）
Core.Battle（Session 构造不变）
Data（RunConfig：本局唯一开战配置）
```

## 4. 核心接口

### 4.1 BattleController

```csharp
public sealed class BattleController : MonoBehaviour
{
    // 删除：BattleConfig、useFixedSeed、seed。不 SerializeField RunConfig。

    public bool IsReady { get; }          // _session != null
    public BattlePhase Phase { get; }
    // 其余只读状态与现网相同（Player / Hand / RelicDisplayName / …）

    /// 用 input 五个字段 new BattleSession 再 StartBattle。Random 只用 input.Random。
    /// 已有一场时先丢掉旧 Session。不读 RunConfig，不填遗物显示名。
    public void Begin(BattleInput input);

    /// 丢掉当前 Session（_session = null）。再来一局、回到 Start 时用。不 Begin。
    /// 不清遗物显示名表。
    public void DiscardSession();

    public bool PlayCard(int handIndex);   // 只给 RunController 转发；View 不调
    public bool EndTurn();
    public string RelicDisplayName(string relicId);  // 一字不改；未知 Id 原样返回

    /// 整表替换。null 抛。空列表 = 清空。不读 RunConfig，不碰 Session。
    /// 必须先 Clear 再按 id → displayName 填。现网 Awake 没有 Clear，不要按它抄。
    public void SetRelicDisplayNames(IReadOnlyList<RelicData> relics);
}
```

`Awake` 不再 `new BattleSession`，也不再读 `BattleConfig`，也不填遗物字典。

`Begin` 之后必须让战斗页 `Refresh`：现网 `BattleView.Start` 只 `Refresh` 一次，开战改到点「开始一局」之后，不刷会停在旧文案。由 `RunController` 在每次 `Begin` 之后调用战斗页 `Refresh`（`Refresh` 改为 public）。Combat / Result **进 Play 即默认隐藏**（第 1 节就做，不要等壳 UI 那一节）；未 `Begin` 前不可点手牌 / 结束回合。`BattleView` 未就绪时不要再写「请检查 BattleConfig」。

`Begin` / `DiscardSession` 都不动 `_relicDisplayNames`，见 4.7。

### 4.2 结束写回 **[已定] 单通道 + View 单入口**

现网：`BattleView` 直接调 `BattleController.PlayCard` / `EndTurn`，`Refresh` → `RefreshEndScreen` 在 Victory/Defeat 时 `EndScreenView.Show`。那是 0.x 单场终局，没有「继续」。本版删除这块遮罩，见 4.8。

**[已定] 局内命令唯一入口是 `RunController.PlayCard` / `EndTurn`。** `BattleView` 不再调用 `BattleController` 的这两方法。`StartPageView` 只调 `StartRun`；`ResultPageView` 只调 `Restart`。`BattleController.PlayCard` / `EndTurn` 只给 `RunController` 转发。不要 View 调完 `BattleController` 再调流程——那是第二入口。

**[已定] 谁读 `Phase`：** 只在 `RunController.PlayCard` / `EndTurn` 里、转发返回之后，调用一次 `ApplyOutcomeIfEnded`。该方法不是第二套公开命令；禁止从 `Update`、协程、定时器、`BattleController` 内部调用它或直接 `ApplyResult`。

场间顺序以本表为准：**先 `ApplyResult`，未通关再 `Begin(CreateBattleInput())`。不要倒过来。** 同节点可以多次 `CreateBattleInput` 且不推进，写反不会抛，只会打成同一敌人 + 写回前生命，1.0 测试也仍会绿。「第二场开局生命 = 第一场结束生命」由游戏设计第 4 节的 Play 锁住。

第 9 节「先发输入」指**本场**开战已经 `CreateBattleInput` 过，不是下一场的 input 要在这次写回之前造好。场间若 Session 仍停在 `Victory`，每帧再 `ApplyResult` 会打穿 1.0，所以 **禁止** `RunController.Update`。

| `Phase` | 写回 | UI |
| --- | --- | --- |
| `PlayerTurn` / `EnemyTurn` / `NotStarted` | 不写回 | 战斗页照常 Refresh |
| `Victory` | **先** `ApplyResult(true, session.Player.CurrentHp)`。写回后若 `IsCleared` → 不再 `CreateBattleInput`；否则再 `Begin(CreateBattleInput())` 再 `Refresh` | 场间无遮罩；通关则 `DiscardSession`（**不清**遗物字典），Hide Combat，切 Result |
| `Defeat` | `ApplyResult(false, remainingHp)`：失败任意 `remainingHp`（1.0 忽略该参数）；**只按 `Phase == Defeat`**，不要 `ApplyResult(phase == Victory, hp)`，也不要用 `hp <= 0` 当失败（会打进胜利校验） | Hide Combat，`DiscardSession`（**不清**字典），切 Result（失败） |

### 4.3 顶栏

战斗中读 `BattleController.Player.CurrentHp`；其它页读 `RunState.CurrentHp`。金币 / 牌组张数 / 遗物 Id 读 Run。遗物显示名仍走 `BattleController.RelicDisplayName`。Start 页在点「开始一局」前没有 `RunState`，**不读 `RunConfig`**：遗物写 `遗物：无`，生命 / 金币 / 牌组不要预填 80 / 0 / 10。Result 顶栏用 `Run.RelicIds` + `RelicDisplayName`。字典填清见 4.7。

### 4.4 RunConfig

Play 只走 `RunConfig`；`TestScene` 改走 Run，单场调试删除。`BattleConfig` / `Default.asset` 不再开战；无引用则删。卡牌 / 敌人 / 遗物资产留给 `RunConfig` 引用。不保留单场旁路、快捷键、命令框、插件入口。

```csharp
namespace CardRPGFramework.Data
{
    [CreateAssetMenu(fileName = "RunConfig", menuName = "CardRPG/Run Config")]
    public sealed class RunConfig : ScriptableObject
    {
        [SerializeField] private int runSeed;              // 0 合法，不是未填哨兵
        [SerializeField] private int playerMaxHp;           // 不要写 = 80
        [SerializeField] private int energyPerTurn;      // 不要写 = 3
        [SerializeField] private int handSize;            // 不要写 = 5
        [SerializeField] private List<CardData> deck = new();
        [SerializeField] private List<RelicData> relics = new();      // 允许空列表
        [SerializeField] private List<EnemyData> encounters = new();   // 必须恰好 3

        public int RunSeed => runSeed;
        public IReadOnlyList<RelicData> Relics => relics;

        /// 产品路径：StartRun 先 TryValidate，再 CreateRunState。
        /// 假定已通过校验；这里不默默填 80 / 10 张 / 1 遗物。
        public RunState CreateRunState();
        // 体内：new BattleSetup(playerMaxHp, energyPerTurn, handSize)（三参满血）
        //       deck → CardDefinition 列表；relics → Id 列表；encounters → ToDefinition 列表
        //       return new RunState(runSeed, setup, deckDefs, relicIds, encounterDefs);

        /// 进战斗前的拒绝合同。SO 校验不写 EditMode（与 CardData / BattleConfig 一致）。
        public bool TryValidate(out string error);
    }
}
```

`TryValidate`：

| 项 | 拒绝 |
| --- | --- |
| `playerMaxHp <= 0` | 是（漏配 Unity 默认 0 必须拦住；不要靠字段默认 80 让空资产看起来合法） |
| `energyPerTurn < 0` / `handSize < 0` | 是（与 `BattleSetup` 同一条） |
| `deck` null / Count == 0 | 是（产品侧空牌组拒；1.0 `RunState` 测试仍允许空列表，那是测试直接 `new`） |
| `deck` 空引用 / 某张 `CardData.TryValidate` 失败 | 是 |
| 两份不同 `CardData` 同 Id | 是（同一资产引用多次合法，牌组里多张打击） |
| `relics` 空引用 / 某件 `RelicData.TryValidate` 失败 | 是 |
| 遗物 Id 重复（同一资产引用两次也算） | 是 |
| `relics` 空列表 | 否（与 1.0 一致；1 件遗物是资产内容，不是类型默认） |
| `encounters` 不是恰好 3、或含 null | 是 |
| 某敌人 `EnemyData.TryValidate` 失败 | 是 |
| 三场敌人重复 | 否（总设计允许两场颚虫） |
| `runSeed == 0` | 否 |

10 张起始牌 / 1 件遗物 / 生命 80 是资产内容，写在 `RunConfig` 资产上，不要写成字段初始值。

### 4.5 RunController

```csharp
namespace CardRPGFramework.Controllers
{
    public sealed class RunController : MonoBehaviour
    {
        [SerializeField] private RunConfig runConfig;           // 本场景唯一一份
        [SerializeField] private BattleController battleController;
        [SerializeField] private BattleView battleView;          // Begin 之后 Refresh
        [SerializeField] private GameObject startPage;
        [SerializeField] private GameObject combatPage;
        [SerializeField] private GameObject resultPage;

        public RunState Run { get; private set; }               // Start 页为 null

        /// 校验失败则 LogError 并停留在 Start，不 new RunState、不填字典。
        /// 通过则 CreateRunState → SetRelicDisplayNames(runConfig.Relics)
        /// → CreateBattleInput → Begin → 显示 Combat → Refresh。
        public void StartRun();

        /// 未开战（Run == null 或 !IsReady）则 false，不读 Phase。
        /// 否则转发 battleController.PlayCard，然后只调用一次 ApplyOutcomeIfEnded。
        public bool PlayCard(int handIndex);

        public bool EndTurn();                                    // 同上，转发 EndTurn

        /// Run = null；DiscardSession()（不清字典）；
        /// SetRelicDisplayNames(空列表) 清空；Hide Combat；显示 Start。
        /// 下一轮 Begin 前 Combat 不可点。
        public void Restart();

        /// 只允许从 PlayCard / EndTurn 调用。禁止 Update / 协程。
        /// 通关 / 失败：DiscardSession 不清字典；场间先 ApplyResult，未通关再 Begin（不再填字典）。
        private void ApplyOutcomeIfEnded();                      // 语义见 4.2 表
    }
}
```

`BattleController` 不挂 `RunConfig`。不要 `RunController` 与 `BattleController` 各 SerializeField 一份。`SetRelicDisplayNames` 只有 `RunController` 调。

文件里**不要** `void Update()`。`ApplyOutcomeIfEnded` 用 `switch (battleController.Phase)`，不要用 `hp <= 0` 当失败。

### 4.6 再来一局

`Restart`：丢掉 `RunState` 和当前 `Session`（`DiscardSession`）；`SetRelicDisplayNames` 传入空列表清空；Hide Combat 与 Result；回到 Start。下一轮 `Begin` 前 Combat 不可点。Start 顶栏因 `Run == null` 不读 `RunConfig`：遗物写 `遗物：无`，不要预填 80 / 0 / 10。

### 4.7 遗物显示名 **[已定]**

`BattleController.SetRelicDisplayNames(IReadOnlyList<RelicData>)` 整表替换。`RunController.StartRun` 在 `Begin` 前调一次（`runConfig.Relics`）；场间 `Begin` 不调；`DiscardSession` 不清；`Restart` 传入空列表清空。`Begin` 不填字典。

| 时机 | 做 |
| --- | --- |
| `StartRun` | `TryValidate` 通过后、**第一次 `Begin` 之前**调一次，传入 `runConfig.Relics`。三场遗物不变，场间 `Begin` **不再**填 |
| `ApplyOutcomeIfEnded` 通关 / 失败 | `DiscardSession` **不清**字典。Result 顶栏仍用 `Run.RelicIds` + `RelicDisplayName` |
| `Restart` | `SetRelicDisplayNames(Array.Empty<RelicData>())`（或空列表）清空 |
| `Awake` / `Update` / `Begin` / `DiscardSession` | 不填、不清 |

`SetRelicDisplayNames`：null 抛；空列表 = 清空。**必须先** `_relicDisplayNames.Clear()`，再 `id → displayName`。现网 `Awake` 只写入、没有 Clear；按现网抄会抄漏。`RelicDisplayName` 一字不改。不读 `RunConfig`，不碰 Session。

### 4.8 EndScreenView **[已定]**

删除 `EndScreenView` 与 `BattleView.RefreshEndScreen`。场间 / 终局都不 `Show`。

一并删：`EndScreenView.cs`（及 meta）、`BattleView` 的 `endScreenView` 字段、`TestScene` 里那块结束遮罩物体。不要「Hide 恒调用」当删除。1.2 回地图也不需要这块单场遮罩。终局是 Result 页。

## 5. 测试策略

- **不要**重写 1.0 已覆盖的三场 `ApplyResult` / `IsCleared`。不要再写「Victory 且未通关 → 再 `CreateBattleInput`」这种复述 1.0 的用例。
- 1.1 要锁的流程在 `RunController.PlayCard` / `EndTurn` 方法体：转发 → 读一次 `Phase` → 至多一次 `ApplyResult` → 未通关则 `Begin`。场间顺序按 4.2，不要先造下一场 input 再写回。`RunController` 是 MonoBehaviour，不抽 `RunLoop`，壳与「第二场开局生命」继续靠 Play。
- Play：开始 → 连打三场（场间无结束遮罩）→ 结束页；中途死亡 → 失败页；再来一局后生命与牌组回到初始、Start 顶栏 `遗物：无`。漏配 `RunConfig`（空牌组、不是 3 敌人）点开始进不了战斗。
- `RunConfig.TryValidate` 不写 EditMode（与 `BattleConfig` 一致）；联调故意配错看 Console。
- 验收 grep：`RunController.cs` 没有 `Update`；`ApplyResult` 只出现在 `ApplyOutcomeIfEnded`；`BattleView` 不调用 `battleController.PlayCard` / `EndTurn`，没有 `RefreshEndScreen` / `EndScreenView`；`Begin` / `DiscardSession` 不出现 `_relicDisplayNames`。

## 6. 排除项

- 地图、`NodeType`、奖励页。
- EventBus、拆场景、异步加载。
- 不改 `BattleSession` 构造签名。
- 不保留 `BattleConfig` 开战、不保留 `Awake` 里 `new BattleSession`。
- 不抽独立 `RunLoop` 类。
- 不把 `useFixedSeed` 留在 `BattleController` 上盖掉 `input.Random`。
- 不保留 `EndScreenView`、不用恒 `Hide` 当删除。

## 7. 关键技术决策

| 决策 | 1.1 选择 | 原因 |
| --- | --- | --- |
| 谁 `new Session` | [已定] 只有 `Begin` | 1.0 把创建权留到流程层 |
| `Begin` 参数 | [已定] `BattleInput` 五字段 | 不要把 `RunState` / `RunConfig` 塞进去 |
| `Random` | [已定] 只用 `input.Random` | `useFixedSeed` 盖掉会变成第二套 RNG |
| `RunConfig` vs `BattleConfig` | [已定] Play 只走 `RunConfig`；单场删除 | 短 Run 是唯一开战真相 |
| 谁持有 `RunConfig` | [已定] 只有 `RunController` 的 SerializeField | 两处各挂一份会裂开 |
| 胜利后 | [已定] 未通关立刻下一场 | 地图是 1.2 |
| View 命令入口 | [已定] 只调 `RunController` | 「View 调 Controller 再调流程」是第二入口 |
| 结束写回 | [已定] `PlayCard` / `EndTurn` 内 `ApplyOutcomeIfEnded` 一次 | 与遮罩回调或 `Update` 并列会二次 `ApplyResult` |
| 轮询 | [已定] 禁止 `Update` 读 `Phase` / `ApplyResult` | 场间停在 Victory 时每帧会打穿 1.0 |
| 场间 / 终局 UI | [已定] 场间无遮罩；通关 / 失败才 Result | 现网 `Show` 是单场终局，没有「继续」 |
| 失败写回 | [已定] `ApplyResult(false, …)`，只认 `Defeat` | 1.0 失败忽略 `remainingHp`；胜利 + `hp <= 0` 会抛 |
| `RunConfig` 默认值 | [已定] 生命 / 能量 / 手牌不写 80 / 3 / 5 | 漏配必须被 `TryValidate` 拦住 |
| 产品空牌组 | [已定] `TryValidate` 拒绝 | 测试仍可直接 `new RunState` 空牌组 |
| 遗物显示名谁填 | [已定] `SetRelicDisplayNames`；`StartRun` 在第一次 `Begin` 前调一次；场间不调；`DiscardSession` 不清；`Restart` 空列表清空 | `Begin` 拿不到 `RelicData`；不改 `Begin`、不给 `BattleController` 挂 `RunConfig` |
| `EndScreenView` | [已定] 删除 | 本版无消费者；留着停用等于死代码，还可能被误 `Show` |

## 8. 完成定义

- 游戏设计第 4 节验收满足。
- `BattleController.Awake` 不再 `new BattleSession`。
- 产品侧 `ApplyResult` 只在 `RunController.ApplyOutcomeIfEnded`、每节点一次；`RunController` 无 `Update`。
- `BattleView` 不调用 `BattleController.PlayCard` / `EndTurn`；Runtime 无 `EndScreenView`。
- `Begin` 只用 `input.Random`；开战配置只来自 `RunController` 上那一份 `RunConfig`。
- `SetRelicDisplayNames` 只由 `RunController` 按 4.7 调用；`Begin` 不填字典。
- Session 构造签名相对 1.0 不变。
- 0.x 与 1.0 测试不改断言通过。

## 9. 复核清单

- [x] 遗物显示名：`SetRelicDisplayNames`；`StartRun` 在第一次 `Begin` 前调一次；场间不调；`DiscardSession` 不清；`Restart` 空列表清空。
