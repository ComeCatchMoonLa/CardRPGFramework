## 1. 技术原则

- **Session 生命周期在流程层。** `Awake` 不再 `new BattleSession`，改由流程调 `Begin`。不把 `RunState` 传入 Session。
- **不引入事件总线。** 战斗结束由 Controller 在命令返回后看 `Phase`，或结束遮罩通知流程。
- **顶栏战斗中跟局内生命，其它页读 Run。** 两者不同步是设计。

## 4. 核心接口

### 4.1 BattleController.Begin

```csharp
public void Begin(BattleInput input);
```

用 `input` 的五个字段 `new BattleSession(...)` 再 `StartBattle()`。已有一场时先丢掉旧 Session（本局连打，不回放）。

`Awake` 不再 `new BattleSession`。`TestScene` 单场还留不留 `BattleConfig`，与下面 **[待确认]** 是同一件事——现在不写死迁移步骤。

### 4.2 RunController

持有 `RunState` 与当前页。开始一局：构造 `RunState` → `Begin(CreateBattleInput())`。每次 `PlayCard` / `EndTurn` 之后看 `Phase`：

- `Victory`：`ApplyResult(true, session.Player.CurrentHp)`；若 `IsCleared` → Result，否则再 `Begin(CreateBattleInput())`。
- `Defeat`：`ApplyResult(false, …)` → Result。
- 再来一局：丢掉当前 `RunState`，回 Start。

不把 `RunState` 传进 Session。

### 4.3 顶栏

战斗中读 `BattleController.Player.CurrentHp`；其它页读 `RunState.CurrentHp`。金币 / 牌组张数 / 遗物 Id 读 Run。遗物显示名仍走 Controller 从配置翻译。

### 4.4 内容配置 **[待确认]**

`RunConfig` SO（玩家生命 / 能量 / 手牌、起始牌组、起始遗物、三场敌人、种子开关）与现有 `BattleConfig` 是否并存：

- 只留 `RunConfig`，`TestScene` 单场调试改走 Run 或删掉；
- 或 `BattleConfig` 继续服务单场，`RunConfig` 服务一局。

**二选一，不留两套真相。** 进入 1.1 前对照 1.0 实现再定，本稿不选。

## 5. 测试策略（草稿）

- 流程用 EditMode 测纯逻辑：构造 `RunState`、模拟三场 `ApplyResult`、断言 `IsCleared` / `IsFailed`。1.0 已覆盖的不要重写一遍。
- `Begin` 的接线靠 Play：开始 → 连打三场 → 结束页；中途死亡 → 失败页；再来一局后生命与牌组回到初始。
- 不给 `RunController` 搭 PlayMode 基建，除非复核时发现不测就无法验收"自动下一场"。

## 6. 排除项

- 地图、`NodeType`、奖励页。
- EventBus、拆场景、异步加载。
- 不改 `BattleSession` 构造签名。

## 7. 关键技术决策

| 决策 | 1.1 选择 | 原因 |
| --- | --- | --- |
| 谁 `new Session` | [已定] 只有 `Begin` | 1.0 把创建权留到流程层 |
| `Begin` 参数 | [已定] `BattleInput` | 1.0 的转换产物；不要把 `RunState` 塞进去 |
| `RunConfig` vs `BattleConfig` | **[待确认]** | 两套真相更糟；现在选会和 1.0 无 SO 的现实打架 |
| 胜利后 | [已定] 自动下一场 | 地图是 1.2；本版证明壳与接入即可 |
| 结束通知 | [已定] 不引入事件总线 | 命令后读 `Phase` 或遮罩回调 |
