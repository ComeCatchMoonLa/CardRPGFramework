# 1.1 游戏设计：Run 壳与战斗接入

> **交付目标：第一次能从开始页点进去，自动连打三场到结束页。** 流程层创建 / 销毁 `BattleSession`；战斗页只管局内；顶栏常驻。还没有地图，胜利后直接下一场。
>
> 不做地图、奖励、选卡。`RunConfig` 与 `BattleConfig` 是否并存进技术设计前再定。
>
> 总设计见 [`../游戏设计.md`](../游戏设计.md)。技术设计与 TODO 是草稿（[`技术设计.md`](技术设计.md) / [`TODO.md`](TODO.md)），1.0 完成后再对照实现转正。

## 1. 设计原则

- **战斗页只管局内。** 选下一场、结束页、再来一局都是流程的事，不塞进 `BattleView`。
- **Session 生命周期在流程层。** 唯一产品侧创建 / 销毁 Session 的地方是 `BattleController.Begin`；不把 `RunState` 传入 Session。
- Start / 顶栏 / Result 与 Combat 同一刀：没有其它页也不成壳，不拆成单独版本。

## 2. 本版做 / 不做

| 做 | 不做 |
| --- | --- |
| `RunController` 持有 `RunState` 与当前页 | 地图页、`NodeType` |
| 顶栏：生命 / 金币 / 牌组张数 / 遗物；战斗中生命跟局内 | 奖励页、三选一 |
| Start / Combat / Result 三页显隐 | 改 `BattleSession` 构造签名 |
| 胜利自动下一场；最后一场胜利或失败 → 结束页 | 空商店、分支图 |
| `EndScreenView` 通知流程，不再自己拦住整局 | 事件总线 |

```text
开始页：[开始一局]
  ↓
初始化 RunState
  ↓
战斗页：Begin(BattleInput) → 打完
  ├─ 失败 → 结束页
  └─ 胜利 → ApplyResult → 还有下一场？自动 Begin 下一场 : 结束页
  ↓
结束页：[再来一局] → 开始页
```

## 3. 顶栏

战斗中生命显示局内值（Run 值在出战斗时才写回，两者战斗中允许不同，顶栏跟局内）。其它页读 `RunState`。这是设计，不是 bug。

## 4. 验收标准

- 从开始页点一次进入，连打三场到结束页，全程不回 Editor（本版没有奖励页，胜利后自动下一场）。
- 第二场开局生命等于第一场结束时的生命；起始遗物三场都在遗物栏且生效。
- 战斗页内没有选卡或进下一场的控件；顶栏在 Start / Combat / Result 之间切页时始终存在。
- 中途死亡进入失败结束页；再来一局后 Run 从初始状态开始。
- `BattleController.Awake` 不再 `new BattleSession`；产品侧创建点只剩 `Begin`。
- 0.x 与 1.0 测试不改断言通过。
