# 0.2 技术设计：效果列表

> **技术目标：`CardDefinition` 从"类型 + 数值"改为"类型 + 效果列表"，`BattleSession` 只按五种效果原语入队，不再按卡牌种类分支；打出时序改为"先离手、再结算、再进弃牌"；卡面描述由效果列表生成。**
>
> 本版本是 0.x 里改动面最大的一次（`CardDefinition` / `CardData` / `CardPile` / `BattleSession` / 七份资产 / 全部构造卡牌的测试），但每一步都有 0.1 的测试当回归网。公式后预览、Buff 行、意图预览是 0.3 的内容，本文不含。

## 1. 技术原则

延续 0.1 的优先级：**正确性 > 可测试性 > 可读性 > 当前已知需求的扩展性**。补充：

- 效果原语是**封闭枚举**，不是插件点：五种 `EffectKind` 全部写在 Core 里，`switch` 穷举，缺分支编译期就能发现。不做"注册新效果种类"的接口。
- `EffectSpec` 只描述"做什么、对谁、多少"，不带执行逻辑；把它变成 `IAction` 的地方只有一个（`BattleSession.ToAction`）。
- 标注 **[已定]** 的是接口形状上曾有备选的地方，结论与不选备选的理由一并写下，实现时不再重议。

## 2. 分层与依赖

```text
Views（CardDescriptionFormatter / BuffDisplayNames：把 EffectSpec 与 Buff Id 变成中文，只用基础数值，不算数）
  ↓ 只读
Controllers（BattleController：转发命令；本版本不变）
  ↓
Core.Battle（BattleSession：TryPlayCard 新时序；ToAction 把 EffectSpec 变成 IAction）
  ↓
Core.Cards（EffectKind / EffectTarget / EffectSpec / CardType / CardDefinition / CardPile）
Core.Actions（新增 DrawCardsAction；其余不变）
Core.Buffs（新增 BuffFactory：Id → BuffState）
Core.Rules（不变）
```

依赖约束：

- `Core.Cards` 不引用 `Core.Actions` / `Core.Buffs`：`EffectSpec` 里的 Buff 只是字符串 Id，解析发生在 `Core.Battle`。
- `Data`（ScriptableObject）→ `Core.Cards`，方向不变；`CardData.ToDefinition()` 负责把可序列化的效果条目转成 `EffectSpec`。`Data` 另外只为校验 Buff Id 调一次 `Core.Buffs.BuffFactory.IsKnown`，方向仍是 Data → Core。
- Views 仍只依赖 Controller 暴露的只读状态；`CardDescriptionFormatter` 只接收 `CardDefinition`，不依赖 Controller（1.0 奖励页在没有战斗时也要生成卡面）。

## 4. 核心接口

### 4.1 效果原语

```csharp
namespace CardRPGFramework.Core.Cards
{
    public enum EffectKind { Damage, Block, Heal, ApplyBuff, Draw }

    // Self / Opponent 而不是 Player / Enemy：0.6 敌人行动表复用同一套 EffectSpec，
    // 那时 Self 是敌人自己、Opponent 是玩家。现在取名就避免以后改枚举。
    public enum EffectTarget { Self, Opponent }

    public readonly struct EffectSpec
    {
        public EffectKind Kind { get; }
        public EffectTarget Target { get; }
        public int Value { get; }          // 伤害 / 格挡 / 治疗量 / 层数 / 抽牌张数
        public string BuffId { get; }      // 仅 ApplyBuff 使用，其余为 null

        // 构造函数校验：Value > 0；ApplyBuff 必须有 BuffId；Draw 的 Target 必须是 Self。
        public static EffectSpec Damage(int amount) => ...;                 // Target 固定 Opponent
        public static EffectSpec Block(int amount) => ...;                  // Target 固定 Self
        public static EffectSpec Heal(int amount) => ...;                   // Target 固定 Self
        public static EffectSpec ApplyBuff(EffectTarget target, string buffId, int stacks) => ...;
        public static EffectSpec Draw(int count) => ...;                    // Target 固定 Self
    }
}
```

**[已定] `readonly struct`。** 它是"做什么、对谁、多少"的四元组，没有身份、没有可变状态；两张牌上的"对敌人造成 6 点"是同一个值，不是两个对象。`DamageContext` 之所以是 `class`，是因为 `Damage` 会被 Rule 改写——要沿管线传递并修改的才用引用类型。不选 `sealed class` 的理由：多一次分配换不来任何新信息。

struct 的代价是 `default(EffectSpec)` 会绕过校验（全 0、`BuffId == null`）。对策不是改成 class，而是：只通过静态工厂构造；`CardDefinition` 构造时拷贝列表并要求每条合法；不要 `new EffectSpec[n]` 这类未初始化数组。Unity 序列化走的是旁边的 `EffectSpecData`，碰不到这个 struct。

Damage / Block / Heal 的目标现在写死，是因为 0.2 没有"对自己造成伤害""给敌人格挡"的卡；出现时再放开 `Target` 参数，不提前开。

### 4.2 卡牌定义

```csharp
public enum CardType { Attack, Skill }   // 0.4 加 Power

public sealed class CardDefinition
{
    public string Id { get; }
    public string DisplayName { get; }
    public CardType Type { get; }
    public int Cost { get; }
    public IReadOnlyList<EffectSpec> Effects { get; }   // 至少一条，构造时拷贝

    public CardDefinition(string id, string displayName, CardType type, int cost, IReadOnlyList<EffectSpec> effects)
}
```

`Value` 字段删除，不保留兼容层：0.1 的七张卡全部迁移，保留旧字段只会留下两套真相。

### 4.3 Buff 工厂

```csharp
namespace CardRPGFramework.Core.Buffs
{
    public static class BuffFactory
    {
        public static bool IsKnown(string id) => ...;
        public static BuffState Create(string id, int stacks) => id switch
        {
            "strength"   => new StrengthBuff(stacks),
            "poison"     => new PoisonBuff(stacks),
            "weak"       => new WeakBuff(stacks),
            "vulnerable" => new VulnerableBuff(stacks),
            _ => throw new ArgumentException($"未知的 Buff Id: {id}", nameof(id)),
        };
    }
}
```

`switch` 而不是字典注册：Buff 种类是代码里的封闭集合，新 Buff 必然要写子类，顺手加一行分支的成本为零；注册表只会让"漏注册"从编译期错误变成运行期错误。

### 4.4 牌堆

```csharp
public sealed class CardPile
{
    /// 从手牌移出，但不放入任何牌区——打出中的牌处于"结算中"状态。
    public CardDefinition TakeFromHand(int handIndex);
    /// 结算完毕后放入弃牌堆。0.4 会加 AddToExhaust。
    public void AddToDiscard(CardDefinition card);
    // Draw / DiscardHand / 重洗不变
}
```

**[已定] 删除 `PlayCard(int)`。** 它就是 0.1 时序（移出手牌并立刻进弃牌）的化身；保留为组合方法等于留一条保证错的路——谁调它谁就回到"抽牌插进手牌、重洗把打出中的牌洗回去"。0.4 落堆按类型分叉后更没有它的位置。`CardPileTests.PlayCard_MovesCardFromHandToDiscardPile` 改成分别测 `TakeFromHand`（手牌少一、弃牌不变）与 `AddToDiscard`（弃牌加一），这是本版本唯一"不只改构造"的旧测试。`BattleSession.TryPlayCard` / `BattleController.PlayCard` 是玩家命令，名字不改。

### 4.5 抽牌 Action

```csharp
namespace CardRPGFramework.Core.Actions
{
    public sealed class DrawCardsAction : IAction
    {
        private readonly CardPile _pile;
        private readonly int _count;
        public DrawCardsAction(CardPile pile, int count) { ... }
        public void Execute(ActionContext context) => _pile.Draw(_count);
    }
}
```

**[已定] 不设 `DrawEffect`。** Phase 2a 把 Effect 钉死为"只改 `CombatantState`、只依赖 `Core.Combatants`"，现有五个 Effect 全是这句话；抽牌改的是 `CardPile`，不是生物。加 `DrawEffect.Apply(pile, n)` 会让 `Core.Effects` 引用 `Core.Cards`，把 2a 的底层切开，而方法体只能是一行转发。Action 自己持有它要改的对象是既有模式（`DamageAction` 持有 source / target），`DrawCardsAction` 持有 `CardPile` 与之一致。出现第二个"改牌堆"的入口再讨论。

`ActionContext` 不加 `CardPile` 字段：只有抽牌需要牌堆，由 `BattleSession` 在构造 Action 时直接传入，和 `DamageAction` 直接持有 `source/target` 一致。

### 4.6 BattleSession

```csharp
public bool TryPlayCard(int handIndex)
{
    // 校验与 0.1 相同
    var card = _cardPile.Hand[handIndex];
    if (card.Cost > Energy) return false;

    Energy -= card.Cost;
    var played = _cardPile.TakeFromHand(handIndex);      // 先离手
    foreach (var effect in played.Effects)
    {
        _actionQueue.Enqueue(ToAction(effect, Player));
    }
    _actionQueue.RunAll(new ActionContext(_actionQueue));
    _cardPile.AddToDiscard(played);                       // 再进弃牌堆

    if (Enemy.IsDead) Phase = BattlePhase.Victory;
    return true;
}

// 唯一的 EffectSpec → IAction 转换点。source 现在只会是 Player，0.6 敌人行动复用。
private IAction ToAction(EffectSpec effect, CombatantState source)
{
    var target = effect.Target == EffectTarget.Self ? source : Opponent(source);
    return effect.Kind switch
    {
        EffectKind.Damage    => new DamageAction(source, target, effect.Value),
        EffectKind.Block     => new BlockAction(target, effect.Value),
        EffectKind.Heal      => new HealAction(target, effect.Value),
        EffectKind.ApplyBuff => new ApplyBuffAction(source, target, BuffFactory.Create(effect.BuffId, effect.Value)),
        EffectKind.Draw      => new DrawCardsAction(_cardPile, effect.Value),
        _ => throw new ArgumentOutOfRangeException(nameof(effect)),
    };
}

private CombatantState Opponent(CombatantState who) => who == Player ? Enemy : Player;
```

`EnqueueCardAction` 与其中的 `switch (card.Type)` 整体删除。`ToAction` 里仍有一个 `switch`，但它穷举的是五种**效果原语**，加一张卡不会再碰它；新增一种原语（以后若有）仍要在这里加一行，这是有意的封闭点，不是要消灭的分支。

**[已定] `ToAction` 留在 `BattleSession` 私有方法。** 它需要的 `Player / Enemy / _cardPile` 都是 Session 的字段；0.6 敌人行动的第二个调用方仍是 Session（`ToAction(effect, source: Enemy)`），0.7 的刚施加保护也顺手写在这里（`source == Enemy` 时给 Buff 带标记）。现在抽 `Core.Battle.ActionFactory` 只是把三个字段改成三个参数，Session 仍知道全部细节，是搬家不是解耦。出现 Session 以外的调用方再抽。

`BattleSession` 暴露的只读预览方法（`PreviewPlayerAttack` / `PreviewEnemyAttack`）属于 0.3，本版本不加。

### 4.7 Data 层

```csharp
[Serializable]
public struct EffectSpecData
{
    public EffectKind kind;
    public EffectTarget target;
    public int value;
    public string buffId;

    public EffectSpec ToSpec() => ...;  // 复用 EffectSpec 的静态构造，让 Core 的校验兜底
    public bool TryValidate(out string error) => ...;
    // 校验：value > 0；ApplyBuff 时 BuffFactory.IsKnown(buffId)；
    // kind 与 target 一致——Damage 必须 Opponent，Block / Heal / Draw 必须 Self，ApplyBuff 任意。
    // 不加这一条，Inspector 里把伤害条的 target 填成 Self 会被 ToSpec 的静态构造静默改回 Opponent，配置错误到打出时才暴露。
}

public sealed class CardData : ScriptableObject
{
    [SerializeField] private string id;
    [SerializeField] private string displayName;
    [SerializeField] private CardType type;
    [SerializeField] private int cost;
    [SerializeField] private List<EffectSpecData> effects = new();
    // value 字段删除；TryValidate 增加：effects 非空、每条合法
}
```

**资产迁移要注意枚举重编号**：0.1 的 `type` 序列化的是整数（Attack=0 … Vulnerable=6）。改成 `{ Attack, Skill }` 后，`Attack.asset` 的 0 和 `Defend.asset` 的 1 碰巧仍合法，其余五份会变成越界值。七份资产全部在 Inspector 里重设类型并填效果列表，然后删掉 YAML 里的 `value:` 行；不要依赖"碰巧还对"。

### 4.8 表现层

```csharp
// Views/BuffDisplayNames.cs：Buff Id → 中文名，只在这里维护一份
public static class BuffDisplayNames { public static string Of(string buffId) => ...; }

// Views/CardDescriptionFormatter.cs：EffectSpec 列表 → 多行描述，只用 spec.Value（基础数值）
// Damage → "造成 N 点伤害"；Block → "获得 N 点格挡"；Heal → "恢复 N 点生命"；
// ApplyBuff → "施加 N 层{BuffDisplayNames.Of(id)}"（Self 目标写"获得"）；Draw → "抽 N 张牌"
public static class CardDescriptionFormatter
{
    public static string Format(CardDefinition card);
}
```

签名只收 `CardDefinition`，**不收 `BattleController`**：1.0 奖励页在没有战斗时也要显示候选卡，描述生成器不能依赖战斗中的 Controller。0.3 加公式后数值时另加一个带预览委托的重载，这个无参数版本保留。

`BattleView.RefreshHand` 用 `CardDescriptionFormatter.Format(card)` 替换原来的 `数值 {card.Value}`——`Value` 删除后这行不改就编不过，所以它属于本版本而不是 0.3。其余显示不变，仍然是"命令执行后主动刷新"，不引入事件。

## 5. 测试策略

- `Core.Cards`：`EffectSpec` 构造校验（Value ≤ 0、ApplyBuff 缺 Id、Draw 非 Self 抛异常）；`CardDefinition` 效果列表为空抛异常、列表被拷贝（外部修改不影响）。
- `BuffFactory`：四个 Id 各返回正确类型与层数；未知 Id 抛异常。
- `CardPile`：`TakeFromHand` 后手牌减少且弃牌堆不变；`AddToDiscard` 后弃牌堆增加；`TakeFromHand` 之后立刻 `Draw` 触发重洗时，被拿出的牌不在抽牌堆里。原 `PlayCard_MovesCardFromHandToDiscardPile` 按 4.4 节改写。
- `BattleSession`（回归）：0.1 的全部用例只改 `Strength(2)` / `Poison(3)` / `BuildDeck` 等辅助方法的构造方式，断言不动。
- `BattleSession`（新增）：
  - 痛击：敌人 HP 减 8，随后易伤 2 层；用满血敌人可断言 8 点没有被自己刚施加的易伤放大。
  - 双击：敌人有易伤时 HP 减 14；无 Buff 时减 10。
  - 剑柄打击：打出手牌第 0 张后，`Hand.Count` 不变，`DiscardPileCount` 加 1，最后一张手牌来自抽牌堆；构造"抽牌堆为空"的牌组，验证重洗后抽到的不是刚打出的那张。
- `Data`：`EffectSpecData.TryValidate` 对未知 `buffId`、`value ≤ 0`、kind 与 target 不一致（Damage + Self）返回错误（EditMode 可直接 new SO 实例测）。
- `CardDescriptionFormatter` 是纯函数，可以直接 EditMode 测三张锚点卡的多行文本；是否测由实现时决定，不作为完成条件。

## 6. 排除项

- 不做效果的条件、随机、目标选择、X 费。
- 不做 `CardType.Power`、消耗堆（0.4）。
- 不做公式后预览、Buff 行、意图预览（0.3）。
- 不做手牌上限与满手改进弃牌堆。
- 不给 `ActionContext` 加任何字段。
- 不做卡面描述里的力量快照（"造成 6 (+2) 点"）。

## 7. 关键技术决策

| 决策 | 0.2 选择 | 原因 |
| --- | --- | --- |
| 效果如何表示 | 封闭枚举 `EffectKind` + 数据条目 `EffectSpec` | 五种原语全在 Core，穷举 `switch` 编译期兜底；不做可注册的效果插件 |
| 卡牌类型 | 回到攻击 / 技能 | 类型是"是什么"，将来遗物 / 能力要读它（"每打出 3 张技能"）；效果种类另有表达 |
| Buff 实例化 | `BuffFactory` 的 `switch` | Buff 是封闭集合，漏分支应是编译期问题 |
| 打出时序 | 先离手、结算、再进弃牌 | 抽牌类效果的正确前提；与原版一致；重洗时不会把打出中的牌洗回去 |
| `EffectSpec` 值类型 | `readonly struct`，只经静态工厂构造 | 无身份、不可变的小值；可变的 `DamageContext` 才是 class |
| `CardPile.PlayCard` | 删除 | 组合方法等于旧时序，留着必被误用 |
| 抽牌走不走 Effect 层 | 直接调 `CardPile.Draw`，不设 `DrawEffect` | Effect 只改 `CombatantState`；加转发层会让 Effects 依赖 Cards |
| `ToAction` 位置 | `BattleSession` 私有方法 | 依赖的都是 Session 字段；0.6 敌人行动仍从 Session 调 |
| 卡面描述 | `Format(CardDefinition)`，不依赖 Controller | 1.0 奖励页无战斗也要生成卡面 |
| `Value` 兼容层 | 不保留 | 七张卡一次迁完，避免两套真相 |

## 8. 完成定义

- 游戏设计第 6 节验收标准全部满足。
- `BattleSession` 里不存在按卡牌 Id 或卡牌种类分支的代码；唯一的 `switch` 穷举 `EffectKind`。
- `Core` 仍不引用 `UnityEngine`；`Core.Cards` 不引用 `Core.Actions` / `Core.Buffs`；`Core.Effects` 不引用 `Core.Cards`。
- 全部 EditMode 测试通过；0.1 的测试只改构造、不改断言（`CardPileTests.PlayCard_*` 按 4.4 节改写除外）。
- README 的卡牌数量、目录说明、测试数量已更新。

## 9. 扩展边界批注（非本阶段范围）

> - **手牌上限**：原版 10 张，满手时抽到的牌进弃牌堆。出现"抽 2 张""回合开始额外抽牌"的效果时在 `CardPile.Draw` 里加，并把 `cardSlots` 扩到 10；同时要重新核对 `TakeFromHand` 之后立刻抽牌是否可能满手。
> - **目标选择**：多敌人时 `EffectTarget.Opponent` 需要变成"打出时选定的目标"，`ToAction` 多一个 `target` 参数，`EffectSpec` 本身不用改；全体 / 随机目标是新的 `EffectTarget` 值。
> - **打出中的牌**：现在"离手到进弃牌"之间牌不在任何牌区。原版此时可以被"复制打出""回声形态"读到；那要给 `CardPile` 加一个显式的"结算中"位置，不是现在。
> - **状态牌 / 诅咒**（不能打出）：需要 `CardDefinition` 上的关键词标记与 `TryPlayCard` 的检查，是 0.4 消耗 / 虚无关键词之后的事。
> - 条件效果、X 费、随机目标都不是往 `EffectKind` 加值就能表达的，出现时再决定是否把 `EffectSpec` 升级成小型表达式；不要为此提前抽象。
