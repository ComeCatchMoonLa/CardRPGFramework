# 0.3 游戏设计：可见规则

> **交付目标：让 0.1 做好的 Buff 和伤害规则在界面上看得见——双方状态栏显示每个 Buff 的层数，攻击牌卡面与敌人意图显示公式之后的伤害。预览和结算用同一个计算入口，界面不允许自己写 0.75 / 1.5。**
>
> 不做图标美术、动画、飘字、卡面上的力量快照（"造成 6 (+2) 点"）、描述文案配置化。不改任何战斗规则。

## 1. 设计原则

- **规则要能被演示。** 0.1 的 `DamageCalculator` 在测试里成立，在 Play 里几乎看不见：卡面写 6、实际掉 9，玩家只能靠心算。本版本不新增规则，只把已有规则放到表面上。
- **预览就是结算。** 卡面和意图上的数字必须等于按下去之后实际发生的数字；两者来自同一个函数，View 不复算公式。
- **界面只读。** View 读战斗状态与只读预览，不改数据，与 0.1 的边界一致。

## 2. 可见规则

| 位置 | 显示 | 数据来源 |
| --- | --- | --- |
| 玩家 / 敌人状态栏 | 每个 Buff 的名称与层数，例如 `力量 2  中毒 3`；0 层不显示 | `CombatantState.Buffs` |
| 手牌卡面 | 0.2 的基础描述，其中攻击伤害一行改为**公式后**数值 | 效果列表 + 只读预览 |
| 敌人意图 | `攻击 X`，X 为公式后数值 | 只读预览 |

对局例子（都以攻击卡基础 6 点、敌人固定攻击 6 点为准）：

- 玩家**没有力量**、敌人有易伤：攻击卡写 `造成 9 点伤害`，打出去掉 9。
- 玩家有 2 层力量、敌人有易伤：攻击卡写 `造成 12 点伤害`（`floor((6 + 2) × 1.5)`），不是 9 也不是 11。
- 敌人有虚弱：意图从 `攻击 6` 变为 `攻击 4`，结束回合后玩家掉 4。
- 双击对易伤敌人：两行各写 `造成 7 点伤害`，合计 14，与 0.2 的结算测试一致。
- 0 层 Buff 不出现在状态栏（0.7 之前 0 层仍留在内部字典里，界面过滤掉）。

## 3. 本阶段不包含

- 力量快照、升级、稀有度等卡面附加信息。
- Buff 图标、意图图标、动画、飘字。
- 描述文案做成配置字段（生成即可，两套真相更糟）。
- 多段攻击意图求和、`减益` / `防御` 等意图种类（0.6 敌人行动表才有多段与非攻击行动）。
- 任何规则改动：虚弱 / 易伤仍按"有无"生效、层数不衰减（0.7）。

## 4. 验收标准

- 对敌人施加易伤后，手牌里攻击卡显示的数字与实际扣血一致；玩家无力量时该数字为 9。
- 玩家有 2 层力量且敌人有易伤时，攻击卡显示 12，实际扣血 12。
- 对敌人施加虚弱后，意图数字从 6 变为 4，与结束回合后实际掉血一致。
- 界面上双方 Buff 名称与层数正确；中毒每轮减 1 时状态栏跟着变；0 层不显示。
- 0.2 的全部测试不改断言通过；全部 EditMode 测试通过；Console 无错误。
