# 0.3 技术设计：可见规则

> **技术目标：`BattleSession` 暴露两个只读预览函数，复用 `DamageCalculator`；`BattleController` 原样转发；`CardDescriptionFormatter` 加一个带预览委托的重载；`BattleView` 增加双方 Buff 行、意图改为预览数、卡面用公式后数值。不改 Core 结算路径。**
>
> 本版本改动小、没有新的 Core 类型，但它决定了 90 秒演示里 Rule 能不能被看见。

## 1. 技术原则

延续 0.1 / 0.2 的优先级：**正确性 > 可测试性 > 可读性 > 当前已知需求的扩展性**。补充：

- 预览是纯函数调用：新建 `DamageContext`，规则只读 Buff、只写 `context.Damage`，不改任何战斗状态。
- 预览是**格挡前**的最终伤害：`DamageCalculator.CalculateFinalDamage` 的返回值，就是 `DamageAction.Execute` 交给 `DamageEffect` 的那个数。格挡在 `CombatantState.TakeDamage` 里扣，预览不复算格挡，也不在 Session 里加一条"预览用"的扣格挡路径。
- 伤害修正只进 `IDamageRule`，不写进 `DamageAction.Execute`：公式只有 `DamageCalculator` 一处，但拼装 `DamageContext` 的地方从此有两处（结算与预览），任何绕过 Rule 的修正都会让预览漂。
- View 不允许出现 0.75 / 1.5 / 力量加法这类公式常数；它只显示 Controller 给的数。
- 描述生成器仍不依赖 Controller 类型：预览以委托传入，0.2 的无委托版本保留给 1.0 奖励页。

## 2. 分层与依赖

```text
Views（BattleView：Buff 行、意图、卡面；CardDescriptionFormatter：加预览重载）
  ↓ 只读
Controllers（BattleController：转发 PreviewPlayerAttack / PreviewEnemyAttack）
  ↓
Core.Battle（BattleSession：两个预览方法）
  ↓
Core.Rules（不变；预览直接调用 DamageCalculator）
```

依赖方向不变，没有新命名空间。

## 4. 核心接口

### 4.1 BattleSession

```csharp
/// 只读预览：与 DamageAction.Execute 用同一个 DamageContext / DamageCalculator。
public int PreviewPlayerAttack(int baseDamage) =>
    DamageCalculator.CalculateFinalDamage(new DamageContext(baseDamage, Player, Enemy));

public int PreviewEnemyAttack() =>
    DamageCalculator.CalculateFinalDamage(new DamageContext(EnemyDamage, Enemy, Player));
```

`PreviewPlayerAttack` 收基础值而不是卡：一张牌可能有多条 Damage（双击），每条独立预览、独立取整，与结算一致。`PreviewEnemyAttack` 现在只读 `EnemyDamage`；0.6 敌人行动表会改成遍历当前行动的 Damage 条目求和，签名不变。

两个预览的 `(baseDamage, source, target)` 配对必须与结算处相同：玩家攻击对应 `ToAction` 里 `EffectKind.Damage` 的 `(effect.Value, Player, Enemy)`，敌人攻击对应 `TryEndPlayerTurn` 里的 `(EnemyDamage, Enemy, Player)`。预览读的是**此刻**的 Buff，所以痛击的 8 点不会算进它自己即将施加的易伤，与"先伤后易伤"的结算一致。

### 4.2 BattleController

```csharp
public int PreviewPlayerAttack(int baseDamage) => _session?.PreviewPlayerAttack(baseDamage) ?? baseDamage;
public int PreviewEnemyAttack() => _session?.PreviewEnemyAttack() ?? 0;
```

原样转发，不加逻辑。`BattleController.EnemyDamage` 在 View 改用预览后暂无消费者，本版不删：0.6 游戏设计已点名它与 `BattleSession.EnemyDamage` 一起换成"当前行动"，留到那时一次处理。

### 4.3 CardDescriptionFormatter

```csharp
public static class CardDescriptionFormatter
{
    // 0.2：基础数值，1.0 奖励页复用
    public static string Format(CardDefinition card);

    // 0.3：Damage 行的数字经 previewAttackDamage 转换，其余行不变
    public static string Format(CardDefinition card, Func<int, int> previewAttackDamage);
}
```

用委托而不是 `BattleController` 参数：View 已经依赖 Controller，但生成器本身保持只依赖 `CardDefinition` 与一个 `int → int`，不必为奖励页造一个假 Controller。委托约定**非空**，不接受 `null`；1.0 奖励页没有战斗，用无委托重载（1.0 游戏设计第 7.7 条已写死这一点）。实现上无委托版本可以用恒等委托复用带委托版本，两条路径只保留一份逐条生成的代码。

### 4.4 BattleView

- `Refresh` 新增双方 Buff 行：遍历 `Buffs`，过滤 `Stacks == 0`，`BuffDisplayNames.Of(id)` + 空格 + 层数，多条用两个空格连接；没有 Buff 时显示空串。
- 意图行改为 `攻击 {controller.PreviewEnemyAttack()}`，不再读 `controller.EnemyDamage`。
- `RefreshHand` 改用 `Format(card, controller.PreviewPlayerAttack)`。
- 场景里补两个 Buff 文本对象（玩家 / 敌人各一）并接线。

仍然是"命令执行后主动刷新"，不引入事件。

## 5. 测试策略

- `BattleSession`（新用例写在 `BattleSessionTests.Preview.cs` partial 文件里，复用 `CreateSession`）。写法固定为：**先调 `Preview*` 记下数字，再 `TryPlayCard` / `TryEndPlayerTurn`，断言 HP 差值等于记下的数字**（双方 0 格挡）。只和 `DamageCalculator.CalculateFinalDamage` 对拍不算覆盖——`Preview*` 本身就是它的一行包装，对拍等于没测。
  - `PreviewPlayerAttack(6)` 在敌人易伤下等于 9，且等于随后实际打出攻击卡的掉血。
  - 玩家 2 层力量 + 敌人易伤时等于 12（`floor((6 + 2) × 1.5)`），且等于实际掉血。
  - `PreviewEnemyAttack()` 在敌人虚弱下等于 4，且等于结束回合后玩家掉血。
  - 预览不改状态：连续调用两次结果相同，双方 HP / Buff 不变。
- `CardDescriptionFormatter` 重载（必测，它锁的是"逐条换 Damage 数字、其余行不动"的生成器契约；0.2 的无委托用例抓不到只换第一行或把 Block 也换掉的错）：
  - 双击在"每段 5 → 7"的 stub 委托下两行各写 7。
  - 痛击在"8 → 12"的 stub 委托下第一行写 12，第二行 `施加 2 层易伤` 不变。
  - 0.2 的无委托用例不改断言。
- Controllers / Views 仍不做自动化测试，靠 Play 验收。

## 6. 排除项

- 不做力量快照（"6 (+2)"），预览直接显示最终数。
- 不做多段攻击意图求和、意图种类推导（0.6）。
- 不做多敌人的预览目标参数。
- 不做 Buff 图标 prefab、事件驱动刷新。

## 7. 关键技术决策

| 决策 | 0.3 选择 | 原因 |
| --- | --- | --- |
| 预览怎么算 | Session 暴露两个纯函数，复用 `DamageCalculator` | 一处公式；View 不复算常数 |
| 预览语义 | 格挡前的 `DamageCalculator` 输出 | 与原版意图一致；把格挡折进去就要在 Session 或 View 复算 `TakeDamage`，等于第二条结算路径 |
| 预览入参 | 基础伤害 `int`，不是卡 | 多段卡每段独立预览、独立取整，与结算一致 |
| 生成器怎么拿预览 | `Func<int,int>` 委托重载 | 不让生成器依赖 Controller 类型；0.2 的无委托版本留给 1.0 |
| 0 层怎么处理 | View 过滤 | 内部清理是 0.7 轮末减层的事，不在显示层顺手改数据 |

## 9. 扩展边界批注（非本阶段范围）

> - **多段行动的意图**：0.6 的 `PreviewEnemyAttack` 改为遍历当前行动的 Damage 条目逐段预览求和；意图文案（`攻击 7 · 防御`）由效果列表推导。
