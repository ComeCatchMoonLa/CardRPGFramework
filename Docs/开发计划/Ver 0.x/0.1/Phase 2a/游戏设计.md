# Phase 2a 游戏设计：Action 驱动的卡牌结算

> **交付目标：把卡牌效果的结算方式从"直接改状态"重构成"生成 Action 入队、Action 执行时调用 Effect"，玩家能观察到的战斗行为与 Phase 1 完全一致。**
>
> 本阶段是纯架构重构，不新增任何玩法规则、卡牌或数值。判断标准不是"好不好玩"，是"结构对不对、能不能被测试证明"。

Phase 1 用 `switch(CardType)` 直接调用 `CombatantState` 的方法完成结算，能跑但没有给后续的 Buff 触发（Phase 2b）和伤害规则修正（Phase 2c）留执行入口。本阶段补上这个入口。

## 1. 设计原则

- 玩家可见行为零变化：攻击 6 点、防御 5 点格挡、治疗 4 点，能量/手牌/牌堆规则全部照旧。
- 只重构"卡牌效果怎么被执行"，不碰"卡牌效果是什么"（那是 Phase 2b/2c 的事）。
- 新增的 Action/Effect 种类和 Phase 1 已有的三种卡牌效果一一对应，不提前设计通用组合能力。

## 2. 玩法要求（与 Phase 1 保持一致）

- 战斗目标、胜负条件、核心循环见 [`Docs/Phase 1/游戏设计.md`](../Phase%201/游戏设计.md) 第 2、3 节，本阶段不修改。
- 卡牌数值（攻击/防御/治疗的费用与效果值）见同文档第 5 节，本阶段不修改。
- 敌人规则见同文档第 6 节，本阶段不修改。

## 3. 可观察的架构证据

因为玩法本身不变，本阶段的"验收"体现在能被 EditMode 测试断言的架构行为上：

- 打出一张卡牌后，能观察到对应的 Action 确实被创建并执行过（不是直接跳过队列改状态）。
- 一次 `TryPlayCard` 调用内，Action 队列执行完毕后才能进入下一步（不存在"队列还没跑完，卡牌已经进弃牌堆"这种时序错误）。
- 队列支持在执行过程中继续入队新 Action（这一条本阶段不会被用到，但要有对应测试证明队列具备这个能力，因为 Phase 2b 的中毒触发直接依赖它）。

## 4. 本阶段不包含

- 不新增卡牌、Buff、Rule 或任何新玩法数值（全部留给 Phase 2b/2c）。
- 不支持多目标、条件判断、延迟执行等组合型 Action（见 [`技术设计.md`](技术设计.md) 排除项）。
- 不改变 UI 表现，`BattleView` 等 Views 层无需改动。

## 5. 验收标准

- 完整运行一次胜利/失败流程，行为与 Phase 1 完全一致（数值、回合数、结束条件不变）。
- EditMode 测试能证明：卡牌效果通过 Action 队列执行，而不是 `BattleSession` 直接调用 `CombatantState`。
- `BattleSessionTests.cs` 中 Phase 1 遗留的测试全部保持通过，不需要因为内部重构而修改断言。
