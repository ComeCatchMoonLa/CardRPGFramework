# 0.4 技术设计：消耗堆与能力牌

> **草稿。** 本文是把原"0.3 消耗堆、能力牌、遗物"的技术设计按功能拆开后留下的牌区部分。按 [`../../README.md`](../../README.md) 第 2 节的细化深度规则，进入 0.4 前要对照 0.2 / 0.3 的实际实现复核接口形状，再补齐并去掉这个草稿头。
>
> **技术目标：`CardPile` 增加第四个牌区，打出后的去向由 `CardDefinition` 自己回答（类型默认 + 关键词覆盖）；`BattleSession.TryPlayCard` 落堆那一行改成按去向分流。**

## 1. 技术原则

延续 0.1～0.3 的优先级：**正确性 > 可测试性 > 可读性 > 当前已知需求的扩展性**。补充：

- 去向判断放在 `CardDefinition`，不放在 `BattleSession`："类型 / 关键词决定去向"是牌的规则，和"效果列表决定发生什么"一样是牌自己的事。
- 关键词只做当前有消费者的那一个（消耗）。
- 标注 **[待确认]** 的是接口形状上有备选的地方，进入本版本时由你定。

## 2. 分层与依赖

## 4. 核心接口

### 4.1 卡牌类型、关键词与去向

```csharp
public enum CardType { Attack, Skill, Power }   // 追加在末尾，0.2 资产的序列化整数不受影响

public sealed class CardDefinition
{
    // ...0.2 的字段
    public bool Exhaust { get; }                      // 关键词，只在被打出时生效
    public bool ExhaustsWhenPlayed => Exhaust || Type == CardType.Power;

    public CardDefinition(string id, string displayName, CardType type, int cost,
                          IReadOnlyList<EffectSpec> effects, bool exhaust = false)
}
```

`exhaust` 用可选参数是为了 0.1～0.3 的测试辅助方法不必全部改动。

**[待确认]** 关键词现在用一个 `bool`。出现第二个关键词（虚无 / 固有 / 保留）时改成 `[Flags] enum CardKeyword`；现在不提前做。

### 4.2 牌堆

```csharp
public sealed class CardPile
{
    private readonly List<CardDefinition> _exhaustPile = new();
    public int ExhaustPileCount => _exhaustPile.Count;

    /// 消耗堆只进不出；重洗只动弃牌堆。
    public void AddToExhaust(CardDefinition card);
}
```

`ReshuffleDiscardIntoDrawPile` 与 `DiscardHand` 不改：消耗堆不参与任何流转，"消耗"只发生在 `TryPlayCard` 落堆那一步。

### 4.3 BattleSession

```csharp
// TryPlayCard 落堆那一行改为：
if (played.ExhaustsWhenPlayed) _cardPile.AddToExhaust(played); else _cardPile.AddToDiscard(played);
```

这是本版本对 `BattleSession` 的唯一改动。

### 4.4 Data 层

```csharp
public sealed class CardData : ScriptableObject
{
    // ...0.2 的字段
    [SerializeField] private bool exhaust;
}
```

`ToDefinition()` 把 `exhaust` 传给构造函数；`TryValidate` 不需要新规则（bool 没有非法值）。

### 4.5 表现层

- `BattleController` 新增 `ExhaustPileCount`。
- `BattleView` 新增一行 `抽牌 X  弃牌 Y  消耗 Z`。文字即可。

## 5. 测试策略

- `CardDefinition`：`Power` 类型 `ExhaustsWhenPlayed` 为 true；`Skill + exhaust` 为 true；普通攻击为 false。
- `CardPile`：`AddToExhaust` 后 `ExhaustPileCount` 增加、弃牌堆不变；抽牌堆与弃牌堆都为空时 `Draw` 不会从消耗堆取牌。
- `BattleSession`：
  - 打出能力牌后 `ExhaustPileCount == 1`、`DiscardPileCount` 不变；连续结束回合触发重洗后，`Hand + DrawPile + DiscardPile` 的总数恒等于牌组张数减 1。
  - 坚不可摧：格挡 30 且进消耗堆；留在手里结束回合时进弃牌堆、消耗堆为 0。
- 0.1～0.3 全部测试不改断言通过。

## 6. 排除项

- 不做 `CardKeyword` 枚举，不做虚无 / 固有 / 保留 / 不能打出。
- 不做"消耗时触发"钩子、不做从消耗堆取牌、不做"消耗手牌中一张"的效果。
- 不做消耗堆列表可视化。

## 7. 关键技术决策

| 决策 | 0.4 选择 | 原因 |
| --- | --- | --- |
| 去向判断在哪 | `CardDefinition.ExhaustsWhenPlayed` | 类型 / 关键词决定去向是牌的规则，`BattleSession` 只问结果 |
| 关键词表示 | 一个 `bool Exhaust`（待确认） | 只有一个关键词有消费者 |
| `Power` 枚举位置 | 追加在末尾 | 不动 0.2 资产里已序列化的整数 |

## 8. 完成定义

- 游戏设计第 5 节验收标准全部满足。
- 新增一张消耗牌 = 一份 `CardData` 勾 `exhaust`，`BattleSession` 不改。
- 全部 EditMode 测试通过；0.1～0.3 测试不改断言。
- README 的卡牌数（18 张 / 11 种）、四个牌区说明、测试数已更新。

## 9. 扩展边界批注（非本阶段范围）

> - **消耗触发**（"每当消耗一张牌"）：在 `TryPlayCard` 落入消耗堆那一步之后遍历钩子；同时要决定"被效果消耗"与"被打出后消耗"是否共用同一个时机。
> - **多关键词**：第二个关键词出现时 `bool Exhaust` 改 `[Flags]`；不能打出 / 虚无还要改 `TryPlayCard` 校验与 `DiscardHand`。
> - **状态牌 / 诅咒**：需要"不能打出"关键词与 `TryPlayCard` 的检查，以及把牌塞进牌组的效果原语。
