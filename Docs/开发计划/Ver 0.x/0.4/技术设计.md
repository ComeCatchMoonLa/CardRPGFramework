# 0.4 技术设计：消耗堆与能力牌

> **技术目标：`CardPile` 增加第四个牌区，打出后的去向由 `CardDefinition` 自己回答（类型默认 + 关键词覆盖）；`BattleSession.TryPlayCard` 落堆那一行改成按去向分流，并按既有模式转发 `ExhaustPileCount`；卡面标类型、勾消耗的牌印"消耗"。**
>
> 本文由原"0.3 消耗堆、能力牌、遗物"的技术设计按功能拆出，在 0.3 完成后对照 0.2 / 0.3 的实际实现（`CardPile` 哑容器、`TryPlayCard` 先离手再落堆、`BattleSession` 私有持有牌堆并转发数量、`CardDescriptionFormatter` 两个重载）复核过接口形状，已转正。

## 1. 技术原则

延续 0.1～0.3 的优先级：**正确性 > 可测试性 > 可读性 > 当前已知需求的扩展性**。补充：

- 去向判断放在 `CardDefinition`，不放在 `BattleSession`："类型 / 关键词决定去向"是牌的规则，和"效果列表决定发生什么"一样是牌自己的事。`BattleSession` 只问 `ExhaustsWhenPlayed`，代码里不出现 `Type == Power`，`CardPile` 也不自己判断去向。
- 关键词只做当前有消费者的那一个（消耗）。
- "消耗只在被打出时生效"由 `DiscardHand` 与 `ReshuffleDiscardIntoDrawPile` **不看牌**来保证，这两个方法本版禁止改动。
- 标注 **[已定]** 的是接口形状上曾有备选的地方，结论与不选备选的理由一并写下，实现时不再重议。

## 2. 分层与依赖

```text
Views（BattleView：牌堆数量行、卡面类型标签；CardDescriptionFormatter：Exhaust 关键词行）
  ↓ 只读
Controllers（BattleController：转发 ExhaustPileCount）
  ↓
Core.Battle（BattleSession：TryPlayCard 按去向落堆；转发 ExhaustPileCount）
  ↓
Core.Cards（CardType 加 Power；CardDefinition 加 Exhaust 与 ExhaustsWhenPlayed；CardPile 加消耗堆）
```

依赖方向不变，没有新的命名空间。`BattleSession` 私有持有 `CardPile`，Controller 只能经 Session 读牌堆数量——所以 `ExhaustPileCount` 必须像 `DrawPileCount` / `DiscardPileCount` 一样在 Session 上有只读口，否则 Controller 没有合法读法。

## 4. 核心接口

### 4.1 卡牌类型、关键词与去向

```csharp
public enum CardType { Attack, Skill, Power }   // 追加在末尾，0.2 资产的序列化整数不受影响

public sealed class CardDefinition
{
    // ...0.2 的字段
    public bool Exhaust { get; }                      // 关键词，只在被打出时生效
    public bool ExhaustsWhenPlayed => Exhaust || Type == CardType.Power;

    public CardDefinition(string id, string displayName, CardType type, int cost,
                          IReadOnlyList<EffectSpec> effects, bool exhaust = false)
}
```

`exhaust` 用可选参数是为了 0.1～0.3 的测试辅助方法不必全部改动。构造函数因此到 6 个参数，超出风格线一格；不为此引入参数对象——出现第二个关键词时 `bool` 换成一个 `[Flags]` 值，参数数不再增长。

**[已定] 关键词用一个 `bool Exhaust`，不做 `[Flags] enum CardKeyword`。** 本版只有消耗一个关键词有消费者，Flags 没有第二个调用方，现在做出来就是空壳；虚无 / 固有 / 保留出现时再把 `bool` 迁成 Flags，那时构造参数数也不再增长。

### 4.2 牌堆

```csharp
public sealed class CardPile
{
    private readonly List<CardDefinition> _exhaustPile = new();
    public int ExhaustPileCount => _exhaustPile.Count;

    /// 消耗堆只进不出；重洗只动弃牌堆。null 与 AddToDiscard 一样抛 ArgumentNullException。
    public void AddToExhaust(CardDefinition card);
}
```

不公开消耗堆的列表（游戏设计只显示数量）。`ReshuffleDiscardIntoDrawPile` 与 `DiscardHand` **禁止改动**：它们不看牌，这正是"消耗只在被打出时生效"的实现——顺手让 `DiscardHand` 检查 `ExhaustsWhenPlayed`，本版的对照用例（坚不可摧留手进弃牌堆）就测不出东西了。`CardPile` 继续是哑容器，去向由调用方告诉它。

### 4.3 BattleSession

```csharp
// 与 DrawPileCount / DiscardPileCount 同一模式的只读口，Controller 经它转发
public int ExhaustPileCount => _cardPile.ExhaustPileCount;

// TryPlayCard 落堆那一行改为：
if (played.ExhaustsWhenPlayed) _cardPile.AddToExhaust(played); else _cardPile.AddToDiscard(played);
```

本版本对 `BattleSession` 的改动只有这两处：一个只读口、一处落堆分流。分流问的是 `played.ExhaustsWhenPlayed`，Session 里不写 `Type == CardType.Power`、不读 `.Exhaust`，也不按卡 Id。

### 4.4 Data 层

```csharp
public sealed class CardData : ScriptableObject
{
    // ...0.2 的字段
    [SerializeField] private bool exhaust;
}
```

`ToDefinition()` 把 `exhaust` 传给构造函数；`TryValidate` 不需要新规则（bool 没有非法值；能力牌再勾 `exhaust` 只是多余，去向不变，卡面会多印一行"消耗"，不算配置错误）。

`Power` 追加为整数 2 之后，`TryValidate` 里的 `Enum.IsDefined(typeof(CardType), type)` 会把 2 视为合法——0.1 遗留的 `Heal = 2` 不再被拦。当前 10 份资产的 `type` 全是 0 / 1，没有残留；迁移力量强化时在 Inspector 里显式把类型改成 Power，不要指望校验去"发现"哪张该改。

### 4.5 表现层

- `BattleController` 新增 `ExhaustPileCount => _session?.ExhaustPileCount ?? 0`，原样转发。
- `BattleView` 新增一行 `抽牌 X  弃牌 Y  消耗 Z`，文字即可。这是牌堆数量第一次上界面：Controller 早有 `DrawPileCount` / `DiscardPileCount` 但 View 一直没显示；场景补一个文本对象并接线。
- 卡面类型标签：`RefreshHand` 的卡面文本从 `名字 / 费用 X / 描述` 改为 `名字 / 类型 · 费用 X / 描述`，**所有手牌**都带类型，不是只给能力牌打标；类型中文（攻击 / 技能 / 能力）用 `BattleView` 里一个私有 `switch`，出现第二个调用方（1.0 奖励页）再抽成与 `BuffDisplayNames` 同类的静态类。描述行本身与 0.3 相同，只有勾消耗的牌多出末行。
- `CardDescriptionFormatter`：`card.Exhaust` 为 true 时在描述末尾追加一行 `消耗`；能力牌靠类型进消耗堆，**不印**"消耗"（原版同）。两个重载共用同一条生成路径，带预览的版本自然也带关键词行。0.2 / 0.3 的用例都是未勾消耗的攻击 / 技能，不改断言。

## 5. 测试策略

- `CardDefinition`：`Power` 的 `ExhaustsWhenPlayed` 为 true；`Skill + exhaust` 为 true；普通攻击为 false；不传 `exhaust` 时 `Exhaust` 为 false。
- `CardPile`：`AddToExhaust` 后 `ExhaustPileCount` 加一、手牌与弃牌堆不变；`AddToExhaust(null)` 抛 `ArgumentNullException`；抽牌堆与弃牌堆都为空、消耗堆有牌时 `Draw` 安全停止、手牌不变；`DiscardHand` 把勾了 `exhaust` 的牌也放进弃牌堆。
- `BattleSession`（新用例写在 `BattleSessionTests.Exhaust.cs`）：
  - 打出能力牌后 `ExhaustPileCount == 1`、`DiscardPileCount` 不变；连续结束回合触发重洗后，**四区之和 `Hand + DrawPile + DiscardPile + ExhaustPile` 恒等于牌组张数，且 `ExhaustPileCount` 仍为 1**（只写三区之和 = 牌组减 1 分不清"进了消耗堆"和"牌丢了"），重洗后手牌与抽牌堆里都没有那张能力牌的实例。
  - 坚不可摧：打出后格挡 30 且 `ExhaustPileCount == 1`；留在手里结束回合时进弃牌堆、`ExhaustPileCount == 0`。
- **既有辅助方法的约定**：0.1 的 `Strength()` **保持 `CardType.Skill`**，所有旧辅助方法不传 `exhaust`。能力牌用新辅助方法（如 `Inflame()`：Power、1 费、2 层力量），坚不可摧用 `Impervious()`。原因：`TryPlayCard_Strength_AppliesStacksToPlayer` 只断言层数，把 `Strength()` 改成 Power 它照样绿，但 0.1 对"技能施加 Buff 后进弃牌"的覆盖就被静默改走了——假绿比红更糟。
- `CardDescriptionFormatter`：勾消耗的技能末行为 `消耗`（`"获得 30 点格挡\n消耗"`）；Power 不印；带预览委托的重载同样追加。
- `Data`：`CardData.exhaust` 只是透传给构造函数，不单独写 EditMode 用例，靠 Play 验收（坚不可摧进消耗堆）覆盖。
- 0.1～0.3 全部测试不改断言通过。

## 6. 排除项

- 不做 `CardKeyword` 枚举，不做虚无 / 固有 / 保留 / 不能打出。
- 不做"消耗时触发"钩子、不做从消耗堆取牌、不做"消耗手牌中一张"的效果。
- 不做消耗堆列表可视化；卡面以外不做关键词 / 类型的图标。

## 7. 关键技术决策

| 决策 | 0.4 选择 | 原因 |
| --- | --- | --- |
| 去向判断在哪 | `CardDefinition.ExhaustsWhenPlayed` | 类型 / 关键词决定去向是牌的规则，`BattleSession` 只问结果 |
| 关键词表示 | 一个 `bool Exhaust`（已定，不做 Flags） | 只有一个关键词有消费者 |
| `Power` 枚举位置 | 追加在末尾 | 不动 0.2 资产里已序列化的整数 |
| 消耗堆数量怎么到界面 | Session 只读口 → Controller 转发 → View | 与 `DrawPileCount` / `DiscardPileCount` 同一条路，Controller 不掏 `CardPile` |
| `DiscardHand` / 重洗 | 不改、不看牌 | "消耗只在打出时生效"就是靠它们不看牌 |
| 卡面怎么体现去向 | 类型标签 + 仅 `Exhaust` 印"消耗" | 原版能力牌不印消耗；Play 里能分清两条路径 |
| 既有测试辅助方法 | `Strength()` 仍是 Skill，能力牌另写 `Inflame()` | 防止"不改断言仍绿"变成假绿 |

## 8. 完成定义

- 游戏设计第 5 节验收标准全部满足。
- 新增一张消耗牌 = 一份 `CardData` 勾 `exhaust`，新增一张能力牌 = 类型设为 Power，`BattleSession` 不改。
- `BattleSession` 里除属性名 `ExhaustsWhenPlayed` 外不出现 `Power` / `Exhaust`（不写 `Type == CardType.Power`、不读 `.Exhaust`）；`DiscardHand` 与 `ReshuffleDiscardIntoDrawPile` 未改。
- 全部 EditMode 测试通过；0.1～0.3 测试不改断言，0.1 的 `Strength()` 辅助方法仍是 Skill。
- README 的卡牌数（18 张 / 11 种）、四个牌区说明、卡面类型与关键词、测试数已更新。

## 9. 扩展边界批注（非本阶段范围）

> - **消耗触发**（"每当消耗一张牌"）：在 `TryPlayCard` 落入消耗堆那一步之后遍历钩子；同时要决定"被效果消耗"与"被打出后消耗"是否共用同一个时机。
> - **多关键词**：第二个关键词出现时 `bool Exhaust` 改 `[Flags]`；不能打出 / 虚无还要改 `TryPlayCard` 校验与 `DiscardHand`。
> - **状态牌 / 诅咒**：需要"不能打出"关键词与 `TryPlayCard` 的检查，以及把牌塞进牌组的效果原语。
