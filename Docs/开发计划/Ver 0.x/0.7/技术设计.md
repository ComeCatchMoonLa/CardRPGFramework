# 0.7 技术设计：回合型 Buff（草稿）

> **草稿。** 本文随 0.6 三件套一并写成，接口形状基于 [`../0.6/技术设计.md`](../0.6/技术设计.md) 而不是 0.6 的实际实现。进入 0.7 前按文末"复核清单"对照 0.6 代码复核，再去掉本头转正；两处接口形状（保护标记走 `BuffFactory.Create` 可选参数、`OnRoundEnd()` 无参）已在 0.6 评审时定下，复核只确认它们与 0.6 实际代码兼容。按 [`../../README.md`](../../README.md) 第 2 节的规则，它不算"已细化"。
>
> **技术目标：给虚弱 / 易伤补"轮结束减 1、刚施加不减、0 层移除"三条语义。新增一个与 `IBuffTrigger` 同形的轮末触发接口和一个两者共用的中间基类；保护标记在构造时给、只跳过一次、叠加时不传递；`BattleSession.TryEndPlayerTurn` 在行动指针前进之后、`StartPlayerTurn` 之前多一步 `EndRound`。Data 层删一条校验、加一份蓝奴隶贩子资产，其余零改动。**

## 1. 技术原则

延续 0.1～0.6 的优先级：**正确性 > 可测试性 > 可读性 > 当前已知需求的扩展性**。补充：

- **三个时机、三个遍历，不合并。** 开战（0.5 遗物）、回合开始（0.1 中毒）、轮结束（本版本）各自是 `foreach` + 类型判断；不做"事件"枚举、不做订阅。
- **轮末触发只改自己的层数，不入队 Action、不碰容器。** 减层没有对外效果（不掉血、不给格挡），`PoisonBuff.OnTurnStart` 里 `RemoveStacks(1)` 是先例；移除 0 层放在遍历之后由 `CombatantState` 自己做，遍历中不改字典。
- **保护标记是构造时的事实。** 与一代 `isSourceMonster` 一致：在 `BuffFactory.Create` 时给，`BuffState` 基类不加字段；叠加走的是 `existing.AddStacks`，新实例被丢弃，保护自然不传递——0.1 的 `ApplyBuff` 一行不改就得到第 4 节的叠加语义。
- **层数语义不变。** `WeakDamageRule` / `VulnerableDamageRule` 仍按"有无"乘倍率；`HasBuff` 仍 `> 0`。本版本只加时间维度。
- **敌人侧零新代码。** 蓝奴隶贩子只是一份 `EnemyData`；0.6 的 `IntentFormatter` 已经会显示 `减益`。

## 4. 核心接口

### 4.1 Core.Buffs

```csharp
namespace CardRPGFramework.Core.Buffs
{
    /// 轮结束触发：只有回合型 Buff 实现。与 IBuffTrigger 同形（固定时机遍历 + 类型判断），
    /// 但没有 queue 参数——减层是 Buff 自己的层数变化，没有对外效果，不需要入队 Action。
    public interface IRoundEndTrigger
    {
        void OnRoundEnd();
    }

    /// 虚弱 / 易伤的共同中间基类：层数 = 剩余轮数；刚施加保护只在新建时给、只跳过一次。
    /// BuffState 基类不加字段：力量 / 中毒没有"剩余轮数"这个概念。
    public abstract class DurationBuff : BuffState, IRoundEndTrigger
    {
        private bool _justApplied;

        protected DurationBuff(int stacks, bool justApplied) : base(stacks) => _justApplied = justApplied;

        public void OnRoundEnd()
        {
            if (_justApplied)
            {
                _justApplied = false;   // 一代 justApplied：跳过第一次轮末减层
                return;
            }

            RemoveStacks(1);
        }
    }

    public sealed class WeakBuff : DurationBuff
    {
        public override string Id => BuffIds.Weak;
        public WeakBuff(int stacks, bool justApplied = false) : base(stacks, justApplied) { }
    }

    public sealed class VulnerableBuff : DurationBuff { /* 同上 */ }

    public static class BuffFactory
    {
        /// justApplied 只对回合型 Buff 有意义，力量 / 中毒忽略它。
        public static BuffState Create(string id, int stacks, bool justApplied = false) => id switch
        {
            BuffIds.Strength => new StrengthBuff(stacks),
            BuffIds.Poison => new PoisonBuff(stacks),
            BuffIds.Weak => new WeakBuff(stacks, justApplied),
            BuffIds.Vulnerable => new VulnerableBuff(stacks, justApplied),
            _ => throw new ArgumentException($"未知的 Buff Id: {id}", nameof(id)),
        };
    }
}
```

**[已定] 保护标记走 `BuffFactory.Create` 可选参数**，由 `ToAction` 传 `justApplied: source == Enemy`——一行改动，标记是构造时的事实，与一代同形；对象出工厂即合法。否决的备选 `DurationBuff.MarkJustApplied()`：工厂签名不动，但 `Create → 挂到状态 → Mark` 中间存在一个"该保护却还没标"的非法窗口，Buff 多一个只在构造后立刻调一次的可变入口，且 `ToAction` 要多一次类型判断。

**[已定] `IRoundEndTrigger.OnRoundEnd()` 无参数**——两个实现都只做"减层 / 跳过一次"，用不到 owner 或队列；`IBuffTrigger.OnTurnStart(owner, queue)` 带参数是因为中毒要对 owner 入队扣血。出现"轮末对所有者做事"的 Buff（再生？它是回合结束不是轮结束）再加，不预留 Context。

### 4.2 CombatantState 与 BattleSession

```csharp
public sealed class CombatantState
{
    /// 把 Stacks <= 0 的 Buff 从字典移除。只在轮结束步骤调用，遍历触发之后；中毒减到 0 也在这里清。
    public void RemoveExpiredBuffs();
}

public sealed class BattleSession
{
    private IAction ToAction(EffectSpec effect, CombatantState source)
    {
        // ...
        EffectKind.ApplyBuff => new ApplyBuffAction(source, target,
            // 只看施加方（一代 isSourceMonster）：敌人施加的带保护，不看目标是谁、也不看所有者本轮是否已行动——
            // 敌人给自己上的同样带保护，让玩家下一回合吃到。
            BuffFactory.Create(effect.BuffId, effect.Value, justApplied: source == Enemy)),
        // ...
    }

    public bool TryEndPlayerTurn()
    {
        // ...0.6 的敌人回合流程：清格挡 → 中毒 → 执行当前行动 → AdvanceEnemyAction
        if (Player.IsDead)
        {
            Phase = BattlePhase.Defeat;
        }
        else
        {
            EndRound();          // 新增：失败时不执行
            StartPlayerTurn();
        }

        return true;
    }

    /// 轮结束：双方回合型 Buff 各减 1（刚施加的跳过），然后统一移除 0 层。遍历中只改 Stacks，不动字典。
    private void EndRound()
    {
        TriggerRoundEnd(Player);
        TriggerRoundEnd(Enemy);
        Player.RemoveExpiredBuffs();
        Enemy.RemoveExpiredBuffs();
    }

    private static void TriggerRoundEnd(CombatantState owner)
    {
        foreach (var buff in owner.Buffs)
        {
            if (buff is IRoundEndTrigger trigger)
            {
                trigger.OnRoundEnd();
            }
        }
    }
}
```

- 叠加：`CombatantState.ApplyBuff` 已是 `existing.AddStacks(buff.Stacks)`，带保护的新实例被丢弃，已有那条的保护状态不变——正好是游戏设计第 4 节"叠加不刷新保护"，零改动。
- 金刚杵开战给的力量、蛇颅骨改层数：`ApplyBuffAction` 与 `IApplyBuffModifier` 不改；`justApplied` 对力量 / 中毒是被忽略的参数。
- `EndRound` 与 `TriggerBattleStartRelics` / `TriggerTurnStartBuffs` 并列，是第三个固定时机的遍历，不抽公共方法（三个遍历的类型和参数都不同）。

## 5. 测试策略

- `BattleSessionTests.RoundEnd.cs`（新 partial；蓝奴隶贩子用测试内 `Raker()` 定义 `[Damage 7, ApplyBuff Opponent weak 1]`，"连续两次耙"用行动表 `[耙, 耙, 待机, 待机]`）：
  - 痛击 2 层：打出痛击后 `Enemy.GetBuffStacks(易伤) == 2`、攻击预览 9；结束回合后 1；下一回合预览仍 9 且打出后 HP 差 9；再结束回合后 0 且 `Enemy.Buffs` 里没有易伤；第 3 回合预览 6。
  - 玩家给敌人 1 层虚弱：本轮敌人攻击预览 4 = HP 差；轮末消失；下一轮预览 6。
  - 耙：结束回合后 `Player.GetBuffStacks(虚弱) == 1`（轮末不减）；下一回合 `PreviewPlayerAttack(6) == 4` 且打出后敌人 HP 差 4；再结束回合后虚弱消失，第 3 回合预览 6。
  - 连续两次耙：三次结束回合后玩家虚弱层数依次 1、1、0；玩家在第 2、第 3 回合的攻击预览都是 4，第 4 回合 6。
  - 中毒不在轮末减层：剧毒 3 → 结束回合后 2（敌人回合开始掉 3 血自减 1，轮末不再减）。
  - 中毒 0 层移除：1 层中毒 → 结束回合后 `Enemy.Buffs` 里没有中毒、`HasBuff` 为 false、只掉 1 血。
  - 玩家自己带虚弱（`Player.ApplyBuff(new WeakBuff(1))`，无保护）：攻击预览 4；结束回合后消失。
  - 失败时不执行轮结束：玩家被打死那一轮，敌人身上的易伤层数不变（可观察即可，不强求）。
- `BuffTests`：`WeakBuff(2).OnRoundEnd()` → 1；`WeakBuff(1, justApplied: true)` 第一次 `OnRoundEnd` 仍 1、第二次 0；`VulnerableBuff` 同；`StrengthBuff` / `PoisonBuff` 不是 `IRoundEndTrigger`。
- `BuffFactoryTests`：`Create(weak, 1, justApplied: true)` 返回 `WeakBuff` 且第一次 `OnRoundEnd` 不减；`Create(strength, 1, justApplied: true)` 正常。
- `CombatantStateTests`：`RemoveExpiredBuffs` 移除 0 层、保留其余；叠加到已有 Buff 时保留原实例（`Buffs` 里的引用不变）。
- `EnemyActionDataTests`：0.6 那条"ApplyBuff Opponent 不通过"改为通过。
- 0.1～0.6 用例：`WeakBuff(2)` / `VulnerableBuff(1)` 这些测试构造仍编译（`justApplied` 可选）；0.1 用 `Enemy.ApplyBuff(new WeakBuff(2))` 后结束回合再断言的用例，虚弱在轮末从 2 减到 1，仍 `HasBuff`，断言不受影响——复核时逐个过一遍 `BattleSessionTests*.cs` 里"上 Buff → 结束回合 → 再断言"的用例。

预计新增约 18 项，总数约 255。

## 6. 排除项

- 不做脆弱、再生、金属化等其它带时间语义的 Buff；不加 `OnTurnEnd`（角色行动结束）时机。
- 不做负层（缴械）、不改 `HasBuff`。
- 不做"叠加刷新保护"的变体；不给 `BuffState` 基类加字段。
- 不做人工制品（取消施加）——它是 Buff 且需要极性标记，另一个版本。
- 不改 `WeakDamageRule` / `VulnerableDamageRule` / `IntentFormatter` / `BattleView`。
- 不做随机行动、多敌人。

## 7. 关键技术决策

| 决策 | 0.7 选择 | 原因 |
| --- | --- | --- |
| 轮末触发形状 | 新接口 `IRoundEndTrigger`，与 `IBuffTrigger` 同形、独立时机 | 三个时机三个遍历（批注第 2 节）；不合并成事件 |
| `OnRoundEnd` 参数 | [已定] 无参数，不预留 Context | 两个实现都用不到 owner / queue；有需要再加（0.6 评审时定） |
| 保护标记怎么传 | [已定] `BuffFactory.Create(id, stacks, justApplied = false)` + `ToAction` 传 `source == Enemy` | 构造时事实；对象出工厂即合法，没有 `MarkJustApplied()` 的非法中间态；与一代 `isSourceMonster` 同形（0.6 评审时定） |
| 保护判定条件 | [已定] 只看施加方：`source == Enemy` | 一代 `isSourceMonster` 的直译；不按"所有者已行动完"判定（那是推导现象，在"敌人给自己"一支会判错）；四种施加组合都与原版一致（游戏设计第 4 节、第 7 节第 2 条） |
| 叠加时保护 | [已定] 不传递，零改动 | `ApplyBuff` 丢弃新实例；每 1 层严格对应 1 段行动 |
| 减层与移除分两步 | [已定] 遍历只减层，`RemoveExpiredBuffs` 事后清 | 不在遍历中改字典 |
| 中毒 0 层 | [已定] 也在轮末移除 | 一处清理；中毒自身逻辑不改 |
| 中间基类 | [已定] `DurationBuff` | 两个子类共享保护与减层；`BuffState` 不加字段 |
