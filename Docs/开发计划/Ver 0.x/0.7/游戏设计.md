# 0.7 游戏设计：回合型 Buff

> **交付目标：给虚弱 / 易伤补上正确的时间语义——层数是剩余轮数，轮结束统一减 1，本轮刚施加的不减，减到 0 从列表移除。用蓝奴隶贩子（会给玩家上虚弱的敌人）当消费者：没有刚施加保护，它的耙就是废招；没有减层，痛击的 2 层易伤永远不掉。**
>
> 不做脆弱、不做新的回合型 Buff、不做敌人施加状态牌、不做随机行动。
>
> **本文只写游戏设计。技术设计与 TODO 在进入 0.7 之前再写**（见 [`../../README.md`](../../README.md) 第 2 节的细化深度规则），第 7 节先列出那时必须回答的技术问题与风险。

## 1. 设计原则

- **回合型 Buff 的层数是时间，不是强度。** 虚弱 / 易伤有就是固定倍率，层数只决定还能维持几轮；衰减发生在**轮结束**，不是中毒那种"结算时自减"。见 [`../../../Phase 2 扩展边界批注.md`](../../../Phase%202%20扩展边界批注.md) 第 4 节。
- **刚施加的不减。** 敌人在自己回合给玩家上的 Debuff，若本轮末就减 1，玩家一次都没感受到就消失了；原版用 `isSourceMonster` 标记让它跳过第一次减层。
- **0 层就消失。** 0.1 把减到 0 的 Buff 留在字典里、靠 `HasBuff` 用 `> 0` 兜住；本版本随轮末减层一起清理，界面与内部状态一致。
- 敌人给玩家上回合型 Debuff 是本版本才允许的敌人行为，0.6 的配置校验在这里放开。

## 2. 蓝奴隶贩子

| 项 | 值 |
| --- | --- |
| 生命 | 48 |
| 行动 1：刺击 | 对玩家造成 12 点攻击伤害 |
| 行动 2：耙 | 对玩家造成 7 点攻击伤害；对玩家施加 1 层虚弱 |
| 循环 | 刺击 → 耙 → 刺击 → … |

耙之后玩家带 1 层虚弱，下一回合玩家的攻击卡预览与实际都 ×0.75。它是一份 `EnemyData`，不需要新代码——0.6 已经把行动表接通，本版本只是放开"给玩家施加 Buff"的校验并配一份资产。意图显示 `攻击 7 · 减益`（0.6 已定的显示规则）。

## 3. 战斗流程更新

```text
玩家回合开始：清玩家格挡 → 玩家回合开始 Buff → 恢复能量 → 抽牌
  ↓
玩家出牌 / 结束回合
  ↓
敌人回合开始：清敌人格挡 → 敌人回合开始 Buff（中毒）→ 敌人死亡则胜利
  ↓
执行当前行动 → 玩家死亡则失败
  ↓
轮结束：双方回合型 Buff 减 1（本轮刚施加的不减）→ 0 层 Buff 移除 → 行动指针前进
  ↓
下一玩家回合
```

轮结束一步插在 0.6 的"行动指针前进"之前；中毒与力量流程不变。

## 4. 回合型 Buff 规则

适用：虚弱、易伤（0.7 时全部回合型 Buff）。中毒（结算时自减）、力量（永久）不受影响。

| 规则 | 内容 |
| --- | --- |
| 层数含义 | 还能维持几轮；效果强度与层数无关（0.75 / 1.5） |
| 减层时机 | 每轮结束（敌人行动完之后、下一玩家回合开始之前），双方身上的回合型 Buff 各 -1 |
| 刚施加保护 | 若该 Buff 是在**所有者本轮已经行动完之后**才施加的，本轮结束不减。当前实际只有一种情况：敌人在自己回合给玩家上的 Buff |
| 叠加 | 同 Id 加层；带保护的新施加让整条 Buff 本轮免减 |
| 归零 | 减到 0 层从所有者的 Buff 列表移除，界面不再显示；中毒减到 0 也在这一步移除 |

两个必须成立的例子：

- 玩家在自己回合打痛击给敌人 2 层易伤：本回合后续攻击 ×1.5 → 轮末减为 1 → 下一回合攻击仍 ×1.5 → 轮末归零消失。**2 层 = 覆盖本回合与下回合**，与原版痛击一致。
- 蓝奴隶贩子用耙给玩家 1 层虚弱：本轮末**不减**（刚施加保护）→ 玩家下一回合攻击 ×0.75 → 轮末归零消失。若没有保护，这 1 层会在玩家出牌前就消失，耙就成了废招。

## 5. 玩家可见

- 玩家 Buff 行显示 `虚弱 1`，下一轮末消失；敌人 Buff 行的 `易伤 2` 逐轮变 1、变无。
- 意图数字随双方 Buff 变化：玩家带虚弱时敌人意图不变（虚弱看攻击方），玩家攻击卡预览 ×0.75。
- Buff 行不再出现 0 层条目（0.3 的"0 层不显示"从过滤变成事实）。

## 6. 本阶段不包含

- 脆弱（格挡 ×0.75）、其它新的回合型 Buff。
- 敌人施加状态牌（黏液、伤口）。
- 玩家给**自己**上回合型 Debuff、敌人给**自己**上回合型 Debuff 的效果（原版个别卡有，本项目没有消费者）；见第 7 节第 2 条的边界。
- 随机行动、多敌人。

## 7. 技术要点与风险（写技术设计时必须回答）

1. **轮结束触发**：在敌人行动结算并判定失败之后、`StartPlayerTurn` 之前，对双方遍历回合型 Buff 减层，然后统一移除 0 层。遍历中只改 `Stacks`，移除放在遍历后，避免修改正在遍历的集合。中毒到 0 也在这一步移除。
2. **刚施加保护的实现**：推荐与一代一致——施加方是敌人、目标是玩家时构造带保护标记的 Buff（一代的 `isSourceMonster`），由 `ToAction` 在 `source == Enemy` 时传入。**适用边界**：这个捷径只覆盖"敌人在自己回合给玩家上回合型 Debuff"；玩家给敌人上的（痛击）不带保护、轮末正常减，是对的；但若以后出现"玩家给自己上虚弱"或"敌人给自己上易伤"的效果，`source` 判定会错，那时改成给 `CombatantState` 加"本轮已行动"标志。现在选前者，状态更少。
3. **回合型接口形状**：虚弱 / 易伤实现一个 `IRoundEndTrigger`（与 `IBuffTrigger` 同形），保护标记与减层逻辑放在这两个子类里（或一个共同的中间基类），`BuffState` 基类不加字段。
4. **0 层移除**：`CombatantState` 增加移除 Buff 的入口，只在轮结束步骤调用；`HasBuff` 仍用 `> 0`，负层力量（缴械）出现时再议。
5. **配置校验放开**：0.6 挡住的"给玩家施加虚弱 / 易伤"在本版本放开；其它未支持组合仍挡。
6. **测试重点**：刚施加保护的两个例子；痛击 2 层覆盖两轮；0 层移除；中毒不实现轮末减层；玩家自己带虚弱（测试构造）打攻击卡 ×0.75 且轮末正常减。
7. **风险**：轮结束步骤和 0.5 遗物开战钩子、0.1 回合开始触发是三个不同时机，不要合并成一个"事件"；每个时机仍是 `foreach` + 类型判断。

玩法规则对照 [`../../../详细游戏设计文档参考/Buff与Debuff.md`](../../../详细游戏设计文档参考/Buff与Debuff.md) 第 4 节与 [`../../../详细游戏设计文档参考/敌人意图与多敌人.md`](../../../详细游戏设计文档参考/敌人意图与多敌人.md)。
