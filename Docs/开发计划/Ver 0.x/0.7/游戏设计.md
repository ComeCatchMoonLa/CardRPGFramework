# 0.7 游戏设计：回合型 Buff

> **交付目标：给虚弱 / 易伤补上正确的时间语义——层数是剩余轮数，轮结束统一减 1，本轮刚施加的不减，减到 0 从列表移除。用蓝奴隶贩子（会给玩家上虚弱的敌人）当消费者：没有刚施加保护，它的耙就是废招；没有减层，痛击的 2 层易伤永远不掉。**
>
> 不做脆弱、不做新的回合型 Buff、不做敌人施加状态牌、不做随机行动。
>
> 技术设计与 TODO 随 0.6 的三件套一并写成草稿，0.6 完成后已对照实际实现复核转正（[`技术设计.md`](技术设计.md) / [`TODO.md`](TODO.md)）；本文第 7 节的问题在技术设计第 4、7 节逐条回答。数值出处：蓝奴隶贩子 46～50 血、刺击 12、耙 7 + 1 虚弱，取一代 wiki 基础难度值（[Slavers](https://slaythespire.wiki.gg/wiki/Slavers)），血量取区间中值。

## 1. 设计原则

- **回合型 Buff 的层数是时间，不是强度。** 虚弱 / 易伤有就是固定倍率，层数只决定还能维持几轮；衰减发生在**轮结束**，不是中毒那种"结算时自减"。见 [`../../../Phase 2 扩展边界批注.md`](../../../Phase%202%20扩展边界批注.md) 第 4 节。
- **刚施加的不减，规则只看施加方。** 敌人在自己回合给玩家上的 Debuff，若本轮末就减 1，玩家一次都没感受到就消失了；原版用 `isSourceMonster` 标记让**敌人施加的**回合型 Buff 跳过第一次减层。"所有者本轮已经行动完"只是这条规则在 1v1 里对"敌人 → 玩家"的直觉解释，不是规则本身（见第 4 节）。
- **0 层就消失。** 0.1 把减到 0 的 Buff 留在字典里、靠 `HasBuff` 用 `> 0` 兜住；本版本随轮末减层一起清理，界面与内部状态一致。
- 敌人给玩家上回合型 Debuff 是本版本才允许的敌人行为，0.6 的配置校验在这里放开。

## 2. 蓝奴隶贩子

| 项 | 值 |
| --- | --- |
| 生命 | 48 |
| 行动 1：刺击 | 对玩家造成 12 点攻击伤害 |
| 行动 2：耙 | 对玩家造成 7 点攻击伤害；对玩家施加 1 层虚弱 |
| 循环 | 刺击 → 耙 → 刺击 → …（原版是 60/40 随机、同一招不连用三次；本项目固定顺序） |

耙之后玩家带 1 层虚弱，下一回合玩家的攻击卡预览与实际都 ×0.75。它是一份 `EnemyData`，不需要新代码——0.6 已经把行动表接通，本版本只是删掉"敌人不能给玩家施加 Buff"那一条配置校验并配一份资产。意图显示 `攻击 7 · 减益`（0.6 已定的显示规则）；状态栏 `蓝奴隶贩子 HP 48/48`。

## 3. 战斗流程更新

```text
玩家回合开始：清玩家格挡 → 玩家回合开始 Buff → 恢复能量 → 抽牌
  ↓
玩家出牌 / 结束回合
  ↓
敌人回合开始：清敌人格挡 → 敌人回合开始 Buff（中毒）→ 敌人死亡则胜利
  ↓
执行当前行动 → 行动指针前进 → 玩家死亡则失败
  ↓
轮结束：双方回合型 Buff 减 1（本轮刚施加的不减）→ 0 层 Buff 移除
  ↓
下一玩家回合
```

轮结束一步插在 0.6 的"行动指针前进"之后、"下一玩家回合"之前，失败时不执行；中毒与力量流程不变。

## 4. 回合型 Buff 规则

适用：虚弱、易伤（0.7 时全部回合型 Buff）。中毒（结算时自减）、力量（永久）不受影响。

| 规则 | 内容 |
| --- | --- |
| 层数含义 | 还能维持几轮；效果强度与层数无关（0.75 / 1.5） |
| 减层时机 | 每轮结束（敌人行动完之后、下一玩家回合开始之前），双方身上的回合型 Buff 各 -1 |
| 刚施加保护 | **由施加方决定**：施加方是敌人的回合型 Buff 带保护，本轮结束不减（一代 `isSourceMonster`）；施加方是玩家的不带。不按"所有者是否已行动完"判定——那是推导出来的现象，只在"敌人 → 玩家"这一支成立；敌人给**自己**上的同样带保护（所有者还在行动中，但施加方是敌人），玩家下一回合才吃得到。当前唯一消费者是耙：敌人 → 玩家 |
| 叠加 | 同 Id 加层。保护只属于**新建**的那条 Buff（原版 `justApplied` 在构造时设置），叠到已有 Buff 上的层数不刷新保护——这样每 1 层严格对应所有者的 1 段行动 |
| 归零 | 减到 0 层从所有者的 Buff 列表移除，界面不再显示；中毒减到 0 也在这一步移除 |

三个必须成立的例子：

- 玩家在自己回合打痛击给敌人 2 层易伤：本回合后续攻击 ×1.5 → 轮末减为 1 → 下一回合攻击仍 ×1.5 → 轮末归零消失。**2 层 = 覆盖本回合与下回合**，与原版痛击一致。
- 蓝奴隶贩子用耙给玩家 1 层虚弱：本轮末**不减**（刚施加保护）→ 玩家下一回合攻击 ×0.75 → 轮末归零消失。若没有保护，这 1 层会在玩家出牌前就消失，耙就成了废招。
- 一只连续两回合用耙的敌人（测试构造）：第一次耙新建 1 层带保护，轮末不减；第二次耙叠到这条上变 2 层、不刷新保护，轮末减为 1；再下一轮末归零。玩家总共**两个**回合虚弱——两次施加各覆盖一回合。若叠加也刷新保护，会变成三个回合，多出的那一回合谁都没有施加过。

## 5. 玩家可见

- 玩家 Buff 行显示 `虚弱 1`，下一轮末消失；敌人 Buff 行的 `易伤 2` 逐轮变 1、变无。
- 意图数字随双方 Buff 变化：玩家带虚弱时敌人意图不变（虚弱看攻击方），玩家攻击卡预览 ×0.75。
- Buff 行不再出现 0 层条目：轮末统一移除。但回合开始自减到 0 的中毒要到本轮末才出字典，中间仍靠 `BattleView` 的 0 层过滤——过滤保留，不删。
- `TestScene` 的战斗配置可在颚虫 / 固定攻击敌人 / 蓝奴隶贩子之间切换。

## 6. 本阶段不包含

- 脆弱（格挡 ×0.75）、其它新的回合型 Buff。
- 敌人施加状态牌（黏液、伤口）。
- 玩家给**自己**上回合型 Debuff、敌人给**自己**上回合型 Debuff 的效果（原版个别卡有，本项目没有消费者）；判定规则对它们仍然正确，见第 7 节第 2 条。
- 随机行动、多敌人。

## 7. 技术要点与风险（技术设计第 4、7 节已逐条回答）

1. **轮结束触发**：在敌人行动结算、行动指针前进并判定未失败之后、`StartPlayerTurn` 之前，对双方遍历回合型 Buff 减层，然后统一移除 0 层。遍历中只改 `Stacks`，移除放在遍历后，避免修改正在遍历的集合。中毒到 0 也在这一步移除。
2. **刚施加保护的实现**：与一代一致——施加方是敌人时构造带保护标记的 Buff（一代的 `isSourceMonster`），由 `ToAction` 在 `source == Enemy` 时标记；判定只看施加方，不看目标是谁、也不看所有者本轮是否已行动。四种组合都与原版一致：敌人给玩家（耙）保护；玩家给敌人（痛击）不保护；玩家给自己（无消费者）不保护、只覆盖本回合；敌人给自己（无消费者）保护、玩家下一回合能吃到。参考文档 `Buff与Debuff.md` 第 4.3 节的"所有者已结束自己这一段"是玩家视角的直觉表述，在"敌人给自己"这一支与原版不等价，本项目以施加方为准。多敌人时敌人回合仍是一个阵营阶段，判定不变，不需要"本轮已行动"标志。
3. **回合型接口形状**：虚弱 / 易伤实现一个轮末触发接口（与 `IBuffTrigger` 同形），保护标记与减层逻辑放在两个子类共同的中间基类里，`BuffState` 基类不加字段；叠加时保护不传递（第 4 节）。
4. **0 层移除**：`CombatantState` 增加移除 0 层 Buff 的入口，只在轮结束步骤调用；`HasBuff` 仍用 `> 0`，负层力量（缴械）出现时再议。
5. **配置校验放开**：只删掉 0.6 `EnemyActionData.TryValidate` 里"ApplyBuff 且目标是 Opponent"那一条；`Draw` 与空 `effects` 仍挡——空行动只在 Core 层给测试用，配置层放开要等沉睡类敌人。
6. **测试重点**：第 4 节的三个例子；敌人给自己上易伤轮末不减（1v1 里痛击 / 耙分不出"施加方是敌人"与"目标是玩家"，这一例专门锁判定看施加方）；0 层移除；中毒不实现轮末减层但 0 层在轮末移除；玩家自己带虚弱（测试构造）打攻击卡 ×0.75 且轮末正常减；蓝奴隶贩子的循环、意图 `攻击 7 · 减益`、耙后玩家攻击预览 4。
7. **风险**：轮结束步骤和 0.5 遗物开战钩子、0.1 回合开始触发是三个不同时机，不要合并成一个"事件"；每个时机仍是 `foreach` + 类型判断。

减层时点对照 [`../../../详细游戏设计文档参考/Buff与Debuff.md`](../../../详细游戏设计文档参考/Buff与Debuff.md) 第 4.3 节与 [`../../../详细游戏设计文档参考/回合时序与能量.md`](../../../详细游戏设计文档参考/回合时序与能量.md) 第 2.7 节；**刚施加保护的判定以本文第 4 节为准**（§4.3 的"所有者已结束自己这一段"是玩家视角对照表，不是本仓库规格）。技术实现见 [`技术设计.md`](技术设计.md)，执行顺序见 [`TODO.md`](TODO.md)。
