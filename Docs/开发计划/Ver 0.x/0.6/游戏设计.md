# 0.6 游戏设计：敌人行动表

> **交付目标：敌人从"一个固定伤害数字"变成配置化的行动表——每个行动是一组效果，与卡牌共用 0.2 的效果原语，按固定顺序循环；意图从当前行动推导、数字是公式后的。做一只原版怪（颚虫）证明"敌人 = 数据"，并把 0.1 的固定攻击敌人迁成第二份配置。玩家最大生命同步改为原版的 80。**
>
> 不做随机行动选择、多敌人、按血线切换模式、Boss、敌人施加状态牌、脆弱。**不做会给玩家上虚弱 / 易伤的敌人**——回合型 Buff 的轮末减层与刚施加保护是 0.7 的内容，没有减层就让敌人上虚弱，那层虚弱会永远挂着；蓝奴隶贩子因此放在 0.7。
>
> 技术实现见 [`技术设计.md`](技术设计.md)，执行顺序见 [`TODO.md`](TODO.md)。数值出处：颚虫 40～44 血、咬 11、猛击 7 + 5 格挡、咆哮 3 力量 + 6 格挡，均取一代 wiki 的基础难度值（[Jaw Worm](https://slaythespire.wiki.gg/wiki/Jaw_Worm)），血量取区间中值。

## 1. 设计原则

- **敌人行动与卡牌是同一种东西。** 一个行动就是一组效果（对玩家造成攻击伤害、给自己格挡、给自己上力量……），用 0.2 的效果列表表达，"自身"是敌人、"对手"是玩家。新敌人 = 配一份数据，不写代码；不给敌人发明第二套效果描述。
- **固定循环，确定性。** 原版是带约束的随机（颚虫"不能连续两次咬"）；本项目按行动表顺序循环，便于测试和复现。随机（用战斗种子）留给以后。
- **意图先于行动。** 玩家回合内始终能看到敌人下一步做什么；行动一执行完就决定下一个意图（原版"怪物角色行动结束时立刻决定并展示"）。攻击数字是公式之后的（含敌人的力量与虚弱、玩家的易伤），与 0.3 的预览走同一个入口；多段攻击每段独立取整后求和，与双击一致。
- **意图文案由效果推导，不单独配置。** 行动表里没有"意图种类"字段，也没有文案字段：含攻击就显示攻击数字，含格挡就显示防御……一份效果列表既是结算依据也是显示依据，不会出现"配的是 7 点、显示的是 8 点"。

## 2. 敌人

数值取原版（一代 wiki 基础难度），血量取区间中值。玩家最大生命同步改为原版铁甲战士的 **80**（0.1 的 40 是配 6 点固定攻击的临时值；颚虫咆哮后一口 14，40 血两回合就见底；1.0 三连战也必须用 80）。**80 改的是 `Default.asset` 与 `BattleConfig.playerMaxHp` 字段的默认值两处**——EditMode 测试里的玩家 40 血是测试自己的常量，所有 HP 断言都是相对它写的，不跟资产走。

### 2.1 颚虫

| 项 | 值 |
| --- | --- |
| 生命 | 42 |
| 行动 1：咬 | 对玩家造成 11 点攻击伤害 |
| 行动 2：猛击 | 对玩家造成 7 点攻击伤害；自身获得 5 点格挡 |
| 行动 3：咆哮 | 自身获得 3 层力量；自身获得 6 点格挡 |
| 循环 | 咬 → 猛击 → 咆哮 → 咬 → …（原版首回合固定咬，之后随机；本项目全程固定顺序） |

- 咆哮之后的咬是 `11 + 3 = 14`，意图上直接显示 14；力量是永久的，第二圈的猛击是 `攻击 10 · 防御`。玩家给敌人上虚弱后咬是 `floor(11 × 0.75) = 8`；**`Default.asset` 默认带纸鹤**，Play 里看到的是 `floor(11 × 0.6) = 6`——8 是无遗物配置（测试）的数字，两者都对，不要为了对齐数字删默认遗物。
- 猛击 / 咆哮给的格挡在**敌人自己的下一回合开始**才清，所以顶着玩家整个下一回合：玩家一张 6 点攻击打在 5 格挡上只掉 1 血。
- 颚虫身上只有力量（永久）和格挡，不涉及回合型 Buff。咆哮的力量走和玩家打出力量强化同一条"施加 Buff"路径——玩家持蛇颅骨对它没有影响（0.5 的钩子看施加方，敌人没有遗物）。

### 2.2 固定攻击敌人（迁移自 0.1）

0.1 的默认敌人（36 血、每回合固定攻击 6）迁成一份 `EnemyData`：单一行动"对玩家造成 6 点攻击伤害"循环。它有两个用途：

- `TestScene` 里和颚虫二选一（换战斗配置里的敌人引用），证明"换敌人 = 换一份配置引用"。
- 0.1～0.5 的既有测试改构造方式时，用"单一行动、伤害 N"的敌人定义替换原来的 `enemyDamage: N` 参数，断言不动。测试里 `enemyDamage: 0` 的"无害敌人"对应一条**没有任何效果的行动**（见 2.3 的 `待机`）。

### 2.3 意图显示

从当前行动的效果列表推导，不单独配置文案：

| 效果 | 显示 |
| --- | --- |
| 含"对玩家造成攻击伤害" | `攻击 N`，N 为公式后数值；多段攻击为各段之和（每段独立取整，与双击一致），只显示一项 |
| 含"自身获得格挡" | `防御` |
| 含"给自身施加 Buff"或"自身恢复生命" | `增益`（原版把敌人的治疗也画成增益意图；0.6 没有会治疗的敌人，规则先定下） |
| 含"给玩家施加 Buff" | `减益`（0.6 的配置校验不允许这样的敌人，0.7 放开；显示规则先定下） |
| 没有任何效果 | `待机`（这条行动正常执行，只是没有效果；测试用的无害敌人、将来的沉睡意图都是它。**眩晕不是空行动**：眩晕是"行动存在、执行前被规则作废"，见第 5 节） |
| 多项 | 按效果首次出现的顺序拼接、同类只出现一次，用 ` · ` 连接 |

颚虫三个行动的意图分别是：`攻击 11`（咆哮后 `攻击 14`）、`攻击 7 · 防御`、`增益 · 防御`。敌人状态栏同时显示敌人名字：`颚虫 HP 42/42  格挡 0`。

## 3. 战斗流程更新

```text
进入战斗：构造双方状态（敌人生命来自敌人配置）、牌堆、遗物栏；行动指针指向行动 1
  ↓
开战遗物钩子 → 玩家回合开始：清玩家格挡 → 玩家回合开始 Buff → 恢复能量 → 抽牌；界面显示当前行动的意图
  ↓
玩家出牌 / 结束回合
  ↓
敌人回合开始：清敌人格挡 → 敌人回合开始 Buff（中毒）→ 敌人死亡则胜利（不执行行动）
  ↓
执行当前行动（效果列表按顺序结算）→ 行动指针前进（末尾回绕）→ 玩家死亡则失败
  ↓
下一玩家回合
```

- 敌人格挡与玩家一样在**自己的回合开始**清除，并且在中毒结算之前——与玩家侧"清格挡 → 回合开始 Buff"的顺序一致。
- 中毒与力量流程不变。0.7 会在"行动指针前进"之后、"下一玩家回合"之前插入轮结束的回合型 Buff 减层。
- 敌人回合仍是瞬时的：一个行动的多段效果一次结算完，玩家在第 2 段死亡时第 3 段仍会结算（对 0 血没有额外效果），胜负在整段行动之后统一判定。

## 4. 玩家可见

- 敌人状态栏显示名字、生命与格挡：`颚虫 HP 42/42  格挡 5`；玩家攻击先扣格挡。
- 敌人 Buff 行显示力量（颚虫咆哮后 `力量 3`）。
- 意图每回合变化，数字随双方 Buff 变化：咆哮后咬显示 14、第二圈猛击显示 10；玩家给敌人上虚弱后咬显示 8（默认配置带纸鹤时 6）；玩家自己带易伤（测试构造）时敌人攻击 ×1.5。
- `TestScene` 可通过更换战斗配置里的敌人引用在颚虫与固定攻击敌人之间切换，不改代码、不改场景。

## 5. 本阶段不包含

- 原版的带约束随机行动（"不能连续两次咬"）；血线 / 回合数切换模式；Boss 阶段。
- 多敌人、目标选择、全体效果。
- 会给玩家施加虚弱 / 易伤的敌人（蓝奴隶贩子，0.7）；回合型 Buff 的减层与刚施加保护（0.7）。
- 敌人施加状态牌（黏液、伤口）、脆弱、其它新 Buff；敌人自己抽牌（敌人没有牌堆，配置校验直接拒绝）。
- 眩晕（展示的意图在执行前被作废）、隐藏意图（符文圆顶）。
- 敌人意图的图标美术；敌人立绘。
- 敌人图鉴数量：一只原版怪 + 一份迁移配置够证明"敌人 = 数据"，第三只不加分。

## 6. 验收标准

- 新增一只敌人只需新增一份敌人配置资产并在战斗配置里引用，不改任何 C# 代码；`BattleSession` 里没有任何敌人 Id 或按敌人分支。
- 颚虫按 咬 → 猛击 → 咆哮 循环并回绕；意图依次显示 `攻击 11` → `攻击 7 · 防御` → `增益 · 防御` → `攻击 14` → `攻击 10 · 防御`（力量永久，第二圈猛击跟着涨）；咆哮后咬的意图与实际掉血均为 14；猛击后敌人有 5 格挡、顶住玩家下一回合的攻击，并在敌人下一回合开始时清除（咆哮之后是 6，不是 11）。
- 玩家给颚虫上虚弱后，咬的意图与实际掉血：无遗物配置（测试）8；`Default.asset` 默认带纸鹤，Play 里是 6。两个数字都要成立，不删默认遗物去对齐。
- 固定攻击敌人的行为与 0.1 / 0.5 完全一致：每回合掉 6 血；虚弱时无遗物 4、默认配置带纸鹤 3。
- 意图显示的攻击数字与实际掉血一致（含多段：两段 3 点对易伤玩家是 4 + 4 = 8，不是 9）。
- 中毒结算与层数变化与 0.1 完全一致；敌人被毒死时不执行行动。
- 配置里出现敌人抽牌、敌人给玩家施加 Buff、敌人引用为空、敌人 Id / 名字为空、生命 ≤ 0 时，启动期在 Console 报错，战斗不初始化（与卡牌 / 遗物配置错误相同）。
- 0.1～0.5 的既有测试只改 `CreateSession` 辅助方法的内部实现，用例正文不改；**唯一例外**是 0.1 的 `PoisonedEnemy_LosesHpIgnoringBlockAtEnemyTurnStart_AndStackDecrements`——它断言敌人回合开始后敌人格挡仍是 10，那是"0.1 敌人从不清格挡"这一缺失功能的副产物而不是规则，本版本敌人回合开始清格挡后该断言改为 0（见技术设计第 5 节）。全部 EditMode 测试通过；Console 无错误。
