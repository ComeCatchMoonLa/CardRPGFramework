# 0.6 游戏设计：敌人行动表

> **交付目标：敌人从"一个固定伤害数字"变成配置化的行动表——每个行动是"意图 + 效果列表"，与卡牌共用 0.2 的效果原语，按固定顺序循环。做一只原版怪（颚虫）证明"敌人 = 数据"，并把 0.1 的固定攻击敌人迁成第二份配置。玩家最大生命同步改为原版的 80。**
>
> 不做随机行动选择、多敌人、按血线切换模式、Boss、敌人施加状态牌、脆弱。**不做会给玩家上虚弱 / 易伤的敌人**——回合型 Buff 的轮末减层与刚施加保护是 0.7 的内容，没有减层就让敌人上虚弱，那层虚弱会永远挂着；蓝奴隶贩子因此放在 0.7。
>
> **本文只写游戏设计。技术设计与 TODO 在进入 0.6 之前再写**（见 [`../../README.md`](../../README.md) 第 2 节的细化深度规则），第 7 节先列出那时必须回答的技术问题与风险。

## 1. 设计原则

- **敌人行动与卡牌是同一种东西。** 一个行动就是一组效果（对玩家造成攻击伤害、给自己格挡、给自己上力量……），用 0.2 的效果列表表达，"自身"是敌人、"对手"是玩家。新敌人 = 配一份数据，不写代码。
- **固定循环，确定性。** 原版是带约束的随机；本项目按行动表顺序循环，便于测试和复现。随机（用战斗种子）留给以后。
- **意图先于行动。** 玩家回合内始终能看到敌人下一步做什么，攻击数字是公式之后的（含敌人的力量、玩家的易伤），与 0.3 的预览走同一个入口。

## 2. 敌人

数值取原版（一代 wiki），血量取区间中值。玩家最大生命同步改为原版铁甲战士的 **80**（0.1 的 40 是配 6 点固定攻击的临时值；1.0 三连战必须用 80）。

### 2.1 颚虫

| 项 | 值 |
| --- | --- |
| 生命 | 42 |
| 行动 1：咬 | 对玩家造成 11 点攻击伤害 |
| 行动 2：猛击 | 对玩家造成 7 点攻击伤害；自身获得 5 点格挡 |
| 行动 3：咆哮 | 自身获得 3 层力量；自身获得 6 点格挡 |
| 循环 | 咬 → 猛击 → 咆哮 → 咬 → …（原版首回合固定咬，之后随机；本项目全程固定顺序） |

咆哮之后的咬是 `11 + 3 = 14`，意图上直接显示 14。颚虫身上只有力量（永久）和格挡，不涉及回合型 Buff。

### 2.2 固定攻击敌人（迁移自 0.1）

0.1 的默认敌人（每回合固定攻击 6）迁成一份 `EnemyData`：单一行动"对玩家造成 6 点攻击伤害"循环。它有两个用途：

- `TestScene` 里和颚虫二选一，证明"换敌人 = 换一份配置引用"。
- 0.1～0.5 的既有测试改构造方式时，用"单一行动、伤害 N"的敌人定义替换原来的 `enemyDamage: N` 参数，断言不动。

### 2.3 意图显示

从行动的效果列表推导，不单独配置文案：

| 效果 | 显示 |
| --- | --- |
| 含"对玩家造成攻击伤害" | `攻击 N`，N 为公式后数值；多段攻击为各段之和（每段独立取整，与双击一致） |
| 含"自身获得格挡" | `防御` |
| 含"给自身施加 Buff" | `增益` |
| 含"给玩家施加 Buff" | `减益`（0.6 没有这样的敌人，显示规则先定下） |
| 多项 | 按效果顺序拼接，如 `攻击 7 · 防御` |

## 3. 战斗流程更新

```text
玩家回合开始：清玩家格挡 → 玩家回合开始 Buff → 恢复能量 → 抽牌；界面显示敌人当前行动的意图
  ↓
玩家出牌 / 结束回合
  ↓
敌人回合开始：清敌人格挡 → 敌人回合开始 Buff（中毒）→ 敌人死亡则胜利
  ↓
执行当前行动（效果列表按顺序结算）→ 玩家死亡则失败
  ↓
行动指针前进（末尾回绕）
  ↓
下一玩家回合
```

- 敌人格挡与玩家一样在**自己的回合开始**清除，所以猛击 / 咆哮给的格挡会顶着玩家整个下一回合。
- 中毒与力量流程不变。0.7 会在"行动指针前进"之前插入轮结束的回合型 Buff 减层。

## 4. 玩家可见

- 敌人 Buff 行显示力量（颚虫咆哮后 `力量 3`）。
- 意图每回合变化，数字随双方 Buff 变化（咆哮后咬显示 14；玩家给敌人上虚弱后咬显示 `floor(11 × 0.75) = 8`）。
- 敌人有格挡时状态栏显示格挡值，玩家攻击先扣格挡。
- `TestScene` 可通过更换战斗配置里的敌人引用在颚虫与固定攻击敌人之间切换。

## 5. 本阶段不包含

- 原版的带约束随机行动（"不能连续两次咬"）；血线 / 回合数切换模式；Boss 阶段。
- 多敌人、目标选择、全体效果。
- 会给玩家施加虚弱 / 易伤的敌人（蓝奴隶贩子，0.7）；回合型 Buff 的减层与刚施加保护（0.7）。
- 敌人施加状态牌（黏液、伤口）、脆弱、其它新 Buff。
- 敌人意图的图标美术；敌人立绘。
- 敌人图鉴数量：一只原版怪 + 一份迁移配置够证明"敌人 = 数据"，第三只不加分。

## 6. 验收标准

- 新增一只敌人只需新增一份敌人配置资产，不改任何 C# 代码。
- 颚虫按 咬 → 猛击 → 咆哮 循环；咆哮后咬的意图与实际掉血均为 14；猛击后敌人有 5 格挡且在敌人下一回合开始时清除。
- 固定攻击敌人的行为与 0.1 完全一致：每回合掉 6 血，虚弱时 4。
- 意图显示的攻击数字与实际掉血一致（含多段）。
- 中毒结算与层数变化与 0.1 完全一致。
- 0.1～0.5 的既有测试除改构造方式（敌人参数）外不改断言即可通过；全部 EditMode 测试通过；Console 无错误。

## 7. 技术要点与风险（写技术设计时必须回答）

1. **敌人定义与配置**：`Core.Enemies.EnemyDefinition`（Id、显示名、最大生命、行动列表）与 `Data.EnemyData` SO；`BattleSetup` 去掉 `EnemyMaxHp` / `EnemyDamage`，`BattleConfig` 改为引用 `EnemyData`。`BattleSession.EnemyDamage` 与 `BattleController.EnemyDamage` 被 View 和测试引用，需要替换成"当前行动"与意图预览。
2. **行动复用效果原语**：`ToAction(effect, source: Enemy)` 直接复用 0.2 的转换；`Opponent(Enemy)` 为玩家；`Draw` 对敌人无意义，配置校验里禁止。
3. **意图预览**：0.3 的 `PreviewEnemyAttack()` 改为遍历当前行动里的 Damage 条目逐段预览求和；意图文案由效果列表推导（决定在 Core 给出结构化的意图种类，还是 View 直接读效果列表拼接）。
4. **敌人清格挡位置**：敌人回合开始、中毒结算之前。
5. **玩家 40 → 80**：改 `Default.asset` 与依赖 40 的测试常量（多为 `CreateSession(playerMaxHp: …)` 显式传参，影响面小）。
6. **测试重点**：行动指针循环与越界回绕；意图预览 = 实际掉血；咆哮后咬 14；固定攻击敌人回归；0.1 的 `enemyDamage: 0` 之类的辅助构造改成"单一行动、伤害 0"的敌人定义。
7. **风险**：`EnemyTurn` 仍是瞬时阶段，多段行动一次 `RunAll` 结算完；有动画需求时再拆。行动表若出现"抽牌"或"对自己造成伤害"等无意义 / 未支持组合，靠配置校验挡住而不是运行时兜底。配置校验还应挡住"给玩家施加虚弱 / 易伤"，直到 0.7 放开。

玩法规则对照 [`../../../详细游戏设计文档参考/敌人意图与多敌人.md`](../../../详细游戏设计文档参考/敌人意图与多敌人.md)。
