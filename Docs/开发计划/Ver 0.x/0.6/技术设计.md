# 0.6 技术设计：敌人行动表

> 本文在 0.5 完成后对照 0.1～0.5 的实际实现写成：`ToAction(effect, source)` 已按 `source` 取对手（0.2 就为敌人行动留的口子）、`BattleSetup` 的注释限定它只装标量、`PreviewEnemyAttack()` 是 `DamageCalculator` 的一行包装、`CardDescriptionFormatter` 只认 `CardDefinition` + 一个委托、Data 层 SO 校验不写单测、`CreateSession` 用可选参数吸收构造变化。唯一一处待确认（意图文案在哪一层拼，第 4.3 / 7 节）已在评审后定为 View 侧 `IntentFormatter`，本文已冻结、可按 TODO 开工。
>
> **技术目标：新增 `Core.Enemies`（`EnemyDefinition` / `EnemyAction`），敌人行动复用 `EffectSpec` 与 `BattleSession.ToAction`——`ToAction` 一行不改，第二个调用方只是 `source: Enemy`。`BattleSession` 持有一个行动下标按表循环，敌人回合开始清敌人格挡；`PreviewEnemyAttack()` 签名不变、改为逐段预览求和；意图文案由 View 从效果列表推导。`BattleSetup` 去掉两个敌人标量，敌人定义整体作为构造参数传入。**

## 1. 技术原则

延续 0.1～0.5 的优先级：**正确性 > 可测试性 > 可读性 > 当前已知需求的扩展性**。补充：

- **敌人行动 = 效果列表，与卡牌同一种原语。** `EffectKind` 仍是封闭枚举，本版本不加值：颚虫三招用 `Damage` / `Block` / `ApplyBuff(Self)` 就够。不给敌人另做一套"意图种类 + 参数"的描述。
- **`ToAction` 一行不改。** `Opponent(source)` 已经按 `source` 取对手；`EnemyAction` 在构造时拒绝 `Draw`（敌人没有牌堆，`DrawCardsAction` 抽的是玩家的牌），所以 `ToAction` 不需要"source 是敌人"的分支。
- **Session 不认具体敌人。** `BattleSession` 里允许出现的敌人相关符号只有 `EnemyDefinition` / `EnemyAction`；不出现敌人 Id、不按敌人或行动种类分支。新敌人 = 一份 `EnemyData`，零 C#。
- **预览与结算配对。** `PreviewEnemyAttack()` 遍历的是 `CurrentEnemyAction.Effects` 里的 `Damage` 段，与 `TryEndPlayerTurn` 用同一份列表入队的 `DamageAction(Enemy, Player, effect.Value)` 一一对应；每段独立取整后求和（与双击一致），不是先求和再乘。
- **意图文案不进 Core。** 与 `CardDescriptionFormatter` 同理：View 侧纯函数读效果列表 + Core 给的预览数字拼文案；Core 不新增 `IntentKind` 枚举（4.3 已定）。
- **固定循环、确定性。** 不引入第二个随机源；`Random` 仍只给牌堆。
- **数值只在资产里。** 11 / 7 / 5 / 3 / 6 / 42 / 80 只出现在 `Assets/Data`；测试用自己构造的 `EnemyDefinition`，玩家血量保留测试常量 40。

## 2. 分层与依赖

```text
Views（BattleView：敌人名、意图行；IntentFormatter：EnemyAction + 预览数字 → 文案）
  ↓ 只读
Controllers（BattleController：构造 Session 时传敌人；EnemyDisplayName / CurrentEnemyAction / PreviewEnemyAttack）
  ↓
Core.Battle（BattleSession：构造接收 EnemyDefinition；行动下标；EnemyTurn 清格挡 → 中毒 → 按当前行动入队 → 推进；PreviewEnemyAttack 求和）
  ↓
Core.Enemies（新：EnemyDefinition / EnemyAction）
Core.Cards（EffectSpec / EffectKind / EffectTarget：不改）
Core.Actions / Effects / Buffs / Rules / Relics（不改）
Core.Combatants（不改：ClearBlock 已有，只是敌人也开始调用）
```

依赖说明：

- `Core.Enemies` 只引用 `Core.Cards`（`EffectSpec` / `EffectKind`），不引用 `UnityEngine`、不引用 `Core.Actions`——和 `Core.Cards` 一样只描述、不执行。
- `Core.Battle` 引用 `Core.Enemies`；`Data` 引用 `Core.Enemies`（`EnemyData.ToDefinition`）；`Views` 引用 `Core.Enemies`（`IntentFormatter` 读 `EnemyAction.Effects`），与今天 `Views` 读 `CardDefinition` / `EffectSpec` 是同一种只读关系。
- `Core.Rules` / `DamageCalculator` 不改：敌人力量、敌人虚弱、玩家易伤都已由三条 Rule 按 `Source` / `Target` 处理，颚虫的 14 和 8 不需要新规则。

## 4. 核心接口

### 4.1 Core.Enemies

```csharp
namespace CardRPGFramework.Core.Enemies
{
    /// 一条行动 = 效果列表。意图文案由效果推导，所以这里没有名字、没有意图种类字段。
    /// 允许空列表——"待机"，这条行动正常执行、只是没有效果：测试里的无害敌人（0.1 的 enemyDamage: 0）与将来的沉睡意图都是它。
    /// 眩晕不是空行动：眩晕是"行动存在、执行前被规则作废"，属于 Session 流程层（第 9 节），不用空表表示。
    public sealed class EnemyAction
    {
        public IReadOnlyList<EffectSpec> Effects { get; }

        // effects 为 null 抛 ArgumentNullException；含 Draw 抛 ArgumentException（敌人没有牌堆，Draw 会抽玩家的牌）；
        // 某条 Value <= 0 抛 ArgumentException（拦 default(EffectSpec)，与 CardDefinition 同一道检查）；构造时拷贝。
        public EnemyAction(IReadOnlyList<EffectSpec> effects);
    }

    /// 与 CardDefinition 同形：不可变纯 C# 内容数据，由 Data 层的 EnemyData 转换生成，Core 不保留 ScriptableObject 引用。
    public sealed class EnemyDefinition
    {
        public string Id { get; }
        public string DisplayName { get; }
        public int MaxHp { get; }

        /// 至少一条、无 null 元素；构造时拷贝列表，元素引用不变（测试用 Assert.AreSame 认当前行动）。
        public IReadOnlyList<EnemyAction> Actions { get; }

        // id / displayName 空抛 ArgumentException；maxHp <= 0 抛 ArgumentOutOfRangeException；actions 空抛 ArgumentException。
        public EnemyDefinition(string id, string displayName, int maxHp, IReadOnlyList<EnemyAction> actions);
    }
}
```

- **没有 `EnemyIds`、没有 `EnemyFactory`。** Buff 与遗物有工厂是因为它们各自是一个 C# 子类、要按 Id 实例化；敌人是纯数据，没有任何代码引用某一只具体敌人。`Id` 保留是为了"配置经稳定 Id 转换为运行时定义"的地基约定与 1.0 节点 / 存档引用，0.6 只在校验里用（非空）。
- **`Draw` 在 Core 拒绝、"给玩家施加 Buff"在 Data 拒绝**（4.4）：前者在任何版本都无意义，是规则真相；后者是 0.6 的范围限制，0.7 删一行即放开，Core 不留痕。
- **空行动 Core 与 Data 都允许。** 一只敌人至少一条行动，但一条行动可以没有效果。Data 层不额外禁止：Inspector 里空列表一眼可见，"漏填"的风险小于"Core 允许、Data 禁止"两套规则的维护成本。

### 4.2 BattleSetup 与 BattleSession

```csharp
/// 只剩玩家侧标量；敌人由 EnemyDefinition 整体描述，和牌组、遗物一样是单独的构造参数。
public readonly struct BattleSetup
{
    public int PlayerMaxHp { get; }
    public int EnergyPerTurn { get; }
    public int HandSize { get; }

    public BattleSetup(int playerMaxHp, int energyPerTurn, int handSize);
}

public sealed class BattleSession
{
    private int _enemyActionIndex;

    public EnemyDefinition EnemyDefinition { get; }
    public EnemyAction CurrentEnemyAction => EnemyDefinition.Actions[_enemyActionIndex];
    // public int EnemyDamage —— 删除；Controller 的同名转发一并删除

    public BattleSession(BattleSetup setup, EnemyDefinition enemy, IEnumerable<CardDefinition> deck, Random random,
                         IEnumerable<RelicState> relics = null)
    {
        Player = new CombatantState(setup.PlayerMaxHp);
        Enemy = new CombatantState(enemy.MaxHp);
        EnemyDefinition = enemy;
        // ...其余与 0.5 相同
    }

    public bool TryEndPlayerTurn()
    {
        if (Phase != BattlePhase.PlayerTurn) return false;

        _cardPile.DiscardHand();
        Phase = BattlePhase.EnemyTurn;

        // 新增：敌人自己的回合开始清格挡，与 StartPlayerTurn 对称，放在中毒之前（回合时序 2.6 第 1 步）。
        Enemy.ClearBlock();
        TriggerTurnStartBuffs(Enemy);
        if (Enemy.IsDead)
        {
            Phase = BattlePhase.Victory;   // 毒死就不出手，行动指针也不推进
            return true;
        }

        // ToAction 的第二个调用方：同一份效果列表既是结算依据也是预览依据。
        foreach (var effect in CurrentEnemyAction.Effects)
        {
            _actionQueue.Enqueue(ToAction(effect, Enemy));
        }

        _actionQueue.RunAll(new ActionContext(_actionQueue));
        AdvanceEnemyAction();   // 行动结束立刻决定下一意图（回合时序 2.6 第 5 步）；失败时它无意义，顺序不重要

        if (Player.IsDead) Phase = BattlePhase.Defeat; else StartPlayerTurn();
        return true;
    }

    /// 当前行动里每个 Damage 段各自过 DamageCalculator 后求和（每段独立取整，与双击一致）；没有攻击段返回 0。
    /// (effect.Value, Enemy, Player) 的配对必须与 TryEndPlayerTurn 里 ToAction(effect, Enemy) 产生的 DamageAction 相同。
    public int PreviewEnemyAttack()
    {
        var total = 0;
        foreach (var effect in CurrentEnemyAction.Effects)
        {
            if (effect.Kind == EffectKind.Damage)
            {
                total += DamageCalculator.CalculateFinalDamage(new DamageContext(effect.Value, Enemy, Player));
            }
        }

        return total;
    }

    private void AdvanceEnemyAction() => _enemyActionIndex = (_enemyActionIndex + 1) % EnemyDefinition.Actions.Count;
}
```

- **敌人定义是单独的构造参数，不塞进 `BattleSetup`。** `BattleSetup` 的注释就写着"标量战斗参数（不含牌组）"，牌组、遗物都是单独参数；`EnemyDefinition` 是结构化内容，和它们同类。构造函数到 5 个参数（第 5 个可选），不引入参数对象。1.0 的 `RunState` 进战斗时也是 `BattleSetup` + 节点的 `EnemyDefinition` + 牌组 + 遗物，形状不变。
- **行动指针是 Session 的一个私有 `int`。** 1v1、固定循环，不需要 `EnemyState` / AI 对象；出现第二种行动模式（概率、不能连用）时再抽 `IEnemyPattern`，见第 9 节。
- **敌人清格挡放在中毒之前。** 与玩家侧 `ClearBlock → TriggerTurnStartBuffs` 顺序一致。代价：0.1 有一项用例在敌人回合前给敌人 10 格挡、断言敌人回合后仍是 10——那是"0.1 敌人从不清格挡"的副产物，见第 5 节。
- **多段一次 `RunAll`，胜负在整段之后判定。** 玩家在第 2 段死亡时第 3 段仍结算，`TakeDamage` 对 0 血无副作用；有动画需求时再拆。`EnemyTurn` 仍是瞬时阶段。
- **敌人施加 Buff 走 `ApplyBuffAction(Enemy, Enemy, ...)`。** 0.5 的施加钩子遍历**施加方**遗物，敌人没有遗物，玩家的蛇颅骨对颚虫的咆哮自然无效——不需要新判断，但要有用例锁住。

### 4.3 意图预览与文案

```csharp
namespace CardRPGFramework.Views
{
    /// 效果列表 → 意图文案。攻击段合并成一项"攻击 N"（N 是 Core 预览好的总和，这里不算公式），
    /// 其余按效果首次出现的顺序去重：Block → 防御，ApplyBuff(Self) / Heal → 增益，ApplyBuff(Opponent) → 减益；
    /// 用 " · " 连接；空行动 → 待机。与 CardDescriptionFormatter 同理：只认 Core 值类型与一个数字，不依赖 Controller。
    public static class IntentFormatter
    {
        public static string Format(EnemyAction action, int previewedAttackDamage);
    }
}
```

**[已定] 意图文案在 View 侧拼：`IntentFormatter.Format(EnemyAction, int)` 直接读效果列表 + Core 的预览数字，Core 不新增任何意图类型 / 枚举。**（评审后拍板；注意"Core 输出 `EnemyIntent { Type, Value }`、View 只做种类→文字"是下面的备选而不是本方案。）

- 选 View 侧 `IntentFormatter` 的理由：Core 里没有任何消费者读"意图种类"——`BattleSession` 不按意图分支，结算只看效果列表；加一个 `IntentKind` 枚举 + 转换方法就是第二份"效果 → 意图"的真相，且它只服务显示。`CardDescriptionFormatter` 已经走的是这条路（效果列表 + 预览委托 → 文案），意图与卡面是同一类东西。以后换图标是 View 把文字换成图，仍不需要 Core 参与；眩晕 / 隐藏意图改的是"当前行动是否执行 / 是否可见"，也不需要 Core 里的意图枚举。
- 否决的备选 Core 结构化（`EnemyAction.IntentKinds`、`BattleSession.PreviewEnemyIntent()` 返回种类列表，或 `EnemyIntent { Type, Value }`）：View 更薄，但 Core 多一个只为显示存在的类型；出现第二个显示消费者（1.0 地图页预览敌人？没有这种需求）之前不值。

`PreviewEnemyAttack()` 留在 Core、签名不变：数字是公式的事，0.3 / 0.5 现有的 `PreviewEnemyAttack() == 4 / 3` 用例经迁移后的固定攻击敌人不改断言。

### 4.4 Data 层

```csharp
/// 一条行动的 Inspector 条目。struct + 测试构造函数，与 EffectSpecData 同做法，所以 TryValidate 能写单测。
[Serializable]
public struct EnemyActionData
{
    [SerializeField] private string name;                  // 只给 Inspector 列表标签与报错定位（Unity 用第一个 string 字段当元素标题）；不进 Core
    [SerializeField] private List<EffectSpecData> effects;

    public EnemyActionData(string name, List<EffectSpecData> effects);   // 供 EditMode 测试直接构造

    public EnemyAction ToAction();      // 逐条 ToSpec 后 new EnemyAction；effects 为 null 视为空行动

    /// effects 允许为空（待机）；非空时逐条 EffectSpecData.TryValidate；
    /// kind == Draw → 错（敌人没有牌堆）；
    /// kind == ApplyBuff && target == Opponent → 错（0.6：回合型 Buff 没有减层，敌人给玩家上的虚弱会永远挂着；0.7 删掉这一条放开）。
    public bool TryValidate(out string error);
}

[CreateAssetMenu(fileName = "EnemyData", menuName = "CardRPG/Enemy Data")]
public sealed class EnemyData : ScriptableObject
{
    [SerializeField] private string id;
    [SerializeField] private string displayName;
    [SerializeField] private int maxHp;                    // 不给默认值：漏填 → 0 → TryValidate 报错，而不是带着 1 点血"正常"开战
    [SerializeField] private List<EnemyActionData> actions = new();

    public string Id => id;
    public string DisplayName => displayName;
    public EnemyDefinition ToDefinition();
    public bool TryValidate(out string error);   // id / displayName 非空；maxHp > 0；actions 非空；逐条 TryValidate，错误信息带 actions[i] 与 name
}

public sealed class BattleConfig : ScriptableObject
{
    [SerializeField] private int playerMaxHp = 80;          // 40 → 80
    [SerializeField] private EnemyData enemy;               // 替代 enemyMaxHp / enemyDamage
    // energyPerTurn / handSize / deck / relics 不变

    public BattleSetup ToSetup() => new(playerMaxHp, energyPerTurn, handSize);
    public EnemyDefinition ToEnemyDefinition() => enemy.ToDefinition();
    // TryValidate：删两个标量的检查；加 enemy 非空 + enemy.TryValidate
}
```

## 5. 测试策略

按 0.3 / 0.5 的做法**锁预览再比 HP 差值**：每个数值用例先记 `PreviewEnemyAttack()`，再 `TryEndPlayerTurn()`，断言玩家 HP 差等于预览（玩家 0 格挡）。

**`CreateSession` 的迁移（0.1～0.5 用例正文不改）：**

```csharp
private static EnemyDefinition FixedAttacker(int maxHp, int damage) => new("fixed_attacker", "固定攻击敌人", maxHp, new[]
{
    // damage == 0 → 空行动（待机）：0.1 的 enemyDamage: 0 就是"敌人不打人"，EffectSpec.Damage(0) 会被工厂拒绝。
    new EnemyAction(damage > 0 ? new[] { EffectSpec.Damage(damage) } : Array.Empty<EffectSpec>()),
});

private static BattleSession CreateSession(
    int playerMaxHp = 40, int enemyMaxHp = 36, int enemyDamage = 6, int energyPerTurn = 3, int handSize = 5,
    List<CardDefinition> deck = null, IEnumerable<RelicState> relics = null, EnemyDefinition enemy = null)
{
    var setup = new BattleSetup(playerMaxHp, energyPerTurn, handSize);
    deck ??= BuildDeck(5, 3, 2);
    enemy ??= FixedAttacker(enemyMaxHp, enemyDamage);   // 传了 enemy 就忽略两个标量
    return new BattleSession(setup, enemy, deck, new Random(1), relics);
}
```

`enemyMaxHp` / `enemyDamage` 两个参数名保留，5 处显式传参的用例一字不改；玩家血量保留 40（测试常量，与 `Default.asset` 的 80 无关）。

**唯一一处 0.1 断言改动：** `PoisonedEnemy_LosesHpIgnoringBlockAtEnemyTurnStart_AndStackDecrements` 在结束回合前给敌人 10 格挡，断言敌人回合后格挡仍是 10、HP 少 3。敌人回合开始清格挡之后，格挡在中毒前就归零，该断言改为 `Assert.AreEqual(0, session.Enemy.Block)`，用例改名为 `PoisonedEnemy_LosesHpAtEnemyTurnStart_BlockClearedFirst_AndStackDecrements`。"中毒无视格挡"本身仍由 `CombatantStateTests.LoseHp_IgnoresBlock`、`EffectTests.HpLossEffect_Apply_ForwardsToLoseHp_IgnoringBlock`、`ActionQueueTests.HpLossAction_Execute_IgnoresTargetBlock`、`BuffTests.PoisonBuff_OnTurnStart_..._IgnoringBlock...` 四处锁住，Session 层不再需要这一条。不要为了保住旧断言把清格挡挪到中毒之后或干脆不清：中毒走 `LoseHp`、本来就不看格挡，挪顺序对中毒数值没有影响，真正的代价是敌我两侧"清格挡 → 回合开始触发"的生命周期顺序不再一致；而那条断言锁的从来不是规则，只是 0.1 缺功能的副产物。

**新增用例：**

- `BattleSessionTests.Enemies.cs`（新 partial，测试内定义 `JawWorm()` / `TwoHits(a, b)` 两个 `EnemyDefinition` 构造辅助；牌堆用 `BuildDeck(0, defendCount: 10)` 只结束回合不打牌，需要打牌的用例换攻击牌堆）：
  - 构造：`CreateSession(enemy: JawWorm())` 后 `Enemy.MaxHp == 42`、`EnemyDefinition` 是传入的同一个实例。
  - 循环与回绕：开战 `CurrentEnemyAction` 是 `Actions[0]`；连续结束 4 个回合后依次为 `[1]`、`[2]`、`[0]`、`[1]`（`Assert.AreSame`）。
  - 咬：`PreviewEnemyAttack() == 11`，结束回合玩家 HP 差 11。
  - 猛击：第 2 回合预览 7、HP 差 7、之后 `Enemy.Block == 5`；第 3 回合打出攻击 6 → 敌人 HP 只少 1、格挡 0。
  - 敌人格挡在自己回合开始清：猛击后不打牌直接结束回合，咆哮后 `Enemy.Block == 6`（不是 11）。
  - 咆哮后咬：咆哮后 `Enemy.GetBuffStacks("strength") == 3`、`PreviewEnemyAttack() == 14`，结束回合 HP 差 14；再下一回合（第二圈猛击）预览 10 且 HP 差 10——力量永久，第二圈跟着涨。这条用 `playerMaxHp: 80` 构造，40 血撑不到第 5 回合。
  - 虚弱敌人：颚虫带 2 层虚弱（`Enemy.ApplyBuff(new WeakBuff(2))`）时咬的预览 `floor(11 × 0.75) = 8` 且 HP 差 8。
  - 多段：`TwoHits(3, 3)` + 玩家 1 层易伤（测试构造）→ 预览 `4 + 4 = 8`（不是 `floor(6 × 1.5) = 9`），HP 差 8。
  - 待机：`CreateSession(enemyDamage: 0)` 的 `CurrentEnemyAction.Effects.Count == 0`，预览 0，结束回合玩家 HP 不变。
  - 毒死不推进指针：颚虫 + 99 层中毒，结束回合后 `Victory` 且 `CurrentEnemyAction` 仍是 `Actions[0]`。0.1 的 `PoisonKillsEnemy` 用单行动敌人，误推进也会 `% 1` 回到同一条，锁不住这一点；玩家被打死时是否推进无意义，不锁。
  - 施加钩子看施加方：玩家持一个测试内定义的 `IApplyBuffModifier`（对任何 Buff +1），颚虫咆哮后力量仍是 3。
- `EnemyDefinitionTests`（新）：`EnemyAction` null 抛 `ArgumentNullException`、含 `Draw` 抛 `ArgumentException`、含 `default(EffectSpec)` 抛、空列表允许（`Effects.Count == 0`）、构造后改原列表不影响；`EnemyDefinition` id / displayName 空抛、`maxHp <= 0` 抛、actions 空抛、构造后改原列表不影响且元素引用相同。约 9 项。
- `EnemyActionDataTests`（新）：Damage + Block 通过；ApplyBuff Self 通过；空 effects 通过；Draw 不通过；ApplyBuff Opponent 不通过（0.7 改为通过）；内层 value 0 不通过并透传 `EffectSpecData` 的错误；`ToAction()` 的 `Effects.Count` 与条目数一致。约 7 项。
- `IntentFormatterTests`（新，纯函数）：`[Damage 11]` + 11 → `攻击 11`；`[Damage 7, Block 5]` + 7 → `攻击 7 · 防御`；`[ApplyBuff Self, Block]` → `增益 · 防御`；`[Damage, ApplyBuff Opponent]` → `攻击 N · 减益`；`[Damage 3, Damage 3]` + 8 → `攻击 8`（只一项）；`[Heal]` → `增益`；`[Block, Block]` → `防御`（去重）；`[]` → `待机`。约 8 项。
- 固定攻击敌人的回归不另写：0.1～0.5 全部用例经 `CreateSession` 跑在它身上，就是回归。

预计新增约 35 项，总数约 235～240。0.1～0.5 除上述 1 项断言外不改断言通过。

## 6. 排除项

- 不做随机 / 带约束随机的行动选择，不给 Session 加第二个随机源；不做血线 / 回合数切换模式、Boss 阶段。
- 不做多敌人、目标选择、全体效果；不做眩晕、隐藏意图。
- 不加 `EffectKind` 原语；不给 `EffectSpec.Damage / Block / Heal` 放开 `Target`。
- 不放开敌人给玩家施加 Buff（0.7 随蓝奴隶贩子放开）。
- 不做 `EnemyIds` / `EnemyFactory`；行动名不进 Core。
- 不改 `ToAction`、`DamageCalculator`、任何 Rule、`CombatantState`。
- 不做意图图标 / 立绘；不改场景。
- 不把 `EnemyTurn` 拆成异步 / 分段动画。

## 7. 关键技术决策

| 决策 | 0.6 选择 | 原因 |
| --- | --- | --- |
| 敌人定义怎么进 Session | [已定] 构造参数 `EnemyDefinition enemy`；`BattleSetup` 只剩三个玩家侧标量 | 牌组 / 遗物都是单独参数；`BattleSetup` 本来就限定为标量 |
| 行动怎么执行 | [已定] `foreach effect → ToAction(effect, Enemy)`，`ToAction` 不改 | 0.2 的 `Opponent(source)` 就是为此留的；`EnemyAction` 构造拒绝 `Draw`，Session 不需要分支 |

| 敌人清格挡 | [已定] 敌人回合开始、中毒之前 | 与玩家侧顺序一致；代价是改 0.1 一项断言（第 5 节） |
| 敌人攻击预览 | [已定] `PreviewEnemyAttack()` 签名不变，改为逐段过 `DamageCalculator` 求和 | 0.3 / 0.5 预览用例不改；每段独立取整与双击一致 |
| 意图文案 | [已定] View 侧 `IntentFormatter.Format(EnemyAction, int)` 直接读效果列表；Core 不加意图类型 | Core 没有消费者读意图种类；与 `CardDescriptionFormatter` 同一条路（评审后拍板） |
| 空行动 | [已定] Core 与 Data 都允许，显示 `待机` | 测试的无害敌人需要；原版沉睡意图的最简形式；两层同一规则。眩晕不是它（执行前作废，第 9 节） |
| `Draw` / 给玩家上 Buff 的拦截位置 | [已定] `Draw` 在 Core 构造拒绝；给玩家上 Buff 在 Data 校验拒绝 | 前者任何版本都无意义；后者是 0.6 的范围限制，0.7 删一行 |
| 敌人显示名 | [已定] `EnemyDefinition.DisplayName`（Core） | 与 `CardDefinition` 一致；不需要 Controller 字典 |
| 玩家 80 | [已定] 改 `Default.asset` 与 `BattleConfig.playerMaxHp` 字段默认值两处；测试保留 40 | 测试 HP 断言全是相对 `CreateSession` 默认值写的 |
| 默认敌人 | [已定] `Default.asset` 指向颚虫 | 演示价值；固定攻击敌人留作切换与回归 |

## 9. 扩展边界批注（非本阶段范围）

> - **概率 / 带约束随机行动**（颚虫真实模式、蓝奴隶贩子 60/40）：给 Session 加第二个 `Random`（1.0 起由 Run 种子派生，保证"同一种子同一局"），行动选择抽成 `IEnemyPattern`（固定循环 / 概率 / 不能连用）——出现第二种模式时才抽接口，0.6 的固定循环就是它的第一个实现。
> - **血线 / 回合数切换模式**：`EnemyDefinition` 带第二张行动表 + 切换条件；执行前多一步"是否还能执行 / 是否换表"。
> - **多敌人**：`Enemy` 变列表；中毒改为怪物阵营开始一起结算、清格挡按角色；意图每只一个；`EffectTarget.Opponent` 需要目标选择——1.2+ 候选池。
> - **眩晕 / 隐藏意图**：执行前把当前行动作废、显示时遮住文案——都在 Session 流程与 View，不需要 Core 里的意图枚举。
> - **敌人施加状态牌**（黏液 / 伤口）："往玩家弃牌堆 / 抽牌堆加牌"是新的效果原语，改 `EffectKind` 与 `ToAction` 一处。
> - **敌人给玩家上 Debuff**：0.7 删 `EnemyActionData.TryValidate` 里那一条，配蓝奴隶贩子。
> - **敌人的治疗 / 自身 Debuff**：`Heal(Self)` 已能配（意图归 `增益`）；敌人给自己上易伤等原版个别行为要等 0.7 的刚施加保护语义定下。
> - **1.0**：`RunConfig` 的三个节点各引用一份 `EnemyData`，进战斗时 `ToDefinition()` 走同一个构造参数；`BattleConfig.enemy` 是否保留给 `TestScene` 单场调试与 1.0 一并决定。
