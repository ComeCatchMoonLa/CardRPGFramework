# Phase 2b 技术设计：BuffSystem

> **技术目标：Buff 的核心状态是数据（所有者隐含在容器归属、层数），只有需要生命周期行为的 Buff 才额外实现触发接口，且触发行为下沉到具体 Buff 子类自己实现，不用外部"扫描器"猜测某个 Buff 属于谁。**
>
> 复用 Phase 2a 的 `ActionQueue`/`Core.Effects`，只新增 Buff 容器和两个具体 Buff。

## 1. 技术原则

延续 Phase 1/2a 的优先级：**正确性 > 可测试性 > 可读性 > 当前已知需求的扩展性**。补充：

- Buff 的触发接口按"自己触发自己"设计（`PoisonBuff` 自己实现 `IBuffTrigger`），不做外部按 Id 扫描匹配的触发器（避免"层数来源不明确"的耦合）。
- 只实现"回合开始"一级触发点。研究文档提到的"阵营级 vs 角色级"钩子粒度差异在多怪物场景才有意义，当前只有单一敌人，两者等价，不提前拆分（YAGNI）。

## 2. 分层与依赖

```text
Core.Battle（BattleSession：在回合切换的固定时机调用 TriggerTurnStartBuffs）
  ↓
Core.Combatants（CombatantState：新增 Buff 容器，暴露 ApplyBuff/GetBuffStacks/HasBuff/LoseHp）
  ↓
Core.Buffs（新增：BuffState 基类、IBuffTrigger、StrengthBuff、PoisonBuff）
  ↓
Core.Actions / Core.Effects（复用 Phase 2a 的 ActionQueue，新增 ApplyBuffAction/BuffEffect、HpLossAction/HpLossEffect）
```

依赖约束新增：

- `Core.Buffs` 不引用 `Core.Actions`：Buff 触发时只往调用方传入的 `ActionQueue` 里塞 Action，不持有队列引用。
- `Core.Combatants` 引用 `Core.Buffs`（`CombatantState` 需要知道 `BuffState` 的形状才能存储），但 `Core.Buffs` 不反向引用 `Core.Combatants` 的具体逻辑，只在方法签名里用到 `CombatantState` 类型。

## 4. 核心接口

### BuffState / IBuffTrigger

```csharp
namespace CardRPGFramework.Core.Buffs
{
    // BuffState 保存核心状态：谁的、多少层。生命周期跟随所在的 CombatantState 存在，
    // 战斗结束即销毁，本阶段不做跨战斗持久化。
    public abstract class BuffState
    {
        public abstract string Id { get; }
        public int Stacks { get; private set; }

        protected BuffState(int initialStacks) => Stacks = initialStacks;

        public void AddStacks(int amount) => Stacks += amount;
        public void RemoveStacks(int amount) => Stacks = Math.Max(0, Stacks - amount);
    }

    // 只有需要"回合开始时做点什么"的 Buff 才实现这个接口；
    // 纯数值型 Buff（力量）不实现它，触发逻辑完全下沉到具体子类，
    // 不存在外部代码"拿着 Id 去找对应 Buff 实例"的情况。
    public interface IBuffTrigger
    {
        void OnTurnStart(CombatantState owner, ActionQueue queue);
    }
}
```

### StrengthBuff / PoisonBuff

```csharp
namespace CardRPGFramework.Core.Buffs
{
    public sealed class StrengthBuff : BuffState
    {
        public override string Id => "strength";
        public StrengthBuff(int stacks) : base(stacks) { }
    }

    public sealed class PoisonBuff : BuffState, IBuffTrigger
    {
        public override string Id => "poison";
        public PoisonBuff(int stacks) : base(stacks) { }

        public void OnTurnStart(CombatantState owner, ActionQueue queue)
        {
            if (Stacks <= 0) return;
            queue.Enqueue(new HpLossAction(owner, Stacks));
            RemoveStacks(1);
        }
    }
}
```

### CombatantState 新增成员

```csharp
private readonly Dictionary<string, BuffState> _buffs = new();

public IReadOnlyCollection<BuffState> Buffs => _buffs.Values;

public void ApplyBuff(BuffState buff)
{
    if (_buffs.TryGetValue(buff.Id, out var existing))
    {
        existing.AddStacks(buff.Stacks);
    }
    else
    {
        _buffs[buff.Id] = buff;
    }
}

public int GetBuffStacks(string id) => _buffs.TryGetValue(id, out var buff) ? buff.Stacks : 0;
public bool HasBuff(string id) => GetBuffStacks(id) > 0;

// 忽略格挡，直接扣血；中毒等 HP Loss 类型伤害专用，Attack 类型伤害继续走 TakeDamage。
public void LoseHp(int amount) => CurrentHp = Math.Max(0, CurrentHp - amount);
```

### 新增 Action / Effect

```csharp
namespace CardRPGFramework.Core.Effects
{
    public static class BuffEffect
    {
        public static void Apply(CombatantState target, BuffState buff) => target.ApplyBuff(buff);
    }

    public static class HpLossEffect
    {
        public static void Apply(CombatantState target, int amount) => target.LoseHp(amount);
    }
}

namespace CardRPGFramework.Core.Actions
{
    public sealed class ApplyBuffAction : IAction
    {
        private readonly CombatantState _target;
        private readonly BuffState _buff;

        public ApplyBuffAction(CombatantState target, BuffState buff) { _target = target; _buff = buff; }

        public void Execute(ActionContext context) => BuffEffect.Apply(_target, _buff);
    }

    public sealed class HpLossAction : IAction
    {
        private readonly CombatantState _target;
        private readonly int _amount;

        public HpLossAction(CombatantState target, int amount) { _target = target; _amount = amount; }

        public void Execute(ActionContext context) => HpLossEffect.Apply(_target, _amount);
    }
}
```

`HpLossAction` 独立于 `DamageAction` 存在，不是同一个类加一个"是否走格挡"的布尔参数——目前只有两种伤害路径（Attack 走格挡、HP Loss 不走），加参数和加类的复杂度相当，但加类更符合"调用方一看类型就知道语义"的可读性优先原则。如果以后出现第三种伤害路径（Thorns），再抽象成统一的 `DamageType` 参数（呼应 [`杀戮尖塔机制研究.md`](../杀戮尖塔机制研究.md) 第 3 节，抽象时机是"出现第二次同类变化"，不是"提前预判"）。

## 5. BattleSession 集成方式

```csharp
private void TriggerTurnStartBuffs(CombatantState owner)
{
    foreach (var buff in owner.Buffs)
    {
        if (buff is IBuffTrigger trigger)
        {
            trigger.OnTurnStart(owner, _actionQueue);
        }
    }
    _actionQueue.RunAll(new ActionContext(_actionQueue));
}
```

`StartPlayerTurn`：在 `Player.ClearBlock()` 之后、恢复能量之前插入 `TriggerTurnStartBuffs(Player)`，触发后立即检查 `Player.IsDead`，为真则 `Phase = Defeat` 并提前返回（当前两张新卡不会让玩家中毒，但接口本身是双方对称的，必须处理这个分支，否则出现新 Buff 来源时会漏判）。

`TryEndPlayerTurn`：进入 `EnemyTurn` 后、`Player.TakeDamage(EnemyDamage)` 之前插入 `TriggerTurnStartBuffs(Enemy)`，触发后立即检查 `Enemy.IsDead`，为真则 `Phase = Victory` 并跳过敌人攻击。

`EnqueueCardAction` 新增两个分支：

```csharp
case CardType.Strength: _actionQueue.Enqueue(new ApplyBuffAction(Player, new StrengthBuff(card.Value))); break;
case CardType.Poison: _actionQueue.Enqueue(new ApplyBuffAction(Enemy, new PoisonBuff(card.Value))); break;
```

## 6. 测试策略

- `CombatantState` 新增测试：`ApplyBuff` 首次施加与叠加层数、`LoseHp` 不受格挡影响且不低于 0。
- `Core.Buffs` 新增测试：`PoisonBuff.OnTurnStart` 层数为 0 时不入队、层数大于 0 时入队正确数值的 `HpLossAction` 并自身层数减 1。
- `BattleSessionTests` 新增：打出力量卡后内部层数增加（通过 `Player` 状态断言，不依赖 UI）；打出剧毒卡后经过一次敌方回合，敌人生命值按层数减少且格挡不吸收；中毒致死时战斗以胜利结束且敌人未发起攻击（用极高层数中毒 + 极低敌人生命的测试构造验证）。

## 7. 排除项

- 不做 Buff 的持续回合数/自动到期。
- 不做 Buff 移除/清除 API（本阶段没有任何机制需要主动移除 Buff）。
- 不引入阵营级触发钩子（`OnFactionTurnStart` 之类），当前单一敌人场景下和角色级钩子等价。

## 8. 关键技术决策

| 决策 | Phase 2b 选择 | 原因 |
| --- | --- | --- |
| Buff 容器 | `Dictionary<string, BuffState>`，按 Id 索引 | 力量/中毒的查找和去重都按 Id 进行，字典比 List 遍历直接 |
| 触发行为归属 | 下沉到具体 Buff 子类（`PoisonBuff : IBuffTrigger`） | 避免外部按 Id 扫描匹配、层数来源不明确的耦合 |
| 触发时机 | 只做"回合开始"一级 | 对齐研究文档中毒结算时机；当前无需求需要"回合结束"钩子 |
| 中毒伤害路径 | 独立的 `HpLossAction`/`HpLossEffect`，不走格挡 | 对齐研究文档伤害类型区分，且是唯一两条路径，加类比加参数更直观 |
| 力量的消费方 | 本阶段不实现，留给 Phase 2c | Buff 只负责存数据，怎么用是 Rule 的职责，边界不能混 |
