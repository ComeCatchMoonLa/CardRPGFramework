# Phase 2b 游戏设计：BuffSystem（力量与中毒）

> **交付目标：新增两张卡牌（力量、剧毒），证明"Buff 是数据容器，部分 Buff 附带触发行为"这条架构边界能在真实战斗里跑通。**
>
> 只做两个 Buff：一个纯数值型（力量，无触发），一个触发型（中毒，回合开始扣血）。不做 Buff 移除机制、持续回合数、图标展示等内容。

## 1. 设计原则

- 只新增能验证"Buff 的核心状态是数据，只有需要生命周期行为的 Buff 才额外实现触发接口"这条边界的最小内容，不追求 Buff 种类数量。
- 力量本身不产生任何效果——它只是一个层数，效果由 Phase 2c 的 RuleSystem 读取并应用。本阶段结束时，打出力量卡在数值上应该"看起来没有用"，这是预期行为，不是 bug。
- 中毒是本阶段唯一有实际可见效果的 Buff，用它验证触发链路是否走通。

## 2. 新增卡牌

| 卡牌 | 费用 | 效果 |
| --- | ---: | --- |
| 力量药剂 | 1 | 自身获得 2 层力量（Strength） |
| 剧毒药剂 | 1 | 对敌人施加 3 层中毒（Poison） |

牌组从 Phase 1 的 10 张扩充为 12 张：原有 5 攻击 / 3 防御 / 2 治疗不变，新增 1 张力量药剂 / 1 张剧毒药剂。

## 3. Buff 规则

### 力量（Strength）

- 只是一个层数，没有持续回合数限制，本场战斗内不会自然衰减。
- 本阶段没有任何数值消费它（消费逻辑在 Phase 2c），因此打出力量卡后玩家看不到直接效果，只能通过后续断言其内部层数增加来验证。

### 中毒（Poison）

- 挂在敌人身上，在敌人"回合开始"时结算（对齐 [`Docs/杀戮尖塔机制研究.md`](../杀戮尖塔机制研究.md) 第 2 节"中毒在回合开始时结算"，不是回合结束）。
- 结算方式：造成等于当前层数的伤害，然后层数减 1；层数为 0 时不再造成伤害。
- 中毒伤害是 **HP Loss** 类型（见研究文档第 3 节的伤害类型表），**不受格挡吸收**、**不受力量/虚弱/易伤等 Buff 加成**——这是本阶段引入的第一次伤害类型区分，Phase 2c 的伤害规则修正只对卡牌攻击（Attack 类型）生效，不影响中毒。

## 4. 战斗流程更新

```text
玩家回合开始：清除格挡 → 结算玩家身上的回合开始触发型 Buff → 恢复能量 → 抽牌
  ↓
玩家使用 0～多张卡牌（可以是攻击/防御/治疗，也可以是力量/剧毒）
  ↓
玩家点击"结束回合" → 弃掉剩余手牌
  ↓
进入敌方回合：结算敌人身上的回合开始触发型 Buff（本阶段即中毒）
  ↓
若敌人因中毒死亡 → 立即胜利，不再执行敌人攻击
  ↓
敌人执行固定攻击 → 检查失败条件 → 下一玩家回合
```

新增的"结算触发型 Buff"步骤可能导致某一方死亡，死亡判定要在该步骤后立即检查（不能等到原有的攻击后再判定），否则会出现"中毒已经打死敌人，敌人还能再攻击一次"的规则错误。

## 5. 本阶段不包含

- Buff 的移除、持续回合数、叠加上限。
- 虚弱、易伤等仅供 Rule 消费的 Buff（留给 Phase 2c，2c 会复用本阶段的 Buff 容器基础设施）。
- Buff 图标或数值展示（UI 改动不在本阶段范围，`Views` 层不变）。
- 敌人主动对玩家施加 Buff（本阶段的 Buff 卡都是玩家单方面使用）。

## 6. 验收标准

- 打出力量卡后，玩家身上的力量层数正确累加（通过测试断言内部状态，玩家能观察到的只是"卡牌被使用、能量被扣除"）。
- 打出剧毒卡后，敌人身上的中毒层数正确累加；在敌人下一次回合开始时，敌人损失等于当前层数的生命值，且格挡不影响这次损失，层数随后减 1。
- 中毒把敌人打死时，战斗立即以胜利结束，敌人不会再发起攻击。
- Phase 1/2a 的既有行为（攻击/防御/治疗、能量、牌堆流转）不受影响。
