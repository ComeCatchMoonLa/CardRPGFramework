# Phase 0 TODO：技术验证

预计总耗时：2～3 天（约 16～20 小时，按每天 6～8 小时有效开发时间估算）

目标：确认技术路线可行——Unity + C# + 配置读取 + 战斗流程 四要素能跑通。

---

## 1. Unity 工程建立（约 2 小时）

- [ ] 创建 Unity 项目，确定引擎版本与渲染管线（Built-in / URP）（0.5h）
- [ ] 规划工程目录结构（Scripts / Prefabs / Scenes / Configs / Art 等）（0.5h）
- [ ] 配置基础工程规范文件（.gitignore、.editorconfig 等）（0.5h）
- [ ] 引入必要的基础依赖包（如序列化库、异步库等，视需要）（0.5h）

## 2. Git 仓库搭建（约 1 小时）

> 分支策略：采用简单的 trunk-based 工作流，个人开发阶段只维护 `main`，不创建 `dev` 分支。

- [x] 初始化本地仓库并关联远程仓库（GitHub / Gitee）（0.5h）
- [x] 约定分支策略（如 main + dev，或简单 trunk-based）（0.25h）
- [x] 编写基础 README（项目定位、运行方式、目录说明）（0.25h）

## 3. C# 代码结构搭建（约 4 小时）
备注：先不急着写XXXManager，想清楚数据层、逻辑层、表现层

- [ ] 确定分层架构（如 View / Logic / Data）（1h）
- [ ] 建立命名空间划分与文件夹映射规则（0.5h）
- [ ] 搭建核心模块骨架类（如 GameManager、BattleManager 占位实现）（1h）
- [ ] 约定代码规范（命名、注释、异步方式），简单记录成文档（0.5h）
- [ ] 搭建单元测试项目骨架（可选，视时间富余程度）（1h）

## 4. 数据配置读取验证（约 3 小时）
备注：先用ScriptableObject，JSON 可以后续加。

- [ ] 选定配置方案（JSON / ScriptableObject / 表格转换等）（0.5h）
- [ ] 设计最小可用的配置数据结构（如卡牌：id / name / damage）（0.5h）
- [ ] 实现配置文件的加载与解析逻辑（1h）
- [ ] 搭建测试场景，验证配置数据能被正确读取并展示（1h）

## 5. 基础场景与简单 UI（约 3 小时）

- [ ] 搭建空场景，包含基础相机与背景/地面（0.5h）
- [ ] 搭建最简 UI（如一个按钮 + 一个文本显示框）（1h）
- [ ] 打通 UI 事件与逻辑层的调用链路（1h）
- [ ] 验证场景可正常运行、无报错（0.5h）

## 6. 战斗流程最小验证（约 3～4 小时）
备注：流程太简单
建议实现：
玩家回合
 ↓
选择技能
 ↓
计算伤害
 ↓
敌人受伤
 ↓
敌人行动
 ↓
胜利/失败
体现：状态机、数据驱动、事件

- [ ] 设计最简战斗流程（点击 → 扣血 → 显示结果）（0.5h）
- [ ] 实现最小可运行的战斗逻辑（暂不考虑扩展性）（1.5h）
- [ ] 将战斗数值接入配置读取结果（伤害等来自配置而非硬编码）（1h）
- [ ] 完整跑通一次流程，记录遇到的问题（0.5h）

## 7. 阶段验收与复盘（约 1 小时）

- [ ] 核对是否满足"Unity + C# + 配置读取 + 战斗流程"四要素（0.5h）
- [ ] 记录当前架构存在的问题与风险，评估是否需要调整 Phase 1 计划（0.5h）

## 时间汇总

| 3. C# 代码结构搭建 | 4h |
| 4. 数据配置读取验证 | 3h |
| 5. 基础场景与简单 UI | 3h |
| 6. 战斗流程最小验证 | 3～4h |
| 7. 阶段验收与复盘 | 1h |
| **总计** | **约 17～18h** |

与"2～3 天"的预估基本吻合，若单日可投入时间较少，可拆分到 3 天执行；若效率较高，2 天即可完成。

## 风险提示

- 不要在本阶段设计过多系统，目标是验证技术路线，不是搭建完整框架。
- 第 3、6 项容易被无限扩展（想一步做到位），需要主动控制范围，先跑通再优化。
